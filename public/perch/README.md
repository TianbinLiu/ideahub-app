# perch 角色贴图

右侧栏 / 底栏激活态出现的 Q 版角色（见 `src/components/CharacterPerch.tsx`）。

形象与创作入口 `/create` 三张封面（`public/create/*.jpg`）是同一位角色：
银白长发 · 薄荷绿挑染 · 金色五角星发饰 · 青蓝大眼 · 藏蓝短披风 + 金色圆扣 + 白立领。

## 六个动作 × 每个 8 帧

每个动作是一张横向排布的 8 帧精灵图（`{pose}.webp`，单格 160px 宽），
靠 `background-position` 逐格平移播放。

| 文件 | 用在哪 | 动作 | 进出场 |
| --- | --- | --- | --- |
| `like` | 右栏点赞 | 双臂从张开平滑抬起成 V 字，开怀大笑 | 蹦最高，收尾先蹲一下再缩回 |
| `save` | 右栏收藏 | 双手合拢抬到胸口，眯眼变睁眼 | 升起时晃两下，收尾直接沉下去 |
| `home` | 底栏「首页」 | 挥手 | 摇三下，退场再摇一下 |
| `explore` | 底栏「分区」 | 手从前指抬到额前搭凉棚远眺，头转向另一侧 | 从左侧探进来，也从左侧退出去 |
| `studio` | 底栏「创意工坊」 | 双手举起向两侧张开，身体轻跳 | 二段跳，退场再蹦一次 |
| `mine` | 底栏「我的」 | 托下巴的手移到脸侧，头歪向另一边 | 不蹦，轻轻落座轻轻淡出 |

**为什么要逐帧**：只靠容器做缩放位移的话，看到的永远是「一张画弹出来了」，
角色本身并没有动。两帧硬切勉强算动，但只有两个姿势、看着生硬；8 帧才是一套动作。

**为什么是一次性演出**：角色的职责是「对这次操作的即时反应」，不是状态显示。
跟着 `filled` 常驻会让点完赞的角色一直杵在心形上方，既挡视频，
也让「已激活」被说两遍（实心红心已经说过了）。
现在是：冒出来 → 翻页演 3 轮 → 缩回图标后面消失，全程 `PERCH_MS`。

六处共用一张图 + 一套动画时，点赞和切 Tab 的反馈完全一样，角色就退化成一个到处乱贴的水印。
姿势、翻页帧、进出场动画都由**同一个 `pose`** 派生，不拆成多个 prop ——
拆开就总有一天会配出「挥手的图 + 蹦跳的动画」。

### 中间帧从哪来：Seedance 首尾帧，不是插值

先出 A / B 两个端点姿势，再把它们作为 `first_frame` / `last_frame` 丢给
**Seedance**（`src/ai/arkClient.ts` 的 `MODELS.video`）生成 3 秒视频，
抽 8 帧做精灵图。

★ **不用 RIFE / FILM 这类帧插值**：插值只能在两帧之间做形变，手臂会「融化」着平移；
视频模型会生成合理的运动弧线（手臂沿弧线抬起、头发跟着甩）。
外部服务（Replicate、HF Spaces 上的 RIFE/FILM）能做前者，但项目本来就接了
Seedance，效果还更好，不必引外部依赖。

提示词要点：动作描述里明确写 **「镜头完全静止不动」「角色始终保持在画面正中，大小不变」**
**「背景始终是纯正绿色 #00FF00，绝对不变」**。不写的话模型会给镜头加推拉摇移，
抽出来的帧角色忽大忽小，做成精灵图就是一团抖动。

`ratio` 取 `1:1`（默认 16:9 会把方形的角色图裁掉两边）。

### 各帧必须用同一个裁切框

取**所有帧包围盒的并集**做统一裁切框，各帧输出尺寸完全一致 ——
逐帧单独 trim 的话，手臂张开那几帧包围盒更大，缩放到同一格宽后角色会忽大忽小。

## 为什么是位图

目标画风是渐变上色 + 发丝高光 + 线稿描边的日系手绘感。这种质感来自逐像素的明暗过渡，
手写 SVG path 只能拼平涂色块 —— 试过两版矢量都败在这上面（不是画得不够细，
而是矢量平涂做不出上色）。所以改用生成图。

## 重新生成

脚本思路见下（一次性脚本，不进项目依赖；用 `sharp` 做抠图与缩放）。
用项目自带的方舟 Seedream（`src/ai/arkClient.ts` 里的 `MODELS.image`）出图。

### ★ 必须逐张生成，不要做精灵图

「六格拼一张、一次出完」看起来更省也更能保证形象一致，但**方舟一律拒绝**：
实测 6 种措辞（去掉「接触」「姿势」「动作」、改成「画六次」「排列六个」等）
全部返回 `InputTextSensitiveContentDetected`（400）。二分定位确认触发的是
「一张图里多个角色」这件事本身，属于策略过滤，措辞绕不过去。

改为逐张生成，靠**传参考图**锁形象：把第一张采纳的图作为 `image` 参数传回去，
提示词只说「保持参考图角色外观不变，改成 X 姿势」。
纯靠文字复述外观是不够的 —— 发色深浅、脸型、披风版型都会漂，六张摆一起就是六个人。

### 提示词注意

- **不要出现「少女」「拥抱」「害羞」等词**，方舟会以 `InputTextSensitiveContentDetected`
  拒绝整个请求（是 400 不是降级）。用「Q版卡通角色」这类中性表述。
- 明确要求 **纯正绿色 `#00FF00` 纯色背景、无渐变无阴影无图案**，方便抠图。
- 要求 **半身像、只到腰部**：腿在 ~50px 下只会缩成两根看不清的小棍，
  而且「手往前伸捧住图标」比「腿垂在图标前」更贴合「抱住图标」的诉求。

### 抠图

按「绿色优势度」`g - max(r, b)` 判定，而不是「颜色接近纯绿」——
AI 出的背景常有轻微明暗不匀，卡死一个 RGB 值会留一圈杂边。

★ 阈值必须**先量分布再定**。实测是干净的双峰：背景 ≥160，角色 ≤40
（薄荷挑染最高，26），中间 50~130 只有几百个抗锯齿边缘像素。
第一次拍脑袋取 40/12，正好把挑染切进过渡带 —— 挑染被做成 50% 半透明还被去了色，
而这种损伤在 50px 的成品上几乎看不出来，只有量 alpha 才会发现。

处理流程（每一帧都做一遍）：

1. `dom >= 130` → `alpha = 0`
2. `50 < dom < 130` → alpha 线性过渡，并把 g 压到 `max(r, b)` 去绿溢色（只在过渡带做）
3. `dom <= 50` → 原样保留
4. 求所有帧包围盒的**并集**，各帧用这个统一框裁切 → 缩到单格 160 宽 → 横向拼接 → 存 WebP

视频帧的抠图比静态图更需要留意压缩伪影（H.264 的色度二次采样会糊掉绿边），
但实测这套阈值下边缘干净：不透明像素里绿优势 >25 的只有 3%，
且经查证全部是**薄荷挑染本身**（它的绿优势度就是 26，正好越过检查线），不是绿边。

单格 160 宽是渲染尺寸（最大约 50px）的 3 倍，够 3x 屏。
WebP q80 比调色板 PNG 小 38%（61KB vs 98KB/张），带 alpha 的 WebP 自 Safari 14
起全平台支持，不用做回退。

改图后记得同步 `CharacterPerch.tsx` 里的 `ART`（各姿势原始宽高，用来算等比高度）。
动画总时长的唯一真源是同文件里的 `PERCH_MS`，CSS 通过 `--perch-ms` 拿到它推导各阶段
（18% 进场 / 18%~72% 翻页 / 72%~100% 退场），别在 `index.css` 里另写一个写死的秒数。

## 角色怎么和图标「长在一起」

角色是彩色厚涂、图标是单色描边，两种视觉语言并排放着必然突兀。
靠三件事绑定（前两件在 `src/index.css` 的 `.perch-pop` 伪元素里）：

1. **接触阴影** —— 角色脚下一团投在**图标上**的软阴影，制造承重与接触感。
   没有它角色就是一张悬在图标上方的贴纸。
2. **同色辉光** —— 角色背后一圈该图标激活色的辉光（赞=玫红 / 藏=金 / Tab=青），
   让两者共享一个色相，而不是各说各话。
3. **重叠 26%** —— 双手实打实压在图标顶沿。这个值调过三轮：
   0.52（重叠 46%）图标被盖到认不出；0.78（22%）图标清楚但角色像悬空贴纸；
   现取 0.74。重叠比例只由 `bottom` 与图标高度决定，与角色贴图大小无关。
