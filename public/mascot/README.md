# mascot 看板娘贴图（工作流页）

屏幕中央的三段演出，见 [`src/components/MascotStage.tsx`](../../src/components/MascotStage.tsx)。

| 文件 | 用在哪 | 动作 | 单格 |
| --- | --- | --- | --- |
| `handover.webp` | 拖素材卡时的落点提示 | 双手从桌面向前伸出、掌心摊开成接取姿势，笑意展开 | 420px |
| `forge.webp` | 出片过程中循环播 | 闭眼专注，双手在桌上把青蓝光团张开成旋转的金色符文法阵 | 420px |
| `forged.webp` | 本段炼成的那一下 | 把成形的发光塔罗牌举到脸侧，表情从惊喜转为开怀大笑 | 420px |
| `cardbtn.webp` | 「生成本段」旁那颗素材按钮 | **Q 版**：躲在竖起的牌后只露眼睛 → 探身把牌举到脸侧得意大笑 | 180px |

都是 8 帧横排，靠 `background-position` 逐格平移；总计约 740KB。

★ `cardbtn` 与另外三张的用法不同：它不是"播一段动画"，而是**一条序列的两端各当一个状态**——
正播 = 展开素材库，倒播 = 收起，两端靠 `animation-fill-mode: forwards` 定格
（见 `MascotStage.tsx` 的 `MaterialButtonArt`）。做成两张静态图的话，切换只能靠淡入淡出，
那是"换了张贴纸"而不是"她动了一下"。所以脚本里 A 必须是收起态、B 必须是展开态，**顺序不能反**。

★ 只有 `cardbtn` 走 Q 版，且参考图不是定妆照而是 **`perch/save.webp` 的第 8 帧**：
按钮里净高只有 ~42px，正片的脸缩到这个尺寸就是一团糊；而 perch 那六张已经是这个角色的
Q 版权威形象，另画一版 Q 版定妆照必然长成第二个人。

## 与 `public/perch/` 是两套东西，别合并

`perch` 是 50px 图标上的 **Q 版**挂件（单格 160px，带"埋进图标里"的进出场编排）；
这三张是屏幕中央 ~250px 的**正片**演出，用的是与 `/create` 三张封面同一位二次元角色
（同一张定妆照 `design/character-ref.jpg` 出的图）。Q 版放大到这个尺寸就是一团糊。

翻页关键帧两边共用 `index.css` 里的 `perch-run`——都是"横向平移背景"，抄第二条迟早会漂。

## 重新生成

```bash
# IMGTOOLS 指向一个装了 sharp 与 ffmpeg-static 的目录（一次性工具，刻意不进项目依赖）
IMGTOOLS=/path/to/tools node design/gen-mascot-sprites.mjs . [handover,forge,forged]
```

中间产物（A/B 端点帧、mp4、抽帧）缓存在 `design/mascot-src/`（不入仓）：
**重跑只重做抠图那几步，不会重复调用方舟**。要重出画面就删掉对应的缓存文件。
脚本跑完会打印各姿势的单格宽高，照抄进 `MascotStage.tsx` 的 `SHEET`——
高度写错不报错，只会把角色拉扁。

流水线与 `perch` 那套同源（先读 [`../perch/README.md`](../perch/README.md)）：
Seedream 出 A/B 两个端点姿势 → Seedance **首尾帧**模式补中间动作 → 抽 8 帧 →
绿幕抠图 → 所有帧包围盒的**并集**做统一裁切框 → 缩放拼接。

## 这次新踩的三个坑

### 1. `sharp.blur()` 收 1 通道 raw，吐回 **3 通道**

实测 8×4 的灰度图进去、96 字节出来。按 1 通道下标读 alpha 的话，读到的是图像上
三分之一的 R 值当成整张的透明度——表现为**一块与人物毫无关系的拱形区域被留了下来**
（绿幕没抠干净），而颜色本身完全正常。极难往"通道数"上想，必须按 `info.channels` 取步长。

### 2. 阈值不能照抄 perch 那套（130/50）

这三张走的是**视频**抽帧，比静态图多一层 H.264 的账。实测 dom 直方图（每档 30，从 -40 起）：

```
handover 714590,241528,23398,9340,13913,39448,824948,206435,0
forge    772986,262549,23304,10679,16802,44720,942436,124,0
forged   730847,257787,24234,9135,12089,16959,38912,952650,30987
```

角色本体全在 dom ≤50（薄荷挑染最高 ~26），背景峰在 ≥140，中间 50~140 是色度二次采样
在高对比边缘糊出来的**宏块**。照抄 130/50 会让这些宏块拿到 alpha 64~159，成品上就是
发丝周围一圈方格状白渣。收到 **85/35** 后它们整块归零，而角色一根头发都没少。

### 3. 光靠颜色阈值杀不干净：还要按连通块面积筛 + 只糊 alpha

- 编码器会在角落糊出**灰白色**宏块，它们 dom≈0，在颜色判据下是彻头彻尾的"前景"。
  但角色+桌子是一整块连通域（桌沿横贯全幅、烛台立在桌上），孤立小块必然是脏东西——
  按连通块面积筛（<0.1% 画幅即丢）比继续调颜色阈值稳得多。
- 画风里那圈「柔和的边缘光」（`STYLE` 里点名要的）落在绿幕上是一条半透明过渡带，
  而 H.264 把这条平滑渐变压成了一格一格的台阶，在深色背景上看就是棋盘格。
  **只糊 alpha、不碰颜色**（σ=2.5）就能抹平；σ=1.5 还看得见格子，σ=4 会把发梢糊成棉花。

## 提示词注意（与 perch 相同的雷）

- Seedance 提示词必须写死「镜头完全静止不动」「角色始终保持在画面正中，大小不变」
  「背景始终是纯正绿色 #00FF00」，否则模型会自己加推拉摇移，抽出来的帧角色忽大忽小。
- `ratio` 取 `1:1`（默认 16:9 会把方形的角色图裁掉两边）。
- B 端点必须**以 A 为参考图**生成，只说"改成 X 姿势"。纯靠文字复述外观，
  两端会长成两个人（发色深浅、脸型、披风版型都会漂）。
- 角色设定文案 `CHAR` 与画风 `STYLE` 与 `design/gen-create-covers.mjs` **逐字一致**，
  改一个字，这三张里的人就和 `/create` 三张封面不是同一个人了。
