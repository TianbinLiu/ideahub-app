# createbtn 底栏 ➕ 上的看板娘

见 [`src/components/CreatePerch.tsx`](../../src/components/CreatePerch.tsx)。
每次切 Tab（首页 / 分区 / 创意工坊 / 我的）随机抽一套演一遍。

| 文件 | 动作 | 表情 | 单格 |
| --- | --- | --- | --- |
| `invite.webp` | 抬手在耳边挥手打招呼，另一手叉腰 | 开心大笑 | 200×228 |
| `cheer.webp` | 双手高举过头顶张开欢呼 | 仰头开怀，周围金色光点 | 200×200 |
| `pull.webp` | 掌心向上做「过来」的招手手势 | 挑眉得意 | 200×243 |
| `magic.webp` | 双手从合十张开，掌心升起青蓝光球 | 睁眼惊喜 | 200×193 |

都是 12 帧横排，靠 `background-position` 逐格平移；四张合计约 645KB。

## 为什么加号不画进贴图里

她手里**不拿加号**，加号仍然是 `components/Icon` 的那枚矢量 `plus`。三个理由：

1. 位图画的加号缩到 26px 一定比矢量糊；
2. 出图提示词里写死了「无任何文字、字母、数字、符号」（文生图写符号本来就不稳），
   要她举一个「+」是自相矛盾的要求；
3. 「Q 版看板娘 + 加号」本来就是**两个元素合成一颗按钮** —— 角色从按钮后面探出来抱住它，
   这正是 `../perch/` 那六个挂件与图标「长在一起」的同一套做法（接触阴影 + 同色辉光 + 重叠）。

## 为什么要好几套、还要随机

一套固定动作看三次就成了背景板。➕ 是全 app 唯一的主 CTA，却是底栏里唯一不会动的东西，
在四个会变实心的 Tab 中间反而最容易被忽略。随机换一套是为了让人多看一眼。

★ 换姿势时**排除当前这一套**（见 `useCreateBurst`）：直接 `random()*4` 有 1/4 概率抽到
同一套，而"换了一套"正是这个功能的全部意义 —— 连着两次一样，用户只会觉得是同一张图。

## 与 `../perch/`、`../mascot/` 的分工

| | 是什么 | 姿势怎么定 |
| --- | --- | --- |
| `perch` | 右栏 / 四个 Tab 图标上的 Q 版挂件（8 帧，单格 160px） | 与图标**一一对应**，固定 |
| `createbtn` | ➕ 上的 Q 版挂件（12 帧，单格 200px） | **随机**，四套轮换 |
| `mascot` | 工作流页屏幕中央 ~250px 的正片演出（单格 420px） | 与流程状态对应 |

`createbtn` 与 `perch` 共用 `index.css` 里的 `.perch-pop`（辉光 + 接触阴影）与
`perch-run`（翻页关键帧）—— 都是"从图标后面探出来的 Q 版挂件"，抄第二套迟早会漂。
只有进出场编排各写各的：动作不同，编排跟着动作走（招手的从侧面探进来、欢呼的往上蹦）。

## 重新生成

```bash
# IMGTOOLS 指向一个装了 sharp 与 ffmpeg-static 的目录（一次性工具，刻意不进项目依赖）
IMGTOOLS=/path/to/tools node design/gen-createbtn-sprites.mjs . [invite,cheer]
```

中间产物缓存在 `design/createbtn-src/`（不入仓）：**重跑只重做抠图那几步，不会重复调用方舟**。
要重出画面就删掉对应的缓存文件。脚本跑完会打印各姿势的单格宽高，
照抄进 `CreatePerch.tsx` 的 `SHEET` —— 高度写错不报错，只会把角色拉扁。

流水线与踩过的坑见 [`design/lib/sprite-pipeline.mjs`](../../design/lib/sprite-pipeline.mjs)
与 [`../perch/README.md`](../perch/README.md)。

★ **不要画单眼眨眼。** 实测这个模型最容易画崩的就是单眼闭合（闭眼弧线朝上反、
还叠一道多余睫毛线），`design/gen-create-covers.mjs` 里为此专门写了「双眼对称」的约束。
俏皮感用「叉腰」「招手」这类手势表达。
