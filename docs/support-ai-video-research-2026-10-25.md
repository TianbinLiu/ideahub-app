# AI 客服 × 四支 B 站视频：调研与这次改了什么（2026-10-25）

主人 10-25：「有三个视频需要你调研来优化 app 的 ai 客服」，随后追加第四支。这里的「AI 客服」= 客服页（Live2D 看板娘「小梦」+ 对话 + 语音 + 转人工）、
数字人形象 / 人格 / 声音三个市场、创作中心（Live2D 上传向导、人格制作向导）。

**做法**：四支视频在浏览器面板里取页面自带的播放信息把音视频拉到本机（B 站风控挡住了 yt-dlp），两支有旁白的用 faster-whisper large-v3 本机转写，
每 4 秒（短片每 1 秒）抽一帧拼成九宫格逐张看；评论区不登录只拿得到置顶加两三条。然后一个 41 个 agent 的工作流：三份现状地图（App / 服务端 + 官网 / 已有文档与拍板）、
四份分视频调研（各自上网查证）、两位不同视角的设计者、合并成 15 条提议、每条两个对抗审核（代码现实 / 可行与代价）、最后一个找漏项的批评者。
本机素材（视频、帧、转写）只放在会话的临时目录，调研完已删。

## 二、我们的 AI 客服现在是什么样（摘要）

一轮对话：输入（文本 ≤1000 字或按住说话）→ `POST /api/support/chat`（SSE，最近 ≤12 条历史）→ 服务端检索知识库、拼系统提示词（演出协议 + 转人工规则）、
DeepSeek 流式生成、按标点切句、剥 `[情绪][face][action]` 标签、过输出守卫 → 逐句 `sentence` → App 文字先上屏、同时逐句发 `/api/tts`、按顺序演（表情 / 动作 / 口型）。
9 种 face、11 种 action 全由模型在句首写标签挑；官方看板娘的 11 种 action 只落到 7 段动作文件。每问预扣 400 token、念字另按每字 33 token。

调研时在代码里核实的问题（文件:行见工作流结果，下面只列结论）：

1. 字幕框显示整段累计文字，文字比声音快，框里常常已经是第 4 句、她还在念第 1 句；记着「正在念哪句」的状态从来没画出来。
2. App 不发 `caps`，危机求助卡退化成一句台词被**念出来并按字扣费**；「我是 AI」告知（SB 243）App 根本收不到，而服务端照常记成「已告知」。
3. 动作比声音早一次 TTS 往返；2.3 秒内的第二个动作被直接丢掉；表情按固定时长收回，与句子长短无关。
4. explain / comfort / acknowledge 共用同一段点头，excited / playful 共用同一段；包里的 bow 动作闲置。
5. 触摸台词写死取中文；装了市场形象也念「薄荷色是我自己挑的」这类官方外貌台词；每碰一次都重新合成语音、按字扣费。
6. 加载 .moc3 前没有跑官方建议的那道检查；两套形象都没加载出来时舞台空着、只 console.warn；加载文案写死「小梦」。
7. 上传向导的试跑按时间打勾，一项没跑也能拿到「试跑过了（0 项）」，改了映射旧 ✓ 还在。
8. 人格市场没有应用内举报（服务端 Report 早就支持 persona），Google Play 的 AI 生成内容与 UGC 政策都要求。
9. 小梦只能用嘴说路径、不能带人去；拿不准时只能猜；看不到这台设备的版本；查不了本人的账；不知道当前形象做不了哪些动作；外貌口径还写「少女」。—— 都在服务端，见四。

## 四、等主人定的（按建议先后）

1. **第三方许可的一件事（最要紧）**：正本在私有笔记（ideahub-private 的「Live2D 许可」那份），不进公开仓。
   结论出来之前不推进任何会扩大「用户上传 / 生成 Live2D 模型」的事（服务端自动生成模型、给用户的一键分层做成 Live2D、市场「先看看」）。
   StretchyStudio、image2live2d 能直接写 .moc3，但它们的写入器自述来自对 Cubism Core / Editor 的逆向，我们不能接。
2. **服务端补安全底线**（App 那一半这次已做）：few-shot 之后补安全段、旧写法历史脱敏、人设描述按预算截而不是在 900 字处硬截。服务端 PR 要「合」，评测重跑约 ¥3 要「花」。
3. **外貌口径一行**：客服提示词里的「银白长发带薄荷绿挑染的**少女**」与陪聊的「一个**成年**、银白长发…」不一致（09-24 已定「成年」，客服漏改一处），服务端一行，Play 合规相关，建议单独先合。
   市场形象加「一句话外观」字段等市场有社区包再做。
4. **「带我去」**：服务端给一份落点白名单（设置 / 钱包 / 形象 / 人格 / 创作 / 声音…），模型在句首写 `[goto:id]`，App 收到画一颗跳转键，跳过去用现成的 `data-guide` 锚点把按钮圈出来；顺带做 caps 握手。
   提示词每轮多 150~600 字（我们付的模型成本略增，没量过），评测约 ¥0.5~3。依赖 2 先上。
5. **拿不准先问**：回答末尾 `[ask:问题|选项A*|选项B]`，App 画成 2~4 颗可点的选项，推荐项排第一、必须是不花钱可回退的那一支。点一次选项仍是一轮 400 token，芯片上要标价 —— 牵出「客服页一个价都不标」（见 10）。
6. **只告诉模型当前形象做得到的动作**，被要求举手、抬腿、指按钮时照实说做不到、不拿别的动作顶替（约 60 字的一句提示词 + 按形象映射裁剪）。生产市场还没有社区包，眼下起作用的只有那一句。评测约 ¥0.3~3。
7. **客服查本人的账**：服务端已有只读、只查本人的任务扣费 / 退款状态（`/api/ark/task-charges/:id`、`/api/ark/video-tasks`）与流水（`/api/me/wallet/ledger`），客服没接。
   接上的话「帮我查一下昨天那单为什么失败」能直接答。要定：流水交给 DeepSeek 算不算把数据分享给第三方；禁止承诺第 37 条要改口。
8. **版本号进提示词**：服务端已经把 `X-App-Version` 解析成 `req.appVersion`，但契约写明「只进日志」。放进提示词能省掉「你用的是哪一版」那一轮 400 token，
   但知识库停在「当前版 2.64」、实际已发到 2.70 —— 先刷新知识库再做，否则模型会拿新版本号去对旧的「当前版」。
9. **开场白跟人格走**：服务端已经下发人格的 greeting，知识库也对用户承诺过「开场白会带进客服页」（KB:1041），App 没读。
   但它和「客服身份是小梦、人格只改语气」冲突，会把没审核的用户原文作为官方客服的第一句话 —— 要么做（加一行固定的职责小字），要么把知识库那句改掉。
10. **客服页标价**：整页一个价都不标（每问 ⚡400，开着声音另按字计），与 CLAUDE.md「价钱一律 priceTag」相反。数要由 `/config` 下发，涉及服务端。
11. **知识库补「数字人：形象 / 人格 / 声音 / 自己做模型」一节 + 评测题**：现在用户问「为什么传不上去」「一张图能不能做 Live2D」，小梦只能转人工。
    要照实写「一张图自动生成可动的 Live2D 目前做不到」，导去第三方站点（HF 上的 See-through 演示）属于产品取舍；建议等 1 的许可结论。
12. **Seedream 图层拆分小验（约 ¥1~5）**：从小梦高清原图裁头部和手，每次点名 3~5 个部件（上下睫毛、瞳孔、高光、手指），和现在 See-through + LaMa 的结果逐像素比；
    同时对比更便宜的 5.0 flash。官方没写像素保真到什么程度，UP 说「色彩些微有变化」。合格了也还要在 Cubism 里手工重新挂网格、重键参数
    （编辑器版本的事见私有笔记）。做成用户功能（「立绘一键分层」）是新的付费能力，等 1。
13. **客服回答、Live2D 形象、声音模板的举报**：要服务端给 Report 加 targetType；人格那一类这次已接上。
14. **形象市场「先看看」+ 搜索 / 热门**：生产市场眼下零社区包，按「空架子不摆筛选」现在不做；等 1 的结论与市场有内容之后再做。

## 五、外部事实（带出处，2026-10-25 查）

- **Seedream 5.0 pro / flash 图层拆分**：`POST /api/v3/images/generations` 加 `layer_decomposition: true`，`image` 必须且只能 1 张；prompt 可空（自动拆）、可点名、可配合涂鸦 / 圈选、可写 `<bbox>` 归一化坐标；
  一次同步返回 1 张底图（z_index 0）+ 最多 16 层透明 PNG，每层带 bounding_box 与名字；任一层失败整单报错；输出最大约 2K；输入只收 png / jpeg、512²~6000²、≤30MB；
  不是组图（5.0 pro / flash 不支持组图）；价目 ≤261 万像素 0.15 元 / 层、更大 0.30 元 / 层（economy.ts:852-853 早有记录），一次最坏 17 × 0.30 = 5.10 元；
  预扣 17 IPM、与普通出图共用 500 IPM；图片地址保留 24 小时。我们的服务端单张出图路由有意拦掉了这个参数（那条路按一张收钱）。
  出处：https://docs.volcengine.com/docs/ark/seedream-5-0-pro 、https://www.volcengine.com/docs/ark/image-generation-api 、https://www.volcengine.com/docs/82379/1544106
- **Krene 背后是不是 Seedream**：没有官方说法；旁证（功能一一对上、输入栏价钱 = 12 ×（2..17）正好对上 17 张上限）指向是，UP 口头「最多 18 张」与之不符。
- **vtuber2d.ai**：「VTuber2D.AI — Anime Layer Decomposition」，上传 PNG/JPG → 1~2 分钟 → 下载 PSD，按积分收费、Stripe（卡 + 微信），等候名单；See-through README 明说作者没开过任何收费服务。
  视频里的 VTuber2D Creator 工程存成自家 `.vt2d.json`，没见 .moc3 导出，GitHub 搜不到。
- **See-through**：约 4.8k star，代码 Apache-2.0，V3 模型 23 个部位层；权重 2026-09-28 补全许可（LayerDiff 3D、深度模型是 Open RAIL(++)-M，分割 SAM 是 Apache-2.0）——
  可商用，但**以服务形式**运行 Open RAIL 模型要把用途限制写进我们的使用条款。我们现在只在开发机上离线给自己的看板娘拆层，不受这一条约束；做成给用户的服务就受。
- **Bunraku**（arXiv 2607.27348）：代码与权重仍未发布（只有 07-31 的 readme），三个问开源时间的 issue 都没回；论文自己说因为 Cubism 二进制加密，输出的是自家资源包 + 自家渲染器，不是 .moc3。
- **StretchyStudio**（MIT）04 月起能导出 .moc3 与 .cmo3 并自动绑定；**image2live2d**（Apache-2.0，10-16 建仓）能无头把 See-through PSD 绑成 nijilive，另出实验性 .moc3。两者的 moc3 写入器都自述来自逆向 —— 不能接。
- **nijigenerate**（Inochi2D 分支，BSD-2）10-10 发了 v1.0.0-beta4，内置 AutoRig 面板与 MCP 接口（agent 可以调它绑定）—— 但格式是 nijilive，我们的运行时是 pixi-live2d-display（roadmap 已定不换）。
- **Cubism Editor 5.3.00**（2026-01-20）没有新 AI 功能；官方「素材分离」PS 插件要 PRO 许可；没有任何官方的无头导出 / API。
- **nizima** 的 AI 政策禁止上架「把 AI 生成插画做成 Live2D」的作品（Editor 自带辅助功能做的不算）。
- **HAST-SEC**：10-13 建仓，许可 `hast-sec-noncommercial-0.1`（只许非商业学习研究）；0.8B 是 Qwen3.5-0.8B（Apache-2.0）Q8_0 GGUF；动作求解跑在浏览器（three.js + three-vrm），LLM 跑本机 llama-server，单用户本地演示，不能直接当多租户服务。
  动作素材是重定向的 CMU 轨迹 + BEAT2 统计模型，视频里说的「20 万元光学动捕」公开版里没有。
- **moc3 一致性检查**：Cubism 官方建议加载 .moc3 之前先调 `csmHasMocConsistency()`（公开安全公告 CVE-2023-27566）；这次加载路径上补了这道检查（`live2d/mocCheck.ts`）。
- **业界「带我去 / 高亮按钮」**：Copilot Vision 的 Highlights（用户共享一个窗口后说「show me how」才标出该点哪里，用户发起、可停）是最接近的；Gemini Live 的视觉指引高亮的是相机画面里的实物；
  Intercom Fin 在对话里启动产品导览还只是社区请求。Clippy 的教训（粗糙规则主动打断）说明这类能力应当由用户发起。

## 六、不建议做的

- 接 HAST-SEC 本体：非商业许可，而且是单用户本地演示。
- 在服务端替用户自动生成 Live2D（不管是跑 Cubism Editor 还是用逆向的 moc3 写入器）：许可上走不通，见四之 1 的私有笔记。
- 把客服的看板娘换成 3D / VRM：roadmap 已定运行时不换，视频 4 的好处（演出跟声音、动作协同）在 Live2D 上就能拿到。
