## 1. 三块各自还原了什么

### 1.1 顶栏（A 案「克制极简」）→ `ui/GameHud.tsx`

撤掉 G2 以来那条居中药丸（`bg-panel/85 + ring + backdrop-blur`）与里面的 8 段血条 / 心形血量，
换成设计稿 A 案的一条**读数带**：

```
[黄铜圆表 46] [● 阶段] [回合 3/8 + 8 道刻线] [计时 0:42] …… 对手条（中间那一格） …… [金币 21px + 利息预告]
```

- 信息只有三档：**主数字**（金币 21px、回合 16px）/ **卡名**（阶段 11.5px 衬线 + 0.16em）/
  **标签**（6.5~8px + 0.26em 字距）。没有第三档字号（设计稿 A 案那一句）。
- 没有面板底色：只有一颗阶段前面亮着的 4px 圆点、阶段名底下一条 1px 铜线、金币那一格的字号差。
- 利息预告是金币下面那一行 7px 小字：`利息 +1 · 下回合 +6`。**数来自 `rules.incomeFor`**
  （利息 10 金一档、上限 5 —— 这条公式与结算早就在线上，这一轮只搬进 HUD 展示，没动结算）。
- 计时从底部阶段条搬到这里（见 §5「与设计稿的差异」第 4 条）；位置在 `--game-hud-top`
  （安全区 + 52px：上面那一排 44×44 圆键让出来的高度）。
- 左起点 `--game-hud-left` = 左上角玩家面板的右沿（它展开时也占那一列，HUD 让位）。
- `pointer-events-none`：HUD 是读数，不许挡桌面上的卡。

### 1.2 黄铜圆表（B 案「一个数一枚表」）→ `GameHud` 里的 `.game-dial`

- **显示的是「生命值」**（`view.hud.hp` / `rules.START_HP`，规则层夹在 0~100）。
  设计稿 B 案的表盘就是生命（`B-table-852.png` 左上角 78 那枚，红色 conic 弧）；主人给的选择里
  也写了"或血量，若现有规则里没有血量" —— 规则层本来就有血量（`settleRound` 扣血、100 血出局），
  所以直接取它，不编"本阶段投入卡数"这种假指标。
- 构成：**conic 弧**（`--p` = hp/100，从 180° 起，红铜 `rgb(203 128 116)`）+ **12 道刻线**
  （`repeating-conic-gradient` 30° 一道）+ **压印牌面**（径向渐变 + 1px 铜边 + 内阴影，数字 15px + `生命` 5.5px）。
- 直径 **46px**（设计稿 52px @ 852；见 §5 第 2 条为什么缩到 46）。
- 全案**只此一枚同亮度铜牌**：顶栏右组原来的「生命 78 + 一条血条」整条撤掉（同一个数摆两处，
  一处是仪表、另一处只是重复）。

### 1.3 缝线卡位（C 案）→ `scene/cardTexture.stitchedSlotTexture` + `scene/TableScene` 的 `SlotPlate`

- 3D 桌面那 5 个位子（4 角色 + 1 场景）的框，从"发光的实线圆角框（`ringTexture`）"换成
  **针脚虚线 + 四角十字结**：虚线 `[34, 24]`、线宽 9、四角十字结 11px（纹理像素，512×768 的
  canvas 纹理），与设计稿 `.c-slot` 同一套视觉参数。
  ★ 那一层没有 DOM（是 3D 平面），针脚只能画进纹理；DOM 那一侧（右侧道具栏 / 创作面板的
  5 个位）用 `index.css` 的 `.game-stitch` / `.game-stitch-x`，两处针脚参数对着写。
- **空位是唯一亮着的可拖入目标**：空位常态黄铜针脚（alpha 0.6）；拖着一张卡时**所有空位一起亮**
  到 0.85；正悬在它上面 1.0 且位内文字换成「松手放下」；已放卡的位子按角色青 / 场景金（0.45）。
- 空位那行字从「+」换成「空位」/「松手放下」（`slotHintTexture`，512×256，字 84px —— 4:1 的
  旧文字纹理铺在 2.1:1 的扁条上会被拉高，空位那两句单开一份 2:1 的纹理）。
- 右键道具栏（`ui/ItemRail`）也换成 C 案：撤掉面板底色，拆除工具 / 没有道具两格是缝线框 + 四角十字结。

### 1.4 商店栏 / 背包栏（A 案）

- **商店栏**（`ui/ShopPanel`）：从"居中的圆角面板"改成**满宽的顶部横带** ——
  `linear-gradient(180deg, rgba(4,4,4,.94), rgba(4,4,4,.82) 58%, transparent)` + 一条横贯的
  1px 铜架线；5 张商品卡站在线上、价钱挂在架下（每格自己画一段线、左右各伸 5px 接成一条），
  抬头是「商店 / 第 N 回合 · 计时 / 点一张就买下 / 金币 21px」，右端是三行无底色操作
  （刷新 / 锁定 / 离开，各一条下划线）。
- **底带**（`ui/BagBar` + `ui/PhaseBar` + 贴纸键 + 商店键）：屏幕下沿**一条横带**，
  上沿一条从中间淡出的 1px 铜线、不铺底板；左边「手牌 N + 拖卡到桌面空位 + 每张卡「卖 +1」」，
  右边「提示 → 贴纸 → 利息商店键 → 实心主键」。原先"背包条 / 阶段条"上下两行并成一行
  （把屏幕下沿那 ~40px 还给桌面）。
- 主键是**全案唯一一处实心键**：黄铜渐变 + 深字 + 44px 高（`.game-primary`）；
  商店键 / 贴纸键是 44 高的铜线小键（`.game-chip`），商店键上写"利息 +N"。

### 2.2 缝线在真机 dpr 下清不清楚

- 纹理 512×768，铺在投影后约 **60~67 CSS 宽**的卡位平面上 ⇒ ~7.6~8.5 纹理像素 / CSS 像素；
  真机 dpr 3.5 时相当于 **2.2~2.4 纹理像素 / 设备像素**（three.js 的 `CanvasTexture` + mipmap +
  anisotropy 4），针脚一段 34 纹理像素 ≈ **4 CSS 像素 / 14 设备像素**长、线宽 9 纹理像素
  ≈ 1.1 CSS / 3.9 设备像素粗。
- 模拟器（dpr 2.625）截图里针脚是**一段一段的虚线 + 四个十字结**，看得清（`04-drag-hover.png`
  里 4 个角色位 + 场景位都清楚）；真机 dpr 3.5 只会更细一档、不会糊成实线。
  ⚠ 真机这次没接上（`adb devices` 只有模拟器），上面是按纹理分辨率推的数，**没有真机截图**。

## 3. 与设计稿的差异（逐条 + 原因）

1. **顶栏在"系统 chrome 那一排圆键"下面一行，不在屏幕最上沿。**
   App 里那一排是 `✕ 结束对局 / ? / ⚙ / 🧩`（44×44，`--safe-float-top` 起），不能删；
   HUD 只好落在它们下面（`--game-hud-top` = 安全区 + 52）。设计稿没有这一排。
2. **圆表 46px（设计稿 52px）。** 真机 800×363 + 41px 状态栏时，顶栏 + 创作面板 + 底带
   三者是紧贴的：`--safe-float-top`=49 → HUD 底 = 153；手牌满 4 张时创作面板顶 = 154.9
   （模拟 800×363 + 把 `--safe-float-top` 覆盖成 49 实测）。46 是"再大就把创作面板顶掉"的上限。
3. **HUD 左起点让开左上角玩家面板**（`--game-hud-left` ≈ 169），不是设计稿的 20px。
   App 的玩家面板（👥 本桌名单）常驻在那一列、展开时也在，HUD 不抢它。
4. **计时从底部阶段条搬进顶栏**（设计稿 A 案顶栏本来就有"计时"）。一屏只留一处时钟：
   `ui/PhaseClock` 同时挂在顶栏与商店栏抬头（商店开着时顶栏让位）——构建门禁钉着这一点。
5. **对手条进顶栏中间那一格**（设计稿没有对手条）：底带并成一行之后，再给对手条单独一行
   就会压到创作面板上（真机 363 高），所以它进流、由 GameHud 摆在左组与金币之间，窄屏截断。
6. **商店栏的三行操作在货架右端，不在屏幕最右端**：屏幕最右端是那排 44px 圆键（它们在商店
   阶段被抬到 `z-35`、压不住也点得着）。所以"刷新 / 锁定 / 离开"跟着货架走，右端留白。
7. **底带的「卖 +1」是 20px 高、整张卡宽**（设计稿 5.5px 字）：44×44 热区纪律与"363 高"冲突 ——
   卖是误触代价很高的动作，给了 20px 高（原来 10px 的圆片），宽度仍是整张卡。
8. **商店的"已买走"格用缝线框**（C 案），设计稿 A 案是普通虚线 —— 与桌面卡位同一套针脚。
9. **没有做"背包栏展开成抽屉"那一屏**（A-bag-852）：App 的交互是"手牌常驻底带 + 拖到桌面"，
   抽屉会多一次开合；设计稿那一屏的信息在底带里都有（手牌数 / 每张卖 +1 / 拖到桌面空位）。
10. **顶栏加了一条很轻的文字阴影**（设计稿的背景是暗角，3D 场景的月亮墙偏亮）。
11. **没有"点卡查看"这一屏**：对局内本来就没有卡详情页（点商店卡 = 买下、点桌面卡 = 开始拖、
    点背包卡 = 开始拖）。验收里用「点一张卡买入 + '买好了' 回执 + 那一格变已买走」当这一项。

## 6. 剩余风险

1. **真机没接上**（`adb devices` 只有 `emulator-5554`）：真机 dpr 3.5 下的针脚清晰度是按纹理
   分辨率推的（§2.2），**没有真机截图**；真机 800×363 + 41px 状态栏的布局是在模拟器上
   `Emulation.setDeviceMetricsOverride(800×363)` + 覆盖 `--safe-float-top: 49px` 量的。
2. **真机 363 高 + 手牌满 4 张时最紧**：HUD 底 153、创作面板顶 154.9 —— 只剩 **1.9px**。
   再给 HUD 加一行字、或把「卖 +1」加高回 22、或创作面板长高，这三处就会叠。
   谁要动其中一处，先跑 `.tmp-hud/measure800.mjs` 那套量法。
3. **贴纸气泡栈抬到底带上方之后**：创作 / 展映屏里 5 条气泡堆满时栈顶在 y 140.4、底 242，
   与创作面板（x 32~768 / y 154.9~248.8）的**左下角**重叠 **~20px**（那一块是第一张卡的左沿）。
   本机局实际最多同时 4 条（我 2 秒 1 条 + AI 每回合最多 2 条）；4 条时栈顶 157 → 与面板顶
   只差 2px。这是旧版就有的取舍（旧版压的是阶段条），这一轮把它换成"让开底带、代价是偶尔
   压住面板左下角一条边"。
4. **商店栏横带 136.8 高**（363 的 37%）：比旧的商店面板高，NPC 的头刚好露在带子下面；
   如果以后相机机位再往下压，带子会吃她的脸。
5. **文字阴影是兜底**：标签那一档在背景最亮处只有 4.39:1（§2.1）；要更稳就得铺一条顶栏黑纱，
   与 A 案"没有面板底色"冲突，留待主人定。
6. **「点卡查看」这一项没有对应界面**（对局内没有卡详情页），验收用"点卡买入"代替（§3 第 11 条）。
