# 工作流节点的「自选卡片 / 自定义」对齐 LibTV 节点 —— 调研与方案

> 2026-10-03。主人问：LibTV 的工作流每个节点是怎么做的？和我们（自定义 = 首尾帧 + 素材卡 + 视频要求 + 可选示例视频）是功能类似，还是有更精准的方式？
> 本文先答这个问题（§一 ~ §三），再给对齐方案（§四），主人的拍板在 §五，落地记录在 §六（N1、N3、N2 都已落地；N2 原计划的付费实测被官方文档免费回答了大半，剩一小笔可选的验证等主人定）。

## 结论先行

1. **功能同族，但 LibTV 更精准，精准在三处**：
   ① 参考素材是**在提示词里内联点名**的（第几张图管什么，由作者写在用到它的那半句里），我们是系统在提示词尾巴上**替用户统一点名**；
   ② 一个视频节点里可以写**多个镜头**（带时间段、硬切）和**逐句台词**（每句前面挂谁的音色），我们一段只有一个镜头；
   ③ 「关键画面」是**先做图再出片**的中间产物（图片节点一步步改：换装 / 去人 / 改时间 / 裁脸，还能从成片里截帧接着用），我们的设定帧只能整张重画或上传。
2. **输入的种类我们并不缺**：帧、素材卡的形象图、参考视频、声音样本，LibTV 视频节点收的也是这几样（图 / 视频 / 音频混排成一张有序清单）。缺的是「怎么点名」与「一段里怎么排时间」。
3. **高手在 LibTV 上几乎不用首尾帧**：两条精选作品 232 个出片节点里，「全能参考」（多参考混排）占 200 个，文生视频 30 个，首帧图生视频只有 2 个，首尾帧 0 个。我们 08-30 定的「帧一律当参考图发」与它是同一个方向。
4. **建议分三步对齐**（§四）：N1 参考清单 + @ 点名（两个模式共用，收益最大、不依赖新能力）→ N2 分镜表（多镜头 + 台词，先开在自定义）→ N3 关键画面可以「改一改 / 从成片截」。**不搬连线画布**：我们的流水线仍是一条线，参考来自卡与帧。

## 一、LibTV 的节点是怎么做的

### 1. 节点是「带类型的素材」，连线只表示「谁给谁当参考」

节点类型：文本、图片、视频、音频、脚本（表格）。每个节点 = 一份素材 + 它是怎么来的（上传的 / 生成的 / 编辑出来的）。
连线的方向就是「上游给下游当参考」。两条作品里连线的种类与数量：

| 连线 | 写实短剧 | 古装短片 | 意思 |
|---|---|---|---|
| 图片 → 视频 | 101 | 284 | 这张图是这段视频的参考 |
| 图片 → 图片 | 32 | 442 | 在上一张图的基础上改 / 合成出下一张 |
| 音频 → 视频 | 20 | 0 | 声音样本（音色）给这段视频 |
| 视频 → 视频 | 10 | 5 | 后处理：高清化、去字幕 |
| 视频 → 图片 | 0 | 72 | 从成片里截一帧（截图 67 / 尾帧 4 / 首帧 1）当后面的参考 |

### 2. 视频节点 = 提示词 + 一张有序的参考清单 + 四个设置

一个出片节点的参数就这几样：

- **模型** 与 **生成模式**（文生视频 / 全能参考 / 图生视频 / 首尾帧 / 图片参考，按模型灰显）；
- **提示词**（见下一小节）；
- **参考清单**：图片、视频、音频各一张表，另有一张把它们**混排**起来的总表 —— 提示词里的「第 N 个参考」认的就是这张总表里的次序。每一项记着它来自哪个上游节点；真人肖像另带一个「已认证素材」的编号；
- **设置**：画幅（可选「跟随参考」）、分辨率、时长、是否出声；高级里有联网搜索、自动校验素材。

实测分布：

| | 写实短剧（26 个出片节点：全能参考 22 + 文生视频 4） | 古装短片（全能参考 178 个；另有文生视频 26、图生视频 2） |
|---|---|---|
| 参考数（全能参考的节点） | 图 1~7 张，其中 10 个节点另带 1~3 段音频；合计 1~9 个，多数 4~8 个 | 1 个的占 114，2 个 38，3 个 16，最多 9 个 |
| 时长 | 4~13 秒为主，另有 25 / 26 / 30 秒各一条 | 4~15 秒，5 秒最多（69） |
| 分辨率 | 480p 20 个、720p 6 个（之后接「高清」节点升到 2K） | 1080p 145 个、720p 24 个、4K 4 个 |
| 出声 | 全开 | 175 开 / 3 关 |
| 一个节点里写了几个镜头（按「镜头 N」字样数） | 没标的 6、1 个 7、2 个 3、3 个 4、4 个以上 6 | 基本都是一个镜头 |

两种工作方式都成立：**写实短剧**是「多参考 + 一条节点多镜头 + 台词」；**古装短片**是「先把这一镜的关键画面做成一张图，再一图一镜」。

### 3. 提示词里内联点名 —— 这是「更精准」的核心

提示词里直接插「第 N 个参考」的标记（界面上是一颗可点的芯片），插在**用到它的那半句**里。按句式归纳有六种用法（例句是示意，不是原文）：

| 用法 | 示意 |
|---|---|
| 定身份 | 「@图1 @图5 是甲，@图4 是乙」—— 同一个人给两张（全身 + 面部），再起一个代号，后文只用代号 |
| 指环境 | 「环境参考 @图6，时间是中午」 |
| 指站位 / 构图 | 「位置关系参考 @图1」「他们从左至右分别是 @图2 @图3 @图4」 |
| 指局部 | 「女子面部参考 @图6」「着装参考 @图2」 |
| 指道具 | 「手里拿着 @图4 的袋子」「照片上是 @图3」 |
| 指音色 | 「甲捂着嘴说 @音频3：……」—— 音频标记插在那句台词前面 |

图片节点同理：「@图2 的衣服换成 @图1」「去掉所有人物，时间改成深夜」。

### 4. 一个节点里的时间轴

写实短剧那条，一个 7~12 秒的节点里常写 2~4 个镜头：每个镜头一句「机位 + 景别 + 谁做什么 + 说什么」，有的带时间段（「镜头 1：1~4 秒……镜头 2：4~8 秒……」），开头统一声明「分镜之间硬切、不要字幕、不要背景音乐」。
提示词因此很长：风格与禁忌的通用前缀就有三百多字，整条常在 500~900 字。

### 5. 关键画面是做出来的

- 图片节点一步只改一件事（换装、去人留景、改时间天气、裁出脸），改出来的新图再接给后面的节点；古装短片 463 个图片节点、442 条图 → 图连线就是这么来的。
- 出图有「相机控制」预设（机身 / 镜头 / 焦距 / 光圈）。
- 从成片截帧（任意一帧 / 首帧 / 尾帧）变成图片节点，接着当下一段的参考 —— 段与段的衔接靠它。
- 先低分辨率出片、满意了再接「高清」节点，是省钱的常规做法。

## 二、我们现在怎么做的

| | 自选卡片 | 自定义 |
|---|---|---|
| 用户给什么 | 挑素材卡 + 写一句要求；运镜芯片；档位 / 画幅 / 时长 | （可选）一段示例视频；首帧 / 尾帧（上传、AI 画、融图；首帧空着 = 承接上一段尾帧或 AI 补画）；有示例视频时可再加最多 2 张中间帧；素材卡；一段视频要求 |
| 中间一步 | AI 推演三套方案，各带首尾帧，挑一套（可改剧情、换帧、圈选重画） | 没有，直出 |
| 发给模型的 | 镜头字段前缀 + 剧情 + 「本段固定素材设定：人物卡「甲」＝出片句；……」+ **系统写的**绑定句（「将 <图片1> 的面部特征定义为角色「甲」……」或紧凑式「甲=@图片1@图片2」）+ 帧的时序点名（「图片 N 是第一帧 / 最后一帧」）+ 音色句（「「甲」的台词使用参考音频 1 的音色」） | 同左（少了镜头字段），有示例视频时加一句「参考视频提供整体画面、运镜与节奏」 |
| 参考图上限 | 高清档 9 张、电影级 30 张；极速 / 标准两档协议上不收参考图 | 同左 |
| 提示词上限 | **400 字**（`types.VIDEO_PROMPT_MAX`），含上面所有系统句；超了从正文尾巴截 | 同左 |
| 一段几个镜头 | 一个（`ShotSpec`：景别 / 运镜 / 情绪节拍） | 一个 |
| 台词与音色 | 剧情里有引号台词 + 卡带声音样本 + 档位出声 → 自动挂（`segmentGen.voiceRefsFor`） | 同左 |

实现位置：模式页签与编辑窗 `components/flow/FlowCanvas.tsx`（NodePanel）、帧位 `CustomFrameSlots`、提示词拼装 `studio/segmentGen.ts`（`materialText` / `customRefPrompt` / `voiceRefsFor`）、参考图分配与绑定句 `ai/real.ts`（`prepareMaterialRefs` 的 `bind` / `bindCompact`）、档位能力 `data/economy.VIDEO_TIERS`。

## 三、差在哪儿

| | LibTV | 我们 | 差距 |
|---|---|---|---|
| 参考怎么点名 | 作者在句子里内联，逐个说它管什么 | 系统在尾巴上统一写「图 N = 卡名」，正文靠卡名指人 | **表达不了**「站位照这张」「左起第二个是他」「只借这张图的脸 / 衣服」「这张图是他手里的照片」；一次性的图（不是卡）进不来 |
| 参考清单看不看得见 | 检视器里一排编号缩略图，可增删、可调序 | 发之前用户看不到「第几张是谁」（步骤日志里只有一行「参考图 N」） | 用户不知道模型实际收到了什么；档位收不下时哪张卡没发图也只是一句提示 |
| 一段的时间 | 多镜头 + 时间段 + 硬切 | 一个镜头；多镜头只能靠多开几段 | 一段 10 秒只能是一个长镜头；多开段 = 多付几次钱、多几道接缝 |
| 台词 | 逐句写、逐句挂音色 | 有引号就自动按卡挂，一段里谁说哪句由模型猜 | 多人对话时音色会串 |
| 关键画面 | 图片节点逐步改 + 从成片截任意帧 | 整张重画 / 上传 / 融图 / 圈选重画；只自动取成片首尾帧 | 「就把衣服换了」「去掉路人」这类小改要整张重来 |
| 提示词容量 | 500~900 字常见 | 400 字封顶（含系统句） | 多镜头 + 台词根本放不下。⚠ 400 这个数是按 1.x 两档时期定的，2.x 两档能吃多长**没量过** |
| 我们有、它没有的 | — | 方案台三套方案带首尾帧预览（花视频钱之前先看）；卡的出片句逐段逐字复用（一致性）；段间自动承接；参考图按档位预算自动分配；报价与契约对账 | 这些要留着，是我们对新手友好的那一半 |

## 四、对齐方案（建议）

原则：**不搬连线画布**（流水线仍是一条线；参考来自卡、帧、示例视频、临时图），对齐的是**节点内部**——两个模式共用同一套「参考清单 + 点名 + 分镜表」，区别只剩「关键画面谁给」：自选卡片 = AI 推演三套方案替你出，自定义 = 你自己给。

### N1 参考清单 + @ 点名（先做；两个模式都用；不依赖新能力）

- 编辑窗里加一排**参考清单**：按真实发送顺序编号的缩略图（首帧、各卡的各张形象图、中间帧、尾帧、示例视频、声音样本），发之前就看得到「模型会收到什么」；档位收不下的卡当场标「只发文字」。可删、可调序。
- 提示词框里打 `@`（或点清单上的一张）插入一颗**引用芯片**；出片时编译成模型认的「图片 N」，插在用户写的那半句里。被点过名的参考不再在尾巴上重复绑定（省字数）；没点名的照旧由系统兜底写绑定句 —— 所以不点名的用户行为一个字不变。
- 清单上每一项可选**用途**：人物形象 / 面部 / 服装 / 场景环境 / 道具 / 站位构图 / 画风。用途决定系统兜底句怎么写（今天只按卡种与图位写）。
- 「＋ 参考图」：加一张**不是卡**的一次性图（站位草图、道具照片），只在这一段生效。
- 方案台的三套方案由 AI 写剧情时直接带芯片（它知道这段挂了哪些卡）。
- 守住的线：绑定句与编号仍只有 `prepareMaterialRefs` 一处算（编号错一位就是「张三的脸给了李四」）；极速 / 标准两档不收参考图，芯片在那两档退成卡名。

### N2 分镜表：一段多镜头 + 逐句台词（先开在自定义，再让方案台产出）

- 一段可以有 1~4 个镜头，每个镜头：时间段（默认均分，可拖）、景别 / 运镜（沿用 `ShotSpec` 词表与运镜芯片）、一句画面、可选一句台词（说话人从这段的人物卡里选；卡带声音样本就把音色挂在这一句上）。
- 编译成「镜头 1（0~3 秒）：……；镜头 2（3~7 秒）：……。镜头之间硬切」+ 每句台词前的音色点名。
- 只在出声且收参考的两档开放（高清 / 电影级）；段时长上限跟档位走（电影级到 30 秒）。
- **前置：要先量提示词上限**。多镜头 + 台词 400 字放不下，而 2.x 两档到底能吃多长、长了之后前半截的绑定还听不听，没有数据。要花钱实测（高清档几发 + 电影级一两发，估算 30 元以内；真跑之前报准确价）。量完再定 `VIDEO_PROMPT_MAX` 按档位分几档。
- 报价不变（仍按时长 × 档位）；一段多镜头比多开几段便宜，接缝也少 —— 这是它对用户最直接的好处。

### N3 关键画面可以「改一改」与「从成片截」

- 帧位与卡的形象图上加「改这张图」：一句话的小改（换装 / 去人留景 / 改时间天气 / 只留脸），改出新的一张、旧的留着可回退。是现有圈选重画 / 融图 / 去人留景那几条出图路的收口，不是新出图能力。
- 成片回看里加「截这一帧」：任意时刻截一帧，放进参考清单或当另一段的起拍画面（今天只自动取首尾帧）。

### 暂不做

- 连线画布、文本 / 脚本节点、技能芯片：与「对话 + 卡片」的产品形态不合，主人 09-08 已定方向。
- 「先低清出片再高清化」：要方舟侧有可用的视频超分并核价，另议。
- 出图的相机机身 / 镜头预设：我们的运镜芯片管的是视频这一侧，出图那一侧收益不明。

## 六、落地记录

### N1 参考清单 + @ 点名（2026-10-03）

**做了什么**

- 画布编辑窗（自选卡片 / 自定义两个车道）与工坊方案台多了一排**参考清单**：出片时视频模型会收到哪些图、各是第几张（首帧 → 尾帧 → 临时参考图 → 各张卡的形象图），发之前就看得到；没分到图的卡写明「只按文字参与」；带不带示例视频、台词带不带声音样本也在这一排说。
- **临时参考图**：`＋ 参考图` 加一张不是卡的一次性图（站位草图、道具照片…），一段最多 3 张，各有名字与用途（站位构图 / 场景 / 道具 / 服装 / 画风 / 其它）。出片时排在帧之后、卡片形象图之前当参考图发；出片前 AI 补画设定帧时也带上它们（站位构图那一类只给起拍画面）。
- **`@` 点名**：在句子里写 `@名字`，或点清单上的一张图把它写进句子。出片时「`@杯子`」变成「杯子（图片 5）」；点过名的临时参考图不再由系统重复说明，没点名的由系统按用途补一句（「图片 4「站位草图」只取人物站位与构图，不照搬长相画风」）。写了 `@` 却没对上的，清单下面当场提醒，出片那一行进度里也说。
- 不收参考图的档（极速 / 标准 / 真人）：清单说明为什么排不出来，点名退成名字本身，临时参考图不发并说出来。

**和 §四 的方案不一样的地方（都是有意的）**

| 方案里写的 | 实际做的 | 为什么 |
|---|---|---|
| `@` 一律编译成「图片 N」 | 临时参考图与帧 → 「名字（图片 N）」；**素材卡 → 只留卡名** | 卡的身份绑定早就由系统写（「凛=@图片4@图片5」，一张卡常带两三张图、谁被额度挤掉只有分配那一处知道），正文靠名字指人是付费 A/B 验过的现行做法；把卡也内联成编号等于同一条绑定规则写两遍，错一位就是张冠李戴。名字留着是因为人会写「递来@杯子」——光换成「递来图片 5」读不通 |
| 清单上每一项都能选用途 | 只有临时参考图有用途 | 卡的用途由卡种与图位决定（人物卡的脸 / 全身、场景卡的定场），那套说法已经在绑定句里 |
| 清单可删、可调序 | 临时参考图可删；**没做调序** | 编号由分配规则算（帧 → 临时参考图 → 卡，卡按挂卡顺序），调序等于改「额度不够时谁先被挤掉」，要连挂卡顺序一起做，放到看反馈之后 |
| 方案台的三套方案由 AI 写剧情时直接带芯片 | 没做 | 卡的点名编译出来就是卡名，AI 写的剧情里本来就是卡名，带不带 `@` 发出去一个字不差 |

**已有功能的复用（没有另做一套的）**

| 用到的 | 复用的是 |
|---|---|
| 上传的图怎么压、越界怎么办 | `utils/image.fileToRefImage`（卡片形象图同一条：长边 1024、比例越界居中裁并说出来） |
| 图转成模型收的公网地址 | 与设定帧同一个转存循环（`api/uploads.uploadImage`） |
| 谁分得到图、额度怎么扣 | `ai/real.allocateRefs`（新增只读出口 `planCardRefs`）；帧与临时参考图占的位在准备卡片图那一步就扣（`segmentGen.refSlotsOf`，出片与清单预览共用的唯一判定） |
| 卡的绑定句、帧的时序点名句 | `prepareMaterialRefs.bindCompact` / `customRefPrompt`，一个字没改，只是编号的起点把临时参考图数了进去 |
| 字数上限 | `VIDEO_PROMPT_MAX`（与输入框、运镜芯片同一个常量；点图插入会超就不插并说明） |
| 「文字是唯一真身」 | 与运镜芯片同一个做法：亮不亮只看句子里有没有这个点名，不另存状态 |
| 公开配方 | 临时参考图不随配方走，记号复用 `mid-frames`（文案改成「另给过自己的参考图」），句子里的 `@名字` 退成普通文字；服务端零改动 |

**顺手改进的已有功能（主人点名的那一类）**

- **台词带声音样本**：原来只认「」与直引号，中文输入法打出来的弯引号 “” 不认 —— 写成 “你来了” 的台词会被配音，人物卡的声音样本却没带上（音色随机，零提示）。现在 “”、『』 都认（`segmentGen.hasDialogue`）。
- **声音带不上要提前说**：卡带着声音样本、这一发却带不上时（句子里没有引号台词 / 这一档出片无声 / 出片方式带不了参考音频），参考清单在出片之前就说原因；原来只在出片那一行进度里说，或者（没写引号时）根本不说。

**规则在哪**

- 点名的认法、编译、名字规则、系统兜底句：`src/data/refMentions.ts`（纯函数，构建里 `scripts/check-ref-mentions.mjs` 实跑 118 条正反例；13 条改坏的写法逐条试红过）。
- 排队编号：`segmentGen.refPlanOf`（界面经 `flowStore.nodeRefPlan` 读），与出片共用 `refSlotsOf`；出片前拿同一份输入再排一次，张数对不上写一句「参考清单核对」进步骤日志。
- 数据：`FlowNode.extraRefs`（与帧同形：本机 dataURL，出片时才转存；回炉工程瘦身后地址为空的当没有）；增改删三个 action 在 flowStore（查重名、上限、改名 / 删除顺手收拾句子里的 `@名字`）。
- 界面：`components/flow/RefStrip.tsx`（只收 props，两个面共用）。

**怎么验的（没花钱）**

本地 dev 开离线模式 + 假的方舟密钥，页面内把 `fetch` 换成桩（只拦 `/api/ark/` 与上传图片），点真实的「生成本段」键，读桩里记下的请求体。四条路各跑过：
① 高清 + 两帧 + 两张临时参考图（一张点名、一张不点名）：8 张参考图顺序为 帧 1-2、临时 3-4、卡 5-8，绑定句「凛=@图片5@图片6；老周=@图片7」，正文「按站位草图（图片3）的位置…」，尾巴只替没点名的那张说话；
② 标准档：只发首尾帧，点名退成名字，进度行说明临时参考图没发；
③ 高清 + 没给帧：两次画帧请求里起拍画面带 5 张图（卡 3 + 临时 2）、结束画面带 4 张（站位构图那张不带），随后出片 7 张、编号顺延正确；
④ 电影级 + 示例视频 + 中间帧：视频 + 帧 1-3 + 临时 4-5。
另验了：经真实文件口加图（300×1500 的长图被裁成 300×900 并提示）、改名（句子里的点名跟着换）、重名 / 保留名被拒、删除（点名退成文字）、点图插入、工坊那一面、弯引号台词带上了参考音频。

**这一版没做的**

- ~~自选卡片车道推演三套方案时画的首尾帧不照临时参考图画~~ —— N3 已接上（见下）。
- 简约模式那一页没有参考清单。
- 提示词容量还是 400 字：三张临时参考图全不点名时系统兜底句最多占约 103 字。容量要等 N2 的付费实测再定。

### N3 关键画面可改、可截（2026-10-03）

**先交主人要的对比：我们已有的「圈图改图」与 LibTV 的图片节点**

LibTV 的做法是「先做图再出片」：关键画面是一个个图片节点，每个节点做一步小改（换装 / 去人 / 改时间 / 裁脸），改对了才连到视频节点；视频节点还能截出任意一帧接着用。
我们其实已经有四种改图的手段，问题不在缺能力，在**摆的位置与时机不对**：

| 我们已有的 | 入口在哪 | 对比下来的问题 |
|---|---|---|
| ⭕ 圈选改画面（圈出一处 + 一句要求，Seedream 只改圈里的） | 只在**成片回看**里；标注存在段上，**重炼这一段时**才生效 | 要先花一次出片的钱才看得到画面，改完还要再花一次出片的钱才看得到结果。出片**之前**的设定帧上不能圈 |
| ✨ AI 改首帧 / 改尾帧（一句话改，带卡片形象图锁脸） | **只有工坊方案台**有 | 画布的方案台与「自定义」车道都没有 —— 同一件事两面不一样；实现也只长在工坊那边 |
| 🎨 融图（挑两三张图融成一帧）、🎬 导演台（摆站位截图融成开头帧） | 方案台、自定义车道的两格帧 | 没问题，留着；只是融图的候选里没有临时参考图 |
| 上传 / 清掉这一帧，✨ 按改过的剧情重画这一套 | 方案台 | 重画是整张重来，「就把伞换成红的」这种小改也得整张重画 |
| 成片的帧 | 只自动取首帧（当预览）与尾帧（给下一段承接） | 中间任意一刻的画面拿不出来 |

对比时还查到一个**实打实的缺陷**（不是摆放问题）：圈选的画板写死 1280×720、把图拉伸着画满，成片回看截帧也是按 16:9 裁的 ——
而默认画幅是竖屏：竖屏帧在画板里被压扁，回看截出来的只有画面中间一条（约三分之一高），圈不到上下的东西；这张变形 / 被裁的图随后又被当成底图去重画一张竖帧，圈外的内容也跟着变了。
（剪辑页那一处早就按画幅截了，画布与工坊的回看、简约页没跟上。）

**所以 N3 做的是「把已有的手段挪到该在的地方」，没有新造出图能力**

- **改这一帧**（出片之前）：首帧 / 尾帧各一颗「✨ 改首帧 / 改尾帧」，两种改法——写一句话改，或者先圈出一处再改；一张图的钱，改好顶替这一帧并锁住。
  画布的自定义车道、画布方案台、工坊方案台三处是**同一个组件、同一处实现**（`flowStore.editFrame`；工坊原来那份 `refineProposalFrame` 现在只是转发）。
  圈着改用的就是成片圈选那个画板（`FrameAnnotator`），那句「只改圈里的、去掉红圈」全仓只留一份（`segmentGen.ANN_CLAUSE`，原来两处各写一份）。
  常用改法给了几颗填词的小键（去掉路人 / 改成夜晚 / 改成下雨天 / 换个表情 / 黄昏光）。句子里写 `@参考图名字` 会把那张临时参考图一并带上（「把她手里的东西换成 @杯子」）。
  这一段承接着上一段结尾时，改的是那张承接帧，改完这一段就不再承接（与上传自己的首帧同一条规则，改之前当面说）。
- **圈选画板跟着画面的比例走**：竖屏帧不再被压扁，成片回看 / 简约页截帧按原比例截整帧（`FrameAnnotator.drawWhole`）。成片圈选、卡片形象图圈选、剪辑页圈选重拍都受益。
- **📸 截这一帧**：成片回看里截下正在看的那一刻，选它的去处——当某一段的首帧 / 尾帧，或加进那一段的参考清单（后面没有能放的段时可以当场新开一段）。
- **临时参考图进了所有画帧的路**：推演三套方案、按修改重画这一套、出片前补画，都照着它们画（站位构图那一类只给起拍画面），规则一处（`refMentions.drawExtraRefs`）；融图的候选里也有它们。

**没做的**

- LibTV 那种「一步一个图片节点、留着每一步的中间图」的链条：我们只留最后一张（改好的顶替原来的）。要回退只能再改一次或重画。
- 圈选仍是一次圈一处。

**怎么验的（没花钱）**：同 N1 的桩法。一句话改首帧（请求里 5 张图：底图 1、卡 2-4、点名的临时参考图 5，编号与绑定句对得上，改完写回并锁住、本机账本按一张图记）；
圈着改尾帧（画板 720×1280、发出去的标注图 720×1280、只带这一张图、带那句圈选指令）；推演三套（首帧各 5 张图、尾帧各 4 张，站位构图那张只进首帧）；
📸 截帧（竖屏假成片截出整帧 720×1280 → 新开一段 → 当参考图 / 当首帧，首帧上锁且不再承接）；工坊方案台上同一个组件改帧成功。

### N2 分镜表：一段多镜头 + 台词（2026-10-03）

**先查了官方文档 —— 原计划「花钱量提示词上限」的那几个问题，文档直接答了**

查的是火山方舟「创建视频生成任务」API 文档（2026-09-22 版）与「Seedance 2.0 提示词指南」，都是公开页面，没花钱：

| 原来想花钱量的 / 设计里想当然的 | 官方怎么说 | 我们怎么办 |
|---|---|---|
| 2.x 两档的提示词能吃多长 | 「中文提示词不超过 500 字，英文不超过 1000 词。字数过多易导致信息分散，模型可能忽略细节」—— 是建议值，不是协议硬顶 | 高清 / 电影级的上限从 400 提到 **500**（`economy.promptMaxOf`），不再往上放；极速 / 标准 / 真人档与白模段仍是 400 |
| 多镜头怎么写 | 用「镜头 1 / 镜头 2 / 镜头 3」标识、按事件顺序写，每个镜头写「镜头怎么动 + 谁做什么 + 在哪 + 声音」 | 分镜表写出来就是这个格式 |
| 要不要写每个镜头的秒数（§四 的方案里写了「0~3 秒」，LibTV 的熟练作者也这么写） | **不要**：「模型对精确时间（如 0–3 秒）的支持不稳定，强行限制时长可能导致生成结果异常」，优先让模型按剧情分配节奏 | 分镜表**不让填秒数** —— 这一条与 §四 的原方案不同，以官方为准 |
| 台词怎么写才会被配音 | 对话放在双引号内，例：男人叫住女人说：“……” | 「＋ 台词」插的就是 `凛说：“”`；`hasDialogue` 已认中文弯引号（N1 那次补的） |
| 参考音频能带多少 | 2.0 系列：单段 2~15 秒、最多 3 段、**合计不超过 15 秒**；2.5：单段 2~30 秒、最多 10 段、合计不超过 30 秒 | 原来只数「最多 3 张带声音的卡」、没看合计 —— 三张卡各录 8 秒就会整发被拒。现在按合计时长装（`segmentGen.fitVoices`），装不下的在参考清单里提前点名 |
| 参考图的尺寸窗口 | 宽高比 [0.4, 2.5]、边长 [300, 6000]px（比出图模型那一套 1/3~3 更窄） | 临时参考图上传时按这个窗口裁 / 放大（`utils/image.VIDEO_REF_WINDOW`）。⚠ 卡片形象图上传仍按老窗口，比例在 2.5~3 之间的卡图直接发给视频模型有被拒的可能，记在那个常量上，另议 |
| 参考素材越多越好吗 | 不建议用满上限，推荐总计 4~5 个（角色图 1~2 张 + 场景图 + 运镜视频 + 音频） | 没动分配规则（那是另一件事）；参考清单让人看得见一共发了几张 |
| 一段最长多久 | 2.0 系列 4~15 秒，2.5 是 4~30 秒 | **没放开**：我们的报价与服务端结算都把时长夹在 10 秒以内，放开要两仓一起改、单次出片也会贵到几十元，等主人定（见下） |

**做了什么**

- **分镜表**（`components/flow/ShotListEditor`）：一个镜头时就是原来那一个输入框，发出去的字一个不变；点「＋ 镜头」把这一段写成 2~4 个镜头（另有一行「整体交代」放人物 / 地点 / 氛围），点「＋ 台词」选说话人（带 🔊 的人物卡按它自己的声音配）。
  画布「自定义」车道的要求框、两面方案台里选定那一套的剧情框，用的是同一份。只在高清 / 电影级能加镜头和台词（别的档不出声、也不收参考）。
- **文字是唯一真身**：分镜表不另存结构，它只是那段文字的结构化编辑（读写规则在 `data/shotScript`，构建里 `scripts/check-shot-script.mjs` 跑 146 条正反例，17 条改坏的写法逐条试红）。
  所以老草稿、做同款、公开配方、对画布说话、手打的「镜头1：…」都天然兼容。出片前空镜头会被收掉、编号重排（`packShots`）。
- 运镜芯片对着**正在写的那个镜头**亮灭与插入；点参考清单上的图插 `@名字` 也是插进正在写的镜头。
- 上面表里那几条：上限 500、声音样本按合计时长装、临时参考图按视频模型的窗口裁。

**合进去当天补的三处（#350 之后的跟进，同样没花钱）**

#350 合进去之后，回头把上一轮只过了类型检查、没在浏览器里实际点过的两处（两面方案台里的分镜表）补点了一遍，这次一个键一个键地敲，抓到三件事：

1. **分了镜之后，行尾刚敲的空格 / 回车会被吃掉**：打英文「Rin walks」出来是「Rinwalks」。原因是每一格的值都是「写回整段文字 → 再读出这一格」绕一圈回来的，
   而第一版在读、写两头都去了首尾空白。上一轮的 44 条用例和浏览器验证都是整串一次写进去的，测不出来。现在读写原样（只认自己加的那一个换行当分隔），
   去首尾空白只在发出去之前做；没分镜的那一个输入框不受影响（它一直是原样的）。
2. **手打镜头标识时焦点会丢**：在一句普通的话里打完「镜头2：」的冒号，输入框当场换成两格，原来那个框被卸掉，后面的字敲不进去；
   在最后一格里接着打「镜头3：」，多出来的第三格是空的而光标还留在第二格。现在光标跟着走到它该在的那一格。
3. **方案台里那一栏太窄**：手机上只有 185px，并排摆「镜头 N」+ 输入框 + ✕ 之后输入框只剩 102px（一行 7 个汉字）。现在方案台里把「镜头 N」与 ✕ 叠到输入框上面，
   输入框回到 185px（一行 13 个字，与没分镜时一样宽）；画布「自定义」那一栏本来就够宽（262px），不动。

顺带：没有临时参考图时，帧的时序句与素材设定之间会拼出两个句号（「……衔接自然。。本段固定素材设定……」，N1 那次只修了有临时参考图的那一半），一并去掉。

**复用了已有的什么（主人点名的那条总则）**

- 「逐句台词挂音色」**没有新做一套**：人物卡的声音样本（卡片页上传本地音频 / 现场录音 / 从原视频取）与出片时的音色点名句（按卡名把台词接到参考音频上）都是已有的。
  缺的只是「把说话人的名字写对」与「提前知道带不带得上」—— 前者由「＋ 台词」的骨架保证，后者由参考清单那两行（🔊 带上了谁 / 🔇 谁没带上、为什么）说清。
- 镜头里的运镜词用的是已有的运镜芯片词表；景别 / 运镜 / 情绪节拍那个结构化字段（`ShotSpec`）照旧是整段一份，写在最前。

**没做的 / 等主人定的**

1. **一小笔可选的付费验证**（官方文档答的是「该怎么写」，没法替我们确认「我们拼出来的那一整段在两档上跑出来什么样」）：
   高清档 10 秒一发（3 个镜头 + 两个人各一句台词 + 两份声音样本）≈ ¥5.01，高清档 5 秒一发（2 个镜头 + 一句台词）≈ ¥2.51，起拍 / 结束画面与声音样本的准备 ≤ ¥1；合计 **≤ ¥8.5**（刊例价；2.0-mini 到 10-07 14:00 前有 4 折活动，账面可能更少）。
   想连电影级一起看再加 10 秒一发 ≈ ¥15.25，合计 **≤ ¥23.8**。不验也能用，只是「多镜头听不听话」是照文档写的、没亲眼看过。
2. **段时长放到 15 秒（高清）/ 30 秒（电影级）**：多镜头最吃时长，但要动两仓的价目与夹值，电影级 30 秒一发约 ¥46。要不要做、放到几秒，等主人定。
3. 推演三套方案时让 AI 直接把剧情写成分镜；简约模式那一页。
