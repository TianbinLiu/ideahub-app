## 3. 落位推导（splat 世界 → 游戏世界）

### 3.1 第一步：坐实"**splat 帧 = 01 相机帧**"

把 splat 摆成**恒等变换**（预览页 `gsScale=1&gsYaw=0`、位置抵消成 0），相机放 `cameras.json` 里 01 的位姿：

```
position  (0, 0.83875, 0)
rotation  四元数 (-0.009439, 0.316174, -0.002145, 0.948652) ⇒ 只含 36.87° 的 yaw（俯仰 -1.1°、翻滚 -0.24° 可忽略）
intrinsics fx=fy=1074.2416, cx=640, cy=360 （1280×720 ⇒ 垂直 fov 36.9°）
```

渲出来与 ZIP 里的 `01-room-master.png` **逐处对得上**（圆窗的十字棂、壁炉的雕花与花瓶、右侧书柜、长桌与跑表、顶部斜梁）。
⇒ 由此定下这间屋子的**房间基**（后面所有量法都用它）：

```
U = (0, 1, 0)                     上
F = (-0.6, 0, -0.8)               朝窗（= 01 相机的 forward）
R = F × U = (0.8, 0, -0.6)        朝右
房间坐标：s = p·R（右）、d = p·F（朝窗）、h = p·U（高）
```

### 3.2 第二步：点云打射线量锚点

做法：在参考图上点像素锚点 → 从 01 相机打射线 → 在 2M 高斯里取**方向落在 1° 锥内**的点、按距离排序取前 30 个的均值（= 前表面）。
读数（splat 单位；括号里是换到房间坐标后的 s / d）：

| 锚点 | 像素 | h | s | d | 说明 |
|---|---|---|---|---|---|
| 桌面·跑表中 | (645,440) | **0.577** | 0.03 | 3.45 | 桌面顶面 |
| 桌面·近端中 | (645,492) | 0.50 | 0.04 | 2.62 | 桌子近端 |
| 桌面·远端中 | (650,388) | 0.69 | 0.03 | 4.27 | 桌子远端（贴窗那一头） |
| 桌面·左缘/右缘中 | (530/768,440) | 0.56 / 0.58 | −0.34 / +0.43 | 3.28 / 3.32 | ⇒ 桌宽 ≈ **0.77** |
| 地板·前左 / 前右 | (300,690)/(1000,660) | **0.00 / 0.00** | — | — | 地板就在 h=0（相机高 0.84） |
| 圆窗心 | (647,190) | **2.03** | 0.11 | **7.83** | 正对中线、直径 ≈ 1.9 |
| 壁炉·炉膛 | (200,450) | **0.48** | **−1.548** | **3.94** | 火占位用它 |
| 壁炉·台面 | (150,235) | 1.14 | — | — | 台面比桌面高 0.56 |
| 书柜·中 / 窗右墙 | (1100,400)/(950,200) | 0.69 / 1.96 | 1.67 / 1.95 | 4.0 / 7.8 | 屋子约 4 宽 × 8 深 × 3 高 |

得到两个关键结论：**桌面 1.65（沿 d，长轴）× 0.77（沿 s）**；**桌子是顺着视线摆的**（近端 0.50 → 远端 0.69，参考图里近端宽 310 px / 远端 160 px 就是这个纵向透视）。

### 3.3 朝向：**yaw = −36.87°，这次不转 90°**（★ 与上一版相反，是这一版最重要的取舍）

- 上一版：桌子的长轴在屋子里是 z、而本仓桌面是 16×7（长轴 x），所以转了 90° 让"桌长轴 = X"，代价是窗墙被拧到 −z 之后**窗与长轴不能同时成立**——上一版能同时成立，是因为那间屋子的窗墙本来就与桌长轴垂直。
- 这一版：**窗与桌长轴是同一个方向**（桌子一头指着圆窗）。转 90° 会让圆窗跑到侧墙（违背"圆窗在正对面"），并且是**从重建没拍过的一侧**看这间屋子（§1.1）。
- 所以这一版 **yaw = −36.87°（= 抵消 01 相机的 yaw，屋子保持参考图里的朝向）** ⇒ 圆窗 −z（正前方）、壁炉 −x（左）、书柜 +x（右），与参考图逐处一致，也没有镜像（别用负 scale 去凑朝向：法线/阴影/背面剔除会一起反）。
- 代价（写在前面）：**我们的 mesh 桌面（22×9，长轴 X）与这间屋子的长桌（长轴 Z）是 90° 交叉的**。这一版用"把整张桌子藏进盖板底下"来消化它（见 3.5 的 SCALE）——桌面完全看不见，交叉也就看不出来。

### 3.4 尺度与平移

| 常量 | 值 | 依据 |
|---|---|---|
| `SCALE` | **3.2** | 桌面 1.65×0.77 → **5.28 × 2.46** 世界单位。上限卡在**纵向**：桌面纵向 = 1.65·SCALE，必须整段压进盖板 z∈[−4.5, 4.5]（9 深）⇒ **SCALE ≤ 5.45**；取 3.2 留了 41% 余量（tilt 还会把桌面近端抬起来，余量在这里是要的）。横向 ±1.23 远窄于盖板 ±11，两侧边缘本来就在画框外（近边可见半宽 ±3.7、远边 ±6.4） |
| `TARGET` | **[0, −1.1, 0]** | 桌面顶面中心落到 (0,−1.1,0)。Y 低的 1.1 = 让桌面（含下面 tilt 抬起来的近端 0.64）全部躲在盖板顶面 y=0 以下；Z=0 = 桌子落在盖板正中 |
| `YAW_DEG` | **−36.87°** | 见 3.3 |
| `TILT_DEG` | **−14°** | 见下 |

### 3.5 ★ 俯仰 −14°（这一版**新增的一位**，上一版只有 yaw）

为什么非加不可（算式）：重建相机是**桌面高度、平视**（高 0.84，见 §3.1），而我们的相机在桌面上方 **3.9**、俯角 **30°**（`layout.LAND_CAM`）。
同一个房间从高 5 倍的位置往下看，**圆窗（比桌面高 1.45 splat 单位 = 4.65 世界单位）会被顶到画框上方**：

- 不 tilt 时：圆窗落在视平线**以上** 11°；而画面顶只到视平线**以下** 5°（fov 50、俯角 30）⇒ 看不见。
- 两条路可以把它拉回来：
  1. **整间屋子往下沉**（上一版那种 `targetY` 让让）—— 窗回来了，但**壁炉整块消失**（台面只比桌面高 0.56 splat 单位 = 1.8 世界单位，沉 4.9 就沉到盖板顶面以下）；
  2. **只把远端往下压**（tilt）：近处的壁炉/柜子几乎不动，圆窗靠"远端下沉"落进画框。
- 取 **tilt = −14°**（绕游戏 X 轴，负 = 远端下压）后：圆窗心在视平线下 **9.6°**；窗在**竖墙上**而我们是俯视，纵向被压扁 cos(30°+14°)≈0.72 ⇒ 纵向角半径 ≈5.5°，整颗窗落在画面顶（视平线下 5°）与盖板远边（18.1°）之间那条可见带里，实测截图上窗顶离画面顶约 8 px；壁炉台面 y=+0.20、烟囱顶 y=+3.5 ⇒ **露在盖板之上**，雕花台面与花瓶都能看见。
- 代价（自己认下来，别以后当成 bug）：墙会略前倾 14° —— 这间屋子本来就有斜顶斜梁，读不出来；**地板的倾斜被盖板远边整块挡住**，看不见；桌面本身也是斜的，但它在盖板底下，看不见。
- **核过"整张桌子真的在盖板下面"**：tilt 把桌面近端抬起来 `(0.825×3.2)×sin14° ≈ 0.64`，`TARGET_Y = −1.1` 留够了余量 ⇒ 最高的一点在 y≈−0.46，仍在盖板顶面（0）以下。

### 3.6 最终常量（`gsStep0.ts`，改落位只改这一处）

```ts
const ANCHOR = { tableTopH: 0.577, tableS: 0.04, tableD: 3.445, tableLen: 1.65, tableWid: 0.77,
                 floorH: 0, winH: 2.03, winD: 7.83, fire: { s: -1.548, d: 3.94, h: 0.48 } };
const CENTER = toSplat(ANCHOR.tableS, ANCHOR.tableD, ANCHOR.tableTopH);  // splat 帧 xyz
const YAW_DEG = -36.87;   // 抵消 01 相机 yaw：圆窗 −z、壁炉 −x、书柜 +x
const TILT_DEG = -14;     // 远端下压，把圆窗压进画框（见 3.5）
const SCALE = 3.2;        // 桌面 5.28×2.46，整段藏进 22×9 盖板
const TARGET: [number,number,number] = [0, -1.1, 0];
```

变换写法（这一版从"手写 cos/sin 只支持 yaw"改成 Euler 算一遍，多一位不用重对符号）：

```
position = TARGET − SCALE · (Euler(TILT, YAW, 0, 'XYZ') 作用在 CENTER 上)
rotation = [TILT, YAW, 0]
```

★ **踩过的坑**：`CENTER` 必须是**splat 帧的 xyz**，不能把 (s,d,h) 三个数直接塞进去（`toSplat()` 这一个小函数就是干这个的）。
第一次写成 `[tableS, tableTopH, tableD]` 的结果是：圆窗跑到画面右边、桌子偏到 −x —— 看起来像 yaw 反了，其实是屋子被多转了一次。

dev 覆盖（生产构建里恒不生效）：`?gs=1&gsYaw=&gsTilt=&gsScale=&gsX=&gsY=&gsZ=`（`gsTilt` 是这一版新加的）。

## 6. 已知风险（第 2 步要拍板的）

1. **炉膛在盖板顶面以下 ⇒ 真火现在看不见**。壁炉炉膛比桌面低 0.31 世界单位（0.48 vs 0.577 splat 单位 ×3.2），而盖板顶面就压在桌面高度上 —— 只要"盖板盖住整张桌子"这条不变，炉膛就永远在它下面。
   要接真火有两条路：① 方案 B（把桌面与桌上物件从 splat 里切掉、盖板只做卡位）之后炉膛自然露出来；② 把这间屋子重出一版更深的（桌子离墙更远、炉膛更高）。**`GS_FIRE` + `GS_FIRE_LIGHT.position` 这两个接口就是为这两条路留的**，换真火时只改 `GsStep0Environment` 里那一段。
2. **屋子比盖板窄 ⇒ 左右墙切进桌沿**（§5 接缝那条）。要干净得把 `SCALE` 提到 ~5（屋子 20 宽就能把墙推出画框），但那时圆窗的角半径会到 9°，超过"画面顶到盖板远边"那 13.1° 的可见带 ⇒ 圆窗会被裁。**这一版选了"圆窗完整"而不是"角落干净"**。
3. **单视角重建的天花板**：屋子里没拍过的那一侧、以及近处的墙，都是从一条视线推出来的，近距离看是拉伸的糊面（截图左右两角那两团）。要更干净只能多拍/多补视角重出。
4. **竖屏机位没适配**：竖屏走 `DEFAULT_CAM`（俯视 9.8 高），落位是按 `LAND_CAM`（横屏、俯角 30°）量的；App 锁横屏，只有浏览器竖屏窗口会看到，那时圆窗不在画里、盖板仍在。
5. **桌面与盖板的 90° 交叉**（§3.3）：这一版靠"整张桌子藏在盖板底下"消化，所以**不能**再把屋子抬高到桌子露出来 —— 一露就与盖板交叉。第 2 步做桌面切除时这条会自然解开。
6. **真机帧率仍未量**：浏览器 143.8 fps 只是基线。2M 高斯 / 4.25M tris 在手机上的读数要用设置页那两档（全部 / 0.8M）+ 角标量。
