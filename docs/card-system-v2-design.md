# 卡片系统 V2：带声音的人物卡 + 圈选提取 —— 可行性调研与设计

2026-08-23 调研。两个需求：① 人物卡加音频，出片时人物对话直接用卡上的声音；
② 「从视频提取」改成逐帧圈选式的卡组/卡片提取（道具圈一帧、人物圈一帧再定一段）。

**结论先行：两个都可行，且比设想的路更近** —— 关键事实是 Seedance 2.x 原生支持
**参考音频输入**与**引号台词配音 + 对口型**，人物卡的"声音"可以先不做声音复刻、
直接存一段声音样本喂给出片模型。全部 V1 工作不引入任何新的供应商依赖。

### 阶段 0 实测结果（2026-08-24 直连，本账号）

已钉死：

- **音频 content 项 schema**：`{ type: "audio_url", role: "reference_audio", audio_url: { url } }`，
  与 reference_image/reference_video 同款式；**base64 dataURL 直接被受理**（69KB mp3 实测），
  不需要先托管 —— 声音样本可以像帧一样从 IndexedDB 直接发。
- **⚠ 设计级约束：首尾帧模式不能混参考媒体**（400
  `first/last frame content cannot be mixed with reference media content`）。
  参考音频只能配 reference_image 模式用。**这与工作流"上一段真实尾帧承接起拍"（first_frame）
  正面冲突**：一个段要么锁死起拍帧、要么带音色参考，二选一。V1 的取舍：
  带台词的段把上一段尾帧降级为 reference_image（软承接）+ 参考音频；不带台词的段照旧
  first_frame 硬承接。衔接损失多大要在阶段 2 实拍里看。
- 首帧模式下 `ratio` 不许传（跟随首帧图），参考图模式下必须传 —— 两种模式的参数集不同，
  接线时 arkClient 要按模式分支。
- **② 计费钉死：参考音频输入零加价**。同提示词/同参考图各一发（2.5、4s、720p），
  带与不带参考音频的 usage **逐位相同**（completion_tokens 87,300 = 87,300），
  且返回里根本没有输入侧 token 项。报价公式不用为音频加任何一项。
- **③ 台词确实被配音**：两发成片都带真实语音级音轨（A -23.5dB / B -27.1dB，
  高于此前纯环境音的 -27.5dB 基线），时长 4.06s。带参考音频那发明显更响
  （台词更突出）。**音色跟随成色（① 的最终判定）交由用户耳朵评**——已把
  样本 + A/B 两片发给用户；粗基频（自相关）三者都在 238~241Hz，分不出音色，
  这个客观量太粗，不作为判据。

## 二、设计：人物卡的声音

### 数据模型（阶段 2 实做时改为**本机侧库**，2026-08-24）

实现在 `data/cardVoice.ts`：`{cardId → {dataUrl, durationSec, note}}` 一张表存 IndexedDB，
**不进 Card 对象**。改的理由：卡在远端模式的真相是服务端那份（loadRemoteAssets 冷启动
整体覆盖 db.cards），Card.voice 要活下来就得四处一起改（branch payload / ApiCard /
toLocalCard / server zod）外加一次服务端部署，且 MB 级样本走卡同步会撑爆请求体。
侧库按 cardId 存本机，卡怎么覆盖都不掉 —— 代价是声音**不跨设备、不随分享**，
恰好就是"分享不带声音样本"那条设计。样本格式：24kHz 单声道 16-bit WAV dataURL
（15s ≈ 960KB），抓取走 ScriptProcessor 直取 PCM（实播一遍、任意大小视频不炸内存），
不走 MediaRecorder（webm/opus 容器的 decodeAudioData 支持面没保证）。

- 卡面/选卡器加 **🔊 徽标**，选卡器可按"有无声音"筛（用户点名的需求）。
- 分享到工坊的卡带不带声音样本：**V1 不带**（样本是本机 blob；上传涉及他人声音的
  授权问题，先不开这个口子）。

### 出片时怎么用（V1 主路）

段落 plot 含「」/"引号台词、且档位 `audio: true`、且挂了带声音的人物卡时：

1. `generateVideo` 的 content 里**追加该卡的声音样本**为参考音频（≤3 段上限内，
   多主角按出场顺序取前 3）；
2. 提示词点名：「角色 X 的台词请使用参考音频 N 的音色」；
3. 对口型由模型原生完成 —— **不需要我们做任何音画对齐**。

三条闸（全部必须，防静默骗人）：

- 档位不支持音频（fast/std）→ 界面明说「此档出片无声，台词只会以画面呈现」，
  **不许**收下台词装作会出声；
- 参考音频语义实测不达标（音色跟不上）→ 退化为"台词照常合成、音色随机"，
  卡上的 🔊 说明里写清"音色跟随为尽力而为"；
- r2v（白模复刻）路保持 `generate_audio: false` 不变 —— 那条路的声音是原片音轨。

### V2（可选，另立项）：声音复刻

样本 → ICL 训练 → `speaker_id` 存卡上 → 任意台词走 TTS（现有 V3 代理加一个
resource id）→ CutPage 混音进成片。价值：**让 1.0 无声档也能有配音**（画外音，
无对口型）、台词不限于出片那一刻。代价：控制台开通 + 按音色付费 + 授权合规。
**V1 不做**：主路（参考音频）零新增供应商、零新增计费项，先把主路走通。

## 三、设计：圈选提取（视频 → 卡组/卡片）

### 入口

「🎬 从视频提取卡片」→「从视频提取**卡组 / 卡片**」：选卡片 = 圈一张就走；
选卡组 = 同一条视频上连续圈多张，攒成一个卡组落库。共用同一个提取会话。

### 交互流（复用现有部件）

1. 选本地视频（**不上传** —— 与经典配方同一承诺，全程本机）；
2. 视频预览 + 拖进度条到目标帧（VideoStage 现成）；
3. 点卡种 → 圈选：**圆形（可缩放）/ 矩形 / 画笔**。画笔生成 mask 后抠出
   透明底 PNG（客户端 canvas 可做）；圆/矩最终都落成一张**紧裁剪参考图**；
4. 人物卡多一步：在时间轴上**再点一帧定段**（帧 A→帧 B），段内产两样东西 ——
   身份参考图（帧 A 的圈选裁剪，可再标一帧脸部特写）+ **声音样本**
   （客户端 `decodeAudioData` 解整条 PCM → 按 A/B 秒切片 → 编成 WAV，
   全程不出设备）。切完**必须试听确认**再入卡：段里没人说话/有 BGM 干扰时，
   这一步是用户唯一的把关点；
5. 起名/简介/genPrompt：默认**手填**（0 token，与「自己传图做卡片」同路）；
   一颗可选的「让 AI 看一眼」按现有铸卡价走豆包 vision + Seedream 洗卡面。

### 各卡种的圈选逻辑

| 卡种 | 圈选 | 产物 |
|---|---|---|
| 道具 | 单帧圈选 | 裁剪/抠图 → detail 参考图 |
| 人物 | 帧 A 圈选 + 帧 B 定段 | body（圈选裁剪）+ face（可选再标）+ 声音样本 |
| 场景 | 单帧（默认整帧，可裁） | body 全景图 |
| 背景 | 单帧圈选背景区域 | 色板/氛围参考 |
| 风格 | 单帧**整帧**（不圈——风格是全画面属性，圈局部反而误导） | 整帧参考 |

### 为什么这条路对"高精度"是最优的（论证，不是断言）

方舟的一致性机制**只吃参考图**（Seedream `image` 参数 / Seedance 2.x 参考图），
没有任何接收 mask 或坐标的入口 —— 所以圈选的全部价值就是产出**特征更纯净的
紧裁剪参考图**（背景杂物 = 特征污染，方舟指南明说素材过多难判优先级）。
紧裁剪 + 抠图恰好是把这条指南做到极致；人物一致性靠 face+body 两张，正是现有
CARD_SLOTS 的形状 —— **不需要改生成侧一行逻辑，精度收益自动生效**。

### 清空旧卡（范围已定：**全部清空**，2026-08-24 用户拍板）

- 一次性迁移把本机的卡与卡组**全部清掉**（含用户自己铸的 —— 已明示不可逆并获确认），
  卡片系统从 V2 的形状重新开始；
- 市场货架的离线种子同步换成空态；
- 迁移带版本号，只跑一次；服务端已分享的卡（工坊广场）不在本次范围。
