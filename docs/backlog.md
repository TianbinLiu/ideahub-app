## 1. 方舟 2.0 `asset://` 真人肖像授权（真人卡合规出片的"正路"）

**状态**：设计已定（见 [`card-prompt-scheme-market-design.md`](card-prompt-scheme-market-design.md) 附录 A），**前置已解除**——仓库主人的火山引擎账号**已完成企业实名认证**（2026-08-24 确认）。

**流程**（方舟官方，非绕过）：建素材组 → 方舟生成真人认证 H5 链接/二维码 → **被拍的本人**手机打开做**活体检测 + 人脸核验 + 肖像授权** → 上传该人素材（**只收 URL**，不收 base64）→ 每次上传做**同人校验**（与授权时采的基准脸比对）→ 得 `asset://<id>`。出片时当参考图传，文本里用「图片N」指代、不写 asset 原文。

### 1.1 产品形态（仓库主人 2026-08-24 拍板）

- **仍然是一张人物卡**：app 里不新开实体，就是 `Card`（`type:"character"`），只是多一枚**「真人认证」标记**。用户的心智模型不变（卡还是卡）。
- **不可分享、不可发布到创意工坊市场**——这是**默认且当前唯一**的行为。理由：资产绑死在**我们的**火山企业账号下，被授权人授权的是"给这个账号用其形象"，**不含**"允许任意第三方拿去出片"。把它挂上市场等于我们替被拍者做了一个他没同意的授权。
  ⇒ 实现上是**一道闸**，不是一句提示：`shareBlockReason` / 发布路径 / 卡组快照三处都要拒（参照 `realFaceIssue` 的形状，判据**唯一实现**一处）。
- **两条"以后可以放开"的路，条件写清楚**（现在不做，但设计时别把门焊死）：
  - **(a) 形象公开化** —— 若 app 内能让被拍者**把自己的形象授权给他人/公开**（即授权范围从"某账号"扩展到"平台内公开"），那么这张卡就**可以**发布到创意工坊市场。⇒ 授权态要设计成**枚举**（`private` / `public`）而不是布尔，否则将来放开时存量数据无法区分"没授权"和"只授权了自己"。
  - **(b) 用户绑定自己的火山账号** —— 若能做到用户在我们 app 内完成**火山引擎账号注册 + 绑定**，则该用户的真人素材资产应当绑在**他自己的火山账号**下（而不是我们的企业账号）。这条更干净：授权链、计费、数据责任都回到用户自己头上，我们只是工具。⇒ `asset://` 的持有者要设计成**按账号存**（`ownerVolcAccount`），别写死成"平台账号"。

### 1.2 落地要点

- **第三条 provider 分支**：`providerOf` 现在 `"ark" | "minimax"`，加 `"ark2-asset"`。与已有的 MiniMax 真人档分叉同构，`segmentGen` 照抄那条 dispatch。
- **卡与资产解耦**：本地只存"这个人的 `asset://` id + 授权态 + 授权范围"，**不塞进 `Card` schema**（同 `cardVoice` 侧库的理由：不进 schema、不随分享、避免 zod strip）。
- **出片闸**：没授权/授权过期的真人卡 → 整句拒 + 指向"请本人扫码授权"（`realFaceIssue` 再加一态，判据仍唯一实现）。
- **授权 UI**：把 H5 链接渲染成二维码 + 轮询 session 状态。
- **计价**：Seedance 2.0 纯生成 46 元/百万 token（≈1 元/秒）、含视频输入 28 元/百万 —— **约本仓锚点（15 元/百万）的 3×**。要单开档位与 `flatCost`，**报价=实扣**跨仓钉死（照 MiniMax 真人档先例）。

### 1.3 动工前仍要确认

1. **官方素材库 REST 路径与字段**：设计doc附录 A2 里的路径来自转售商代理文档，**必须**对着火山官方 `82379/*`「素材库 API 参考 / 录入真人形象素材」核对再写死。
2. **直连火山 vs 转售商**：真人活体/肖像属生物信息，**直连火山**（授权链清晰、资产在自己企业账号下）。转售商只适合非真人的 2.0 能力。
3. **一发真机探针**：`asset://` 主体 + `reference_video`（白模 r2v）**能不能同用**——没有任何资料，必须实测。这条通了才谈得上解开"真人卡 × 白模模板"那个双向死路。

## 2. 提示词方案市场（已完成，留几条约束）

三件剩余项 2026-08-24 全部做完：**自建方案编辑屏**、**预览示例图**、**远端共享市场**
（server 的 `PromptScheme` + `/api/branch/schemes`，6 例 spec）。

⚠ 后续改这块时不能破的三条：
- **市场不得按"绕过真人检测的成功率"排序或标注**——那会把中立工具变成主动帮凶
  （design doc §B2）。`faceless` 只描述**产出形态**，排序键也只有它 + 更新时间。
- **预览示例图不得是真人**（判据唯一实现 `promptSchemes.exampleIssue`）。
- **`data/promptSchemes.ts` 必须保持叶子**（只依赖 types）。联网那半边在
  `data/schemeMarket.ts`：promptSchemes 一旦 import videos 就成环
  （videos → account → mock/ai → promptSchemes），Vite 下拿到半初始化模块。
