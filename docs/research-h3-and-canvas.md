# 调研：MiniMax H3 档位方案 与 画布化创作（2026-08-20）

两项调研的原始问题：① MiniMax H3 能否在阿里云自部署、什么价位，能不能当「高清档」，
让档位变成 Seedance 1.5 / MiniMax H3 / Seedance 2.0 / Seedance 2.5 四选；
② 对照 updream.cn 与 liblib.tv，在保住「卡片/卡组」特色的前提下对齐 AI 视频生成形态，
工作流与工坊互通可切换，工作流改成无限画布+卡片。

---

## 一、MiniMax H3：结论 = 不自部署，走官方 API 当「高清有声档」

### 事实（2026-08-20 调研，来源见括号）

- **形态**：H3（Hailuo 3.0）2026-07-17 发布，**08-03 开源了基座权重**（HF/ModelScope），
  但三模块里只开了 H3-Base（33B）；**Context-IR（提示词理解）与 768p→2K 超分不开源、
  只有 API**——纯自部署的出片效果与官方 API 有代差（官方 GitHub README 原文）。
- **自部署硬件**：官方推荐 **4×H100/H200**（SGLang cookbook；4×H200 实测 5s 片 75s/条）。
  阿里云行情：H100 档 ≈¥15,000/卡/月 ⇒ 推荐档 **≈¥6 万+/月**；按量每天开 2 小时也要
  ¥1.9–2.9 万/月。gn7i（A10 24G，¥3,200/月）**装不下**最小 42.5GB 权重集，
  ComfyUI 单卡 offload 是分钟级出片，玩具档不是服务档。
- **官方 API**：国内 **768p ¥0.5/秒、2K ¥0.8/秒**，失败/安审拦截不扣费，
  **原生 32kHz 立体声音画同出**，4–15 秒，个人实名即可充值调用。
- **「最高 768p」半对半错**：开源权重确实原生短边 768；**官方 API 有 2K 档**。
- **许可证仅自部署受限**：UI 必须醒目标注 "MiniMax H3"、年营收 >$2,000 万需书面授权、
  禁用欧盟/英国/韩国/美国（大陆不受限）。走 API 则不受这些条款约束。
- **成本对比**（每天 50 条 × 5s × 768p ≈ 7,500 秒/月）：
  API ≈**¥3,750/月** vs 自部署按量 ≈¥19,000–29,000/月 vs 包月推荐档 ≈¥60,000+/月。
  **差 5–15 倍**，且日利用率只有 ~6%。量要再涨 1–2 个数量级自部署才开始有讨论价值。
- **旁证**：liblib.tv（LibTV）就是 Seedance 全系 + MiniMax H3 并列挂 API 卖
  （首页横幅：2.5 促销 ¥0.4/秒、H3 定位「高性价比」）——同行也没自部署。
- 阿里云百炼**没有** MiniMax 视频模型（只有其 LLM）。想要"托管备选"：
  万相 wan2.2-t2v-plus 720p API ¥0.4/秒；真想自部署 768p/720p 级，开源可行解是
  万相 TI2V-5B（单卡 24G 能跑）而不是 H3。

### 四档方案的落地路径

- `doubao-seedance-1-5-pro-251215` **真实存在**（2026-08-20 本账号模型表实测；
  2026-08-01 注记它有 200 万 token 免费额度）。模型表里还有
  `doubao-seedance-2-0-260128` / `2-0-fast` / `2-0-mini`。
- 现状档位：极速=1.0-pro-fast、标准=1.0-pro、高清=**2.0-mini**、电影级=2.5。
- 提案映射：**极速+标准 → 1.5-pro**（合一档还是保两档，取决于 1.5 对
  首尾帧/audio 的实测行为）；**高清 → MiniMax H3 768p**（原生带声，替代 2.0-mini）；
  **新档「超清」→ seedance-2-0-260128**；**电影级 → 2.5 不动**。
- 工程量（按本仓规矩走，预估 2–3 天）：
  1. server 新 `minimaxGateway.service`（与 arkGateway 平行；**H3 按秒计费不按 token**，
     economy 是 token 本位 → 像 `r2vTokens` 那样定一个「秒→锚定 token」换算，两仓钉死
     + `payOrder.spec` 加钉子）；
  2. `ALLOWED_MODELS` / 价目表两仓同改（契约铁律：App 新增视频档位 = 两仓一起动）；
  3. 1.5 / 2.0 的 mult **先拿账单核了再进表**（没核过的价不进表；1.5 有免费额度可实测）；
  4. H3 产物 URL 域名不是方舟域——`/api/ark/transfer-video` 与 `/asset` 的白名单要加
     MiniMax 产物域（2026-08-20 刚修的「出片即转存」链路直接复用）；
  5. 风险：H3 时长窗口 4–15s（现段时长 3–10s，minSec 要按档钳）；内容安审口径与方舟
     不同，「敏感词 400 整单拒」那类坑要在 H3 上重踩一遍才能写进文案。

## 二、updream / LibTV 调研 与 画布化设计

### 两家的形态（登录墙外实测所见，2026-08-20）

**updream.cn**：对话 agent 是唯一入口（输入框示例「试试说"在画布上为我创建…"，
生成不阻塞，随时开启下一轮对话」）；官方技能市场（剧本策划 / 剧本转视频提示词 /
剧本直出美术资产 / 分镜光影 / 人物多视角 / **sd2.5 提示词优化**——他们也在 Seedance 2.5 上）；
积分制（长期/短期/冻结）。

**liblib.tv（LibTV）**：主入口=**「新建画布创作」**；模型平铺可选
（Seedance 2.5「音视频直出 30s」/ MiniMax H3「高性价比」）；**导演台**（虚拟 3D 场景、
空间精准控制——与我们 3D 铸卡桌同族）；**逐帧拉片**（传参考视频逐帧参考，标注"独家"——
与我们白模链路同源但浅一层：他们只做参考，我们 r2v 直接换主体+挂卡点名）；
LibTV Agent + Skills 市场（按 MV/影视/广告分类）；社区作品带**「查看创作过程」**
（过程可回放）；Blender 插件；积分+会员。

**共同收敛点**：agent 对话 + 无限画布 + 技能市场 + 过程可分享。**都是 PC Web 优先**。

### 差集

| | 它们有我们无 | 我们有它们无 |
|---|---|---|
| 创作面 | 无限画布、agent 对话驱动 | 3D 铸卡桌（沉浸感）、移动端原生 |
| 资产 | 技能市场（提示词类） | **卡片/卡组**（人物一致性资产化、可装走可交易） |
| 视频 | 多模型平铺可选 | **白模模板**（r2v 复刻+按颜色/成组点名换主体）、**分支互动视频** |
| 社区 | 作品过程回放 | 模板市场、卡组广场（本质就是"技能"，缺提示词类目） |

### 设计：保卡片特色的画布化（三步走，每步可独立发布）

核心原则：**卡片升格为画布一等公民**。画布节点类型 = 卡片（现有五类）+ 帧 + 段 +
白模模板 + 文本要求；**连线即语义**：卡→段 = 挂卡，段→段 = 承接（真实尾帧），
模板→段 = 白模复刻。

- **数据一行不动**：一段一份（`Proposal.videoUrl`）、炼段一份（`segmentGen`）、
  方案台共用、承接门禁只在 `flowStore.clampCursor`/`addNode`——画布只是 FlowNode 链的
  **另一个渲染器**，链式门禁映射为「下一节点锁定直到本段炼成」。
- **互通与随时切换**：同一份 draft 三视图（工坊 3D 桌 / 工作流线性条 / 画布），
  切换 = 换渲染器不换数据；store 单向依赖不破（切换动作住 studioStore，它认识 flowStore，
  反向仍然绝不 import）。
- **三步**：
  1. 工作流页加**只读画布视图**（把现有链画在 pan/zoom 画布上，方案台/进度原样复用）；
  2. 画布内**拖卡挂卡**与节点操作（复用 RoleCastBoard 的拖拽与 NodeSlot 语义）；
  3. **agent 输入条**：把简约模式「一句话出片」泛化成「对画布说话」（新建节点/改要求/
     发起重炼），生成不阻塞对话（updream 的核心体验）。
- **最大风险=移动端**：两家都是 PC 产品；6 寸竖屏上无限画布的手势（捏合缩放 vs
  首页上下滑）冲突要专门设计。建议画布视图**进入即 `requestLandscape(true)`**
  （hooks/useOrientationLock 已有这条路，退出必须传 false）。
- **不抄的**：积分制（已有 token 钱包）、Blender 插件（桌面生态）、2K 档（H3 API 有但
  我们的消费端是手机竖屏流，768p/720p 够）。

### 与第 1 项的交点

LibTV 用「模型平铺可选」替代我们的「档位抽象」。我们保留档位（报价=实收的钱包体系
依赖它），但档位描述里**写明模型名**（现在已经这么做），四档上齐后与 LibTV 的选择面
实质等价，还多出卡片/白模两个他们没有的杠杆。
