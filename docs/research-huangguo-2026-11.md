# 「黄果短剧开源」核查：有没有、能不能照搬（2026-11-16）

> **结论先行：没有可照搬的代码。**
> 网上那条「黄果 App 源码被离职码农开源」是 2026-11-11 起在 X 上发酵的传闻，黄果官方与
> HGhub 真正的维护者**都否认**了它。GitHub 上真实存在的是**第三方播放器、抓站解析器和反编译包**，
> 许可与来源都不允许我们使用。唯一值得对照的是短剧的**留存结构**（剧集 / 续播 / 自动下一集 /
> 追更），而那是产品决策，不是抄一段代码。

本文只做调研与判断，**没有下载、运行或引入任何第三方代码**。

---

## 1. 黄果是什么

| 项 | 事实 |
| --- | --- |
| 定位 | **AI 成人（R18）短剧平台**，域名 `huangguoai.com`，2026-07-15 在荷兰注册，新加坡有备用域名 |
| 上线 | 2026-09 官方 App 上线 |
| 内容形态 | 每集 3~6 分钟、共 7~12 集的短剧系列；另有 AI 换脸 / AI 魔改等衍生内容 |
| 商业模型 | 给创作者「破限模型」（不受常规过滤的生成模型）+ 收购符合标准的作品 + 订阅收费 |
| 名字 | 与字节「红果短剧」一字之差，暗示成人向定位 |

来源见文末 [1][2]。

★ 这条最关键：**它不是一个「AI 生成工具」App，而是「AI 生成内容的发行平台」**。生成在创作者那边，
App 里只有浏览、播放、互动、订阅。它的能力结构和我们（生成工作台 + 成片分发）只在一头重叠。

## 4. 为什么不能照搬（四条，任何一条就够）

1. **许可**：HGhub 是 PolyForm Noncommercial 1.0.0，明文禁止商业用途（销售、广告、卡密、VIP、
   付费解锁都算）；guomu / hongguo-cast 是 GPL-3.0，**传染性**会要求我们整个 App 开源；
   反编译包与抓站脚本大多没有许可。我们是收费产品，用一行都构成侵权。
2. **来源**：反编译是衍生作品；解析器绕的是 CDN 鉴权、AES 封面加密与 m3u8 清单签名。
   这类实现本身的合法性就存疑（著作权法 + 反不正当竞争），搬进来等于把别人的法律风险
   变成我们的。
3. **内容与渠道合规**：那是 R18 + 盗版边缘生态。我们正在走 Google Play
   （见 [`play-store-checklist.md`](play-store-checklist.md)），UGC + 18+ 已经把审核敏感度拉满；
   再沾上「成人短剧 / 破解」的代码或素材，等于自己把上架路堵死。
4. **技术不匹配**：它的解析代理、封面解密、优选 IP、多数据源，全部是为**盗链播放**服务的；
   我们既没有这个需求，也没有这个权利。而它 App 里**没有生成能力**——我们已有的
   Seedream / Seedance 流水线，没有一样能从它那儿学到。

## 5. 值得对照的：只有短剧的留存结构

把「代码」换成「产品机制」看，真正可迁移的是下面这几件。左边是他们做到的，中间是我们仓库的现状
（都核过代码），右边是我的判断：

| 机制 | 黄果系客户端 | 我们现状 | 判断 |
| --- | --- | --- | --- |
| **剧集化 + 续播** | 「打开就能看，切集不中断」：收藏、观看历史、**续播进度**、追更 | **没有观看进度 / 续播**（全仓只有播放器进度条）；多 P 只剩读路径（[`videos.ts:707`](../src/data/videos.ts#L707)），选集条在 [`VideoPage.tsx:390`](../src/pages/VideoPage.tsx#L390) | 唯一真有价值的一条 |
| **自动下一集 + 预加载** | 播完自动下一集，邻近集预热 | feed 内已有「多段顺序连播」（[`FeedPage.tsx:297`](../src/pages/FeedPage.tsx#L297)），但没有「下一集」这个概念 | 小改可复用 |
| **榜单 / 发现** | 热播榜 / 推荐榜 / 潜力榜 | 没有榜单（grep 为空），只有搜索与发现页 | 中等价值 |
| **离线缓存** | 整剧 HLS 分片缓存、下载进度 | 无用户可见的离线下载（只有原生临时 cache） | 对 AI 成片优先级低 |
| **供给侧激励** | 破限模型 + 收购版权 + 订阅 | 模板作者奖励 / 同款奖励已有（P1 / P3b）；「付费解锁」因结算链不存在已下架 | 形态可对照，**破限模型这条绝不能学** |

★ 关键差别不在功能数量，而在**内容从哪来**：它是「拿别人的成片做分发」，我们是「让用户自己生成」。
所以它的留存机制能借，它的供给方式不能借。

## 6. 建议

1. **不做「照搬」**。这条线到此为止，不下载、不参考其实现。
2. 如果要做，先做一个**最小实验**：给成片（尤其多段 / 多 P 作品）记住播放位置，下次进入续播。
   纯客户端、不碰数据模型、不花钱，能直接验证「我们的用户会不会连着看」。
3. **系列化是产品决策，不是技术任务**。把「剧集」做成一级对象要动数据模型与发布链路，
   得先回答：我们的用户是来「做」的还是来「追」的？在没答案之前不做。
4. **对标对象换掉**：短剧看**红果**（正版、公开数据：2026-07 日活 1.68 亿）；AI 视频工具看
   LibTV / updream（本仓已有对照调研）。黄果是「传播现象」，不是「产品标杆」。

---

## 7. 明确不做

- 不引入 HGhub / guomu / 任何抓站脚本的代码或依赖（许可 + 来源）。
- 不做「解析第三方站点」「绕付费/鉴权」「VIP 去广告」这类能力。
- 不碰 R18 内容与相关素材；不在产品里出现任何指向该生态的入口。
- 不以「黄果同款」做宣传（商标与商誉风险，且对方本身在争议中）。
