# 模板体系统一与「工作流复刻」：调研与方案（2026-10-02，主人当天已拍板）

> 背景：主人 2026-10-02 点名两件事 ——
> ① 继续统一视频生成各组件之间的联系：模板也像卡片那样**注明适用哪些出片模型**，用了模板，模型选项就被**固定**；
> ② 模板要有**类型**：现有的「示例视频 + 分段 + 人物卡拖拽」与卡组之外，加上 LibTV 式的**工作流复刻** ——
>   在 App 生成的 AI 视频上点「查看制作过程」，预览它用的工作流，复制到草稿接着做；用户能把工作流发成模板
>   （跑通一次才能发），节点用过的素材、功能、**别的模板**一并存下 —— 模板里可以嵌模板。
> 主人要求先去 LibTV 等平台调研，再把这份粗想法优化、补全。本文就是那份调研 + 优化后的方案。
> §五是拍板结果（主人 2026-10-02 当天回了四条，其余六条按建议走）。P0 已开工。

## 结论先行

1. **这个方向行业已经验证过，而且做法高度一致**：LibTV、TapNow 都是「看片 → 查看创作过程 → 只读画布 → 复制 / 克隆项目」，
   复制带走的是节点、连线、提示词、参数（§一）。我们不是在发明形态，是在把它搬到一条**竖屏、线性**的流水线上。
2. **地基我们已经有了大半**。「回炉重做」从 2026-09-07 起就把每条发布作品的整份工坊画布（只含永久地址）存在服务端；
   白模模板的「试炼闸」（作者自己真出过一次片才能发布）就是主人说的"跑通一次才能发"；档位那一排（`TierRow`）
   本来就有"这一档为什么点不动"的原因链。缺的是三样：**一份能公开的配方**、**看与复制的两个面**、**模型适配的统一口径**（§二）。
3. **最该补的不是功能，是一条规矩**：复制带走的是**配方**，不是成品；公开出去的是**白名单投影**，不是那份画布原件。
   画布里有用户的原话、没选中的方案、真人卡、上传的参考视频 —— 原样公开等于替作者泄露（§三 C5）。
4. **「模板里嵌模板」用"包含 + 快照 + 回指"就够，不需要递归**：流程 ⊃ 段模板 ⊃ 卡，三层各管各的；
   被嵌进去的模板存一份当时的快照、留一个指回原模板的 id。真正要小心的是**素材的生命周期**（原模板被删，嵌它的流程全断）（§三 D）。
5. 分四期，**第 0 期不依赖任何新实体**，可以先发（§四）。

## 一、别人怎么做

### 1. LibTV（liblib.tv）—— 实测

| 位置 | 看到的 |
|---|---|
| 首页「TV Show」 | 社区作品流，分类里有一栏就叫**「精选画布」**；列表里每张作品卡都带一颗「查看创作过程」 |
| 作品详情页 `/detail/<id>` | 播放器下面一行：**「查看制作过程」**、点赞、分享；作品描述、更新时间、「含 AI 生成内容」标 |
| 点「查看制作过程」 | 当前页盖一层**只读的整张项目画布**（未登录也能看）。顶栏：项目名｜视图切换（工作流 / 故事板）｜「只读模式，如需创建请点击 **复制项目**」｜关闭 |
| 工作流视图 | 作者的全部节点、连线、生成结果原样可见。作者自己把画布打了组：人物资产 / 场景资产 / 道具资产 / npc 资产 / 分镜参考图 / 分镜资产 1~5 / 场 1~3 |
| 点开任意节点 | 检视面板**全开**：编号的参考图缩略图（1~7）、提示词里的 `图片5 曜、图片6 李白…参考 图片4 场景` 点名绑定、每个角色的音色规格、逐分镜时间轴（`分镜7：3s｜特写快速跟随…`）、收尾的强制声明；设置项（高级设置 / 联网搜索 / 自动校验素材 / 智能引用）也在 |
| 故事板视图 | 两栏：**图片**、**视频**，逐节点竖着列：产物、时长（16 秒 / 30 秒）、分辨率、**用到的参考图缩略图**；视频栏可筛 全部 / 成片 / 片段 |
| 「复制项目」 | 未登录 → 登录框。登录后的行为没走到；公开资料的说法是"一键复制到自己的画布进行二次创作和学习" |

公开资料补的三条（来源见文末）：

- 画布右上角「**分享 / 发布**」是两件事：分享 = 把画布给别人看（对方看得到画布及后续所有操作）；发布 = 进社区首页，**通过审核后**才曝光。
- **打组（Ctrl+G）→「创建工作流」保存 → 左侧栏「我的工具箱」调用** —— 这是它的"段级模板"：一组节点连同设置存成可复用块，换输入再跑。
- 跨画布复制粘贴**带连线**。

⇒ LibTV 其实有**两种粒度的模板**：整张画布（作品 = 模板，靠「复制项目」）与一组节点（工具箱）。这正是主人说的"模板里嵌模板"的形状。

### 2. TapNow / TapTV —— 同一套，且「查看创作过程」是作者可选的

测评原文：「可以点击【立即观看】观看视频，旁边还有【查看创作过程】，**如果是可以点击的**，那就可以一键克隆了」「点进后就能看到工作流画布了…右上角有【克隆项目】」。
克隆得到的是完整工作流、节点设置、参数配置、提示词；作者的用法是**保留结构、替换人物设定与风格参考**再跑。平台对分享作品给积分奖励。

### 3.「模板的引擎说了算」—— PixVerse / 可灵特效

这是主人第 ① 条（模板注明适用模型、用了就固定）在行业里的原型：

- **PixVerse** 模板对象：`qualities` =「模板接受的清晰度**闭集**」；`template_model` = 底层引擎；文档原话
  "When you invoke a template, you do not need to (and should not) pass a `model` parameter — **the template's engine is authoritative**"；
  `effect_type` 把"要几张输入图"编进模板（恰好 1 张 / 恰好 2 张 / 多张）。
- **可灵 Effects**：特效按 `effect_scene` 选，绑定在具体 `model_name`（kling-v1-6）上，双人特效要求恰好 2 张图且检测到人脸。

共同点：**模板 = 在某个引擎上调好的东西**，换引擎不保证成立，所以不给换；输入槽位的个数与校验规则写在模板里。

### 4. ComfyUI 生态 —— 配方不含模型，所以导入要查依赖

工作流 JSON / PNG 元数据只记节点类型、参数、连线，**不含模型文件**；加载模板时自动检查所需模型在不在，缺了就提示下载。
对我们的含义：复制一条流程之前，先把"这条流程要用到的档位你有没有资格用"查一遍（电影级仅付费套餐），**在复制之前说**，不是炼到第 3 段才说。

### 5. 剪映模板 —— 槽位 + 审核 + 创作者体系

模板 =「创作者对一个或多个元素的**占位预设**」，用的人只替换占位素材；提交后**审核 3~5 个工作日**；创作者有等级与收益。
（2021 年杭州互联网法院判过：短视频模板构成类电作品 —— 我们的初始模板必须自产，旧底稿 §三已写。）

### 6. 扣子 Coze —— 模板商店

免费模板点「复制」进自己的工作空间再改；收费模板先试运行、再购买。工作流可以导出 / 导入。

### 归纳：六条可以抄的"形"

| # | 形 | 出处 |
|---|---|---|
| 1 | 作品页一颗「查看制作过程」→ 只读 → 一颗「复制」 | LibTV、TapNow |
| 2 | 只读页给**两个视图**：结构图 + 按产物竖排的清单（后者才是手机上看得懂的那个） | LibTV 故事板 |
| 3 | 是否公开制作过程由**作者选**；进社区曝光要过审 | TapNow、LibTV |
| 4 | **模板的引擎说了算**：适用的清晰度 / 模型是模板自带的闭集，使用时不让换 | PixVerse、可灵 |
| 5 | 模板写明**要几个输入、各是什么**，缺了就点不动并说原因 | PixVerse `effect_type`、可灵、剪映占位 |

## 三、方案

### A. 一张统一的图：模板分三层，一层管一件事

主人说的三种类型，其实正好是三个**粒度**，各自往「一段出片的生成契约」（`real.GenSpec`）里填不同的格子：

| 层 | 类型（用户看到的名字） | 管什么 | 填契约的哪几格 | 今天 |
|---|---|---|---|---|
| 素材层 | **卡组** | 谁、在哪、什么画风 | 参考图 + 出片句 | 已有 |
| 段层 | **示例视频模板**（白模：示例视频 + 分段 + 角色位拖卡） | 这一段的动作、站位、镜头 | 参考视频 + 点名骨架 + 时长 | 已有 |
| 流程层 | **工作流模板**（新） | 整条片子怎么一段段做出来 | 每一段的模式 / 档位 / 剧本 / 镜头字段，以及它用了哪张段模板、哪几张卡 | 新 |

- **上层可以装下层，下层不认识上层**：工作流模板里的某一段可以是一张示例视频模板，段里再挂卡 —— 这就是"模板里嵌模板"。
- 经典配方模板（`recipe.beats`，一句话换主题那种）是工作流模板的**前身**（它只有文字节拍、没有每段的设置）。
  建议并进工作流模板，不再当第四种（§五-6）。
- 「技能」（结构化技能、出片技能）不是模板：技能是**动作**（一段流程怎么跑），模板是**材料**（跑出来的东西怎么复用）。两者以后可以互转（P3），本期不混。

### B. 模板 ↔ 出片模型：一条口径，四种东西

**口径：每一种可复用的东西都要能回答「我在哪些档位上成立」，而且答案来自事实，不来自作者自称。**

| 东西 | 「适用档位」从哪来 | 用的时候 |
|---|---|---|
| 卡片 | 已有：各档能用到这张卡的什么（形象图 / 文字版 / 起拍画面） | 不锁档；档位那排下面点名"哪张卡在这一档收不到形象图" —— 已有 |
| 卡组 | **由卡推**：一行摘要，如「高清 / 电影级：5 张卡形象图直进｜标准 / 极速：3 张有文字版、2 张只剩出片句｜真人档：有起拍画面」 | 不锁档，只告知 |
| 示例视频模板 | **硬条件**（协议）：要能跑参考视频的档（今天只有电影级）＋ **验证过的档**：试炼闸成功那一发用的模型，服务端记 `provenModels` | **固定**：不在清单里的档灰掉，原因印在旁边 |
| 工作流模板 | 每一段各自的档位 = **原作那一段真正用的档**（事实）；整条的清单 = 各段去重 | **逐段固定**（见下） |

细则：

1. **"注明"由事实生成**。作者想让模板多支持一档，就自己在那一档再跑通一次 —— 与试炼闸同一条理由：坏模板的学费由作者付，不摊给每个套用的人。
2. **固定的写法沿用 `TierRow` 的原因链**。不摆灰按钮不说话（本仓老规矩）。
   白模段上这一环本来就在（`economy.r2vPriceIssue`），P0 只改了它的说法 —— 从「暂未开放…等开放后再来」改成「做不了按参考视频出片，只有『电影级』做得到」；
   工作流模板"逐段固定"那一环（「这一段是照原作的档位复刻的」）等 P2 模板实体落地时再加。
3. **不给「解除固定」的出口**（主人 2026-10-02 拍板，推翻了本文原来的建议）。原建议的理由是"永不解锁，免费用户就用不了电影级模板"，
   主人指出这个理由不成立：模板对模型是**硬要求** —— 示例视频模板要按参考视频逐镜头复刻，只有 Seedance 2.5 支持；真人档模板只能走真人档。
   解除之后换到别的模型不是"效果差一点"，是**出片直接失败**（那个模型根本没有这项生成能力）。给一个按下去必然失败的出口，比不给更坏。
   ⇒ 用户该做的不是在模板上换模型，而是**按自己能用的模型去挑模板**：模板市场搜索栏旁边加一颗「出片模型」筛选（P0）。
4. **锁的是档位（产品概念），同时记下当时的模型 id**。档位底下的模型换代后，模板页如实写一句「这一档的模型已升级，模板是在旧模型上验证的」，不拦。
5. **使用前先查资格**：模板详情页与复制确认卡上直接写「其中 2 段要用电影级（仅付费套餐）」与「照原样炼完约 N token（按今天的价目）」。
   估价从算真扣的那套函数取（`segmentCost` / `r2vTokens`），不另算一遍。

### C. 制作过程：看、复制、存为模板

#### C1. 数据：一份「公开配方」，不是把画布原件放出去

回炉用的画布（`CanvasSnapshot`）是"客户端定义形状、服务端只当 Mixed 存"的东西，里面有用户的原话、三套方案里没选中的两套、圈选标注、
真人卡、上传的参考视频。**不能原样公开**。做法是在分享那一拍由客户端出一份**白名单投影**，服务端用严格 schema 再验一遍：

```
WorkflowRecipe v1（公开配方）
  source      出自哪条作品、哪一版（revision）
  summary     段数 / 总时长 / 画幅 / 用到的档位清单 / 照原样炼完的估价
  deck        随配方带走的卡（只收"可以分享"的那些）
  cast        全片的「角色位」：A = 主角（原作：凛雪）…  ← 要使用者自己填的位子
  nodes[]     每一段：
                剧本、镜头字段（景别 / 运镜 / 情绪节拍）、时长、档位、画幅、是否承接上一段
                生成模式（经典 / 参考直出 / 白模复刻 / 自定义 / 返修）
                用了哪几张卡（指向 deck 第几张，或指向 cast 的某个位子）
                用了哪张段模板（快照 + 指回原模板的 id）、角色位各对应 cast 的谁
                导演台站位（可带）
                预览：成片那一段、起止画面（只给人看，不进出片）
  lineage     这份配方本身是从谁那儿复制来的（同款链）
```

- 存量作品：有回炉画布的可以由作者补出一份配方；没有的（2026-09-07 之前，或简约模式）只能给**简版**（按段的剧本 + 档位 + 卡组，就是今天做同款用的那些），界面如实写"简版"。
- 上限沿用工程那套（≤2MB，只含永久地址）。

#### C2. 看：作品页一颗「查看制作过程」

- 入口只放**作品详情页**，紧挨「⚡ 做同款」。首页右侧栏不加键 —— 那一栏 640 屏只剩 24px（CLAUDE.md 钉过）。
- 形态用 LibTV 的**故事板**那一面，不用节点图：我们的流水线本来就是线性的，手机上竖着一段段看才看得懂。
  顶部一张摘要卡（N 段 · 总时长 · 适用档位 · 估价 · 用到的卡），下面逐段：成片缩略 → 剧本与镜头字段 → 档位 · 时长 · 画幅 →
  用到的卡（小图）→ 用到的模板（可点进模板页）→ 起止画面。
- 付费作品未解锁时不给看（与做同款同一条闸）。

#### C3. 复制到草稿：带走配方，不带走成品

| 带走 | 不带走 |
|---|---|
| 每一段的剧本、镜头字段、时长、画幅、档位（固定，见 B） | **成片与起止画面**：那是原作者花钱炼的产物；同款不同人，本来就要按你的卡重画（沿用做同款现在的口径） |
| 每一段各自挂的卡（不再是"全部卡挂到每一段"） | 没选中的方案、用户原话以外的草稿痕迹、圈选标注 |
| 段模板快照（示例视频模板连同角色位） | 真人卡、从别人那儿装来的卡、挂第三方版权模型的卡 —— 变成空位（C5） |
| 导演台站位 | 上传的参考视频（权利不明，默认变成"自己传一段"的空位） |

- **一次选角，全片生效**：复制时先过一屏「选角」——把 cast 里每个角色位换成自己的卡（或保留原作随配方带来的卡）。
  填一次，所有引用这个位子的段（含白模段的角色位）一起生效。这比今天"每段各挂各的"省事，也是白模拖卡的自然延伸。
- 复制是**第十条「整表换 nodes」的入口**：先问 `flowDirty`、成了再 `newWorkDraft()`、在途生成时不许换，三件套照旧（CLAUDE.md）。
- 复制出来每一段都是"未出片"，钱在各段生成时照常一段一结；顺序门禁照旧。
- **做同款升级成同一颗键的两档**：作品公开了配方 → 按配方复制（保真）；没公开 → 退回今天的简版，键上写清是哪一档。

#### C4. 存为工作流模板

主人说的两条入口都保留，而且它们天然满足"跑通一次"：

1. **从成片存**：组稿之后 / 已发布作品的编辑页 →「存为工作流模板」。作品本身就是试炼的证据。
2. **先搭后发**：在工作流里把每一段设好、**整条跑通一次**（每段都出过片）→ 才亮起「发布为模板」。判据在服务端（各段的出片任务确实成功，沿用试炼闸那条"不信客户端一句我跑通了"）。

模板页 = 示例视频（就是那条成片）+ 摘要卡 + 配方故事板 + 一颗「用这个流程做一条」。模板市场的货架加一层类型筛选：全部 / 示例视频 / 工作流。

#### C5. 脱敏与权利（这一节是红线）

| 画布里的东西 | 公开配方里怎么处理 | 依据 |
|---|---|---|
| 真人卡（含已认证的） | **一律变空位**，连名字都不带 | 真人卡本来就不许上广场（`shareBlockReason`）；肖像授权绑定只有卡主读得到 |
| 声音样本 | 不带 | 本来就只存本机 |
| 从别人那儿装来的卡 | 变空位，旁注"原作用的是某某的卡" | 转发件不许再分享（`sourceOwner`） |
| 挂第三方版权模型的卡 | 3D 模型不带，卡面与出片句照常 | 服务端本来就 400 |
| 上传的参考视频 / 参考图 | 默认不带，变成"自己传"的空位；作者可逐个勾选"我有权分享" | 权利不明 |
| 没选中的方案、原话草稿、圈选标注 | 不带 | 不是配方的一部分 |
| 付费作品 | 未解锁的人看不到配方 | 与做同款同一条闸 |

公开之前给作者一屏**预览**："别人会看到这些"，逐段列出、空位标出来。看不到这一屏就点了公开，是替用户做决定。

#### C6. 归属与同款链

- 复制出来的草稿带 `remixOf`（原作品 / 原模板 + 作者）；发布后作品页显示「按 @某某 的流程制作」，原作品页显示「N 人用这个流程做了同款」。
- 同款的同款继续往上指，形成一条链；链上任何一环被下架，下游作品不受影响，但那一环的配方不再可看可复制。

### D. 模板套模板：包含 + 快照 + 回指

- **只有包含，没有递归**：流程 ⊃ 段模板 ⊃ 卡。流程里不再套流程 —— 想在别人流程上接着做，走"复制 → 改 → 再发布"，那是同款链，不是嵌套。
  这样不会有环，也不存在"模板 A 引 B、B 又引 A"。
- **嵌进去的是快照，另留一个回指**（原模板 id + 当时的版本）。快照保证"原模板后来被改了，这条流程照样跑得通"；回指用来做三件事：
  点进原模板页、给原模板作者署名、**下架传导**。
- **下架传导**：原模板被平台下架（`status: blocked`）→ 嵌它的流程在"用这个流程"时，那一段标红「这一段用的模板已下架」，要求换一张或删掉这一段，其余段照常。
- ★★ **素材生命周期是这里唯一真会出事的地方**：快照抄的是字段，示例视频本身还是原模板那个地址。原作者删模板会级联回收托管视频 ——
  于是每一条嵌了它的流程都指向一个死地址，而出片是"受理即扣费"。两道一起做：
  ① 被公开流程引用着的模板**只能下架、不能删素材**（服务端记引用数，降到 0 才真回收）；
  ② 出片前对段模板的示例视频做一次存活检查（认 Content-Type，不认状态码），不通就整句拒、不花钱。

### E. 治理

- 公开配方跟着作品走：作品被举报下架，配方与由它生成的模板一起下架。
- 工作流模板进市场走**事后治理**（与白模模板一致：发布即可见，管理员可下架），不做 3~5 天的事前审核 —— 我们没有那个人力，而且示例视频就是一条已经在站内的作品。
- 提示词是用户写的内容：配方里的剧本同样过现有的敏感词与举报通道。

### F. 明确不做

- **不做节点图画布**。LibTV / updream 自己都承认 20 个节点以上就乱；我们的流水线是线性的，手机上更没地方摆。
- **不免费送成品**。复制不带成片与帧。
- **不做流程套流程的引用式嵌套**（理由见 D）。
- 本期**不做模板收益 / 付费模板**（token 不可提现那条红线之内可以做站内奖励，但规则要另议，§五-9）。

### A. 「按我的主题改写每段剧本」

**要解决的事**：按别人的流程做同款，铺过来的每一段剧情还是原作的故事（信使、雨夜、递伞）。用户要么逐段手改，要么每段「重新推演」（每段一次推演费 + 三套帧）。经典配方模板当年解决的正是这个（`{{主题}}` + `setSubject`），而工作流模板没有它。

**形状**（照 `SCRIPT_TO_SHOTS` 那份实例来，四件齐：步骤 / 形状检查 / 确认点 / 价签）：

- 输入：主题一句话（`SCRIPT_MIN`~200 字）+ 当前流水线里**还没出片**的普通 / 自定义段（白模段跳过：它的 plot 是点名句，画面来自模板）—— 每段的标题、剧情、镜头字段、时长、挂的卡名。
- 模型一发（`skillChat` → `chatBounded`）：系统提示词冻结中文，要求**段数不变、顺序不变、每段 60~120 字、镜头字段与时长照抄、人物换成卡名、只输出 JSON**。输出 `{"segments":[{"title","plot"}]}`。
- 形状检查：段数必须等于送进去的段数（少一段整句失败，不落地 —— 与「剧本 → 分镜」同口径，钱在请求成功那一拍扣过一次）；每段 plot 非空且 ≤ `VIDEO_PROMPT_MAX`（400）；重复键那一档按 `cutProject.linePairs` 的办法从原文捞（方舟 chat 写数组偶尔漏 `},{`，ark-api-facts 记过）。
- 确认：一屏「原 / 新」逐段对照，可逐段勾掉不改的；点头才落地。
- 落地：`updateProposal(nodeId, { plot, title }, chosenId)` 逐段写（认 node.id 不认下标）；已出片的段原样不动并说明；`requirement` 不动（那是用户的原话，改写出来的不是）。
- 价签：一次 chat 定额 `CHAT_TURN_TOKENS`（400）。**输出上限要量**：按 8 段 × 120 字估 ≈ 1,100 token，与「剧本 → 分镜」同量级 → 先用 `SCRIPT_SHOTS_MAX_TOKENS`（2400）；段数 > 12 的流水线分两发（每发各计一次 chat），面板上先说清。

**两条入口**：
1. 制作过程页「按这个流程做同款」的选角一屏多一栏「我的主题（可选）」：填了 → 铺完当场弹改写的确认卡（铺是免费的，改写花钱，所以不能"顺手"跑）。
2. 画布「/」面板里新增官方技能「按主题改写全片剧本」—— 对任何流水线都有用（做同款抄来的、自己写了一半想换故事的）。

**不做的**：不改白模段；不改已出片的段；不新开生成路径（改的只是 plot，出片 / 报价 / 承接一行不动）。

**体量**：中（`structuredSkills` 加一条 + 一张面板 + 选角一屏加一栏；无服务端改动）。

### B. 把一条流程接进现有流水线

**今天**：制作过程页的「按这个流程做同款」是**整表覆盖**（第九条入口，守卫先问脏 / 成了再断草稿）。手上有一条做了一半的流水线时，用户只能二选一。

**做法**：`flowStore.appendNodes(nodes)` —— 把 `recipeNodesOf` 铺出来的 N 段**接在末尾**：
- 闸与 `addNode` 同一组（`appendBlocked`：最后一段是白模段就拒；`busy` / 有段在生成中就拒）；**不要求**上一段已出片（追加的是整条有剧情的段，不是空段 —— 空段的那条门槛是为"承接要先有尾帧"设的，而这里第一段接上来时 `chain` 置 false、整条按原配方的 chain 走）；
- 每段 `tpl` 显式表态（对象或 null），与 `recipeNodesOf` 今天一样，不留 undefined（`pinUnstatedTpl` 的 ★★）；
- 不是整表覆盖，**不走** `useApplyTemplate`（没有东西会丢），但 `remixOf` 这一格怎么办要定：接上去的那条片同时有自己的段和别人的流程 —— 建议**不写** `remixOf`（署名只给"整条照着做"的那种），接段只在被接的那几段卡上留一行「来自 @谁 的流程」（`FlowNode` 加一位可选 `fromRecipe?: { videoId, author }`，只管渲染）。
- 制作过程页 CTA 变成两档：流水线为空 → 只有「铺成我的工作流」；非空 → 「替换我现在的流水线」/「接在后面」。

**不做插到中间**：中间插入要改 `cursor` / `alts` 的节点引用、承接（新段前面的段尾帧）、`clampCursor` 的 frontier 判定、底部节点条的下标 —— 这三道闸都是按"只能在末尾追加"写的（`addNode` 的注释），插中间等于把顺序门禁重做一遍，换来的只是"把别人的三段塞进我第 2 段后面"这种少见的事。真要的话走"接在后面 + 拖动换序"（换序也没有，另议）。

**体量**：小（一个 action + CTA 分档；无服务端改动）。

### C. 站内奖励

**外面怎么做**（10-02 查）：剪映把模板创作者的收益分成六类（免费模板按使用量拿平台补贴、付费模板 3~6 元 / 个、活动奖金……），按月结算到抖音钱包，创作者分 9 级；可灵「创作者计划 3.0」是每月百万级现金池 + 千万级「灵感值」（站内积分）：站内作品给灵感值分成，去抖音 / 小红书发带话题的视频才给现金。两家共同点：**站内用的是平台发的积分，现金只给有结算资质的那条路**。

**我们能做的形态**（`token-wallet-payment-redlines` 那条红线之内）：
- **平台印 token 给原作者**：同款作品发布成功（`createVideo` 认下了 `remixOf`）→ 服务端 `wallet.credit(原作者, N, "remix_reward", memo)` + 一条通知「@谁 按你的流程做了同款，奖励 N token」。`TokenLedger` 的 reason 枚举加 `remix_reward`（**不进** `REPAY_REASONS`：它是印钱，不抵欠额）。这是平台的成本，不是同款作者的钱 —— 不是用户间流转。
- **不能做的**：同款作者付 token 给原作者（流转）；按作品销量分成（没有销售）；给现金（没有通道）。
- 网站那套「点数」（`points.service`，悬赏托管用的虚拟点数）App 不显示，不借它。

**防刷**（这才是设计的大头，奖励本身一行）：
- 自己给自己做同款不算（P1 的 `remixCount` 已排除作者本人）；
- **发布 24 小时后仍公开可见才发**（清扫器跑，不在发布那一拍发）—— 发了就删的刷法一分钱拿不到；
- 每位原作者每天最多 N 次、每条原作最多 M 次（账本里按 reason + memo 现数，不另存计数）；
- 同款作品被下架 / 删掉不追回（追回要动负向分录，复杂度不值）；
- 只奖励**公开**的同款（私密 / 凭链接可见的不算）。

**要主人定的三个数**（给个参照：标准档 5 秒一段 108k token，极速档 30k，免费套餐每月 300k）：每次奖励多少（建议 30k ≈ 一段极速档）、每人每天几次（建议 10）、每条原作一共几次（建议 50）。

**体量**：中（服务端清扫器 + 账本 reason + 通知一条 + App 通知文案 / 个人页「流水」可以不做）。

### D. 付费模板 —— 不做

与 2026-08-31 下架「付费解锁」是同一个判断：① token 不许在用户间流转（二清）；② 现金分成要企业商户号的「商家转账到零钱」，个体户不支持，公司还在注册（`qimeng-company-registration`）；③ 没有结算、对账、个税代扣任何一环。等收款与分账真通了，付费模板和付费解锁一起开。

### E. 黑盒模板 —— 不做

主人 §五-10 已否。记一下真要做的话动哪儿：提示词只存服务端（配方 `nodes[].plot` 不下发，换成 `plotHidden: true`）、出片时由服务端在 `/api/ark` 代填（客户端只送 `recipeId + nodeIndex`）、报价照常。整条出片路要为它开第二条分叉 —— 这正是本仓最忌讳的形状，不做是对的。

### F. 经典配方模板 —— 不迁，收车道

事实：经典模板（无 `refVideo`）**只存本机**，`saveTemplate` 不登记、`apiToTemplate` 丢弃、市场只列作者自己本机已发布的 —— 别人从来看不见。所以没有"存量"要迁。
建议：A 上线之后，提取器（`VideoTemplateExtractor`）里「经典配方」那条路线（抽帧总结画风 + 提炼卡，付费）隐藏；本机已有的经典模板照常能套用（简约模式那条路不动）；市场页的「经典 / 不限档位」文案随之收掉。

**拍板的四条之外，落地时定下的口径**（都写在代码与契约里；要改说一声）：
1. **上限不顺延**：到了「每天 10 次 / 每条 50 次」的那几条记成不发，不排队等明天（顺延的话"每天最多"只是限速，欠下的那一摞可以无限长）。
2. **「每天」= 任意连续 24 小时**（不按自然日：不用选时区，也没有零点前后各刷一轮的缝）。
3. **同一个人对同一条原作只算一次**（不然一个号对着一条原作发 50 条就把它的上限吃满）。
4. **同款必须真公开**（凭链接可见的不算）；**原作凭链接可见的算**（拍板 5：工作流模板可以挂在那种作品上）。
5. **判一次就定案**：到期那一刻不满足的之后再变公开也不补；发了的之后被删 / 下架也不追回。
6. 两边账号任何一个注销 / 被封，不发（封号不自动藏内容，所以要在这里挡）。
7. **上线之前发布的同款不补发**；开关（`REMIX_REWARD_ENABLED=false`）关着时到期的记成不发、不攒着。

**刷量的口子与两道防刷**：注册不要验证码（每 IP 每小时 30 个），所以"小号互相做同款"是刷得动的 —— 光靠上面的规则，上限是每个收奖励的号
每天 300k token（≈ 4.5 元算力）、每条原作 1.5M（≈ 22.5 元），兜底只有封号（被封的同款作者到期不算）与总开关。
主人 10-03 说「开始做」，加了两道（服务端 ideahub-server#104；**两个数是我提的**，都在 server `config/remixReward.js`）：
- **防刷一**：每个**同款作者**任意连续 24 小时内最多给别人带来 **3** 次奖励（`remixer_cap`）。一圈互刷的小号，"每号每天收到的"平均不可能超过
  "每号每天带来的"，所以互刷的日产量从 10 次 / 号压到 3 次 / 号（90k token ≈ 1.35 元），还得每天公开挂出三条垃圾作品满 24 小时。
  对正常人的影响：一天公开发 4 条以上别人的同款时，第 4 条起原作者拿不到奖励。
- **防刷二**：**全站**任意连续 24 小时内最多发 **100** 次（保险丝，≈ 45 元 / 天；环境变量 `REMIX_REWARD_GLOBAL_PER_DAY` 可调、不用发版）。
  到了就不发（`budget`，排在最后判）、也不补；这个窗口里第一次断的时候给管理员发一封信，信里列最近 24 小时收得最多 / 带来最多的各五个号，
  方便分清"被刷了"（封号）还是"真火了"（调大额度）。
- 两道都**不进规则端点、不上屏**（App 那句话说的仍是四个产品口径的数），所以 App 不用动。

**七条口径的状态**：1~7 都随 #103 在线上了（不是待办）。

验法：服务端 `tests/remixReward.spec.js` 15 条（钱的去向 / 恰好一次与两种崩法 / 九种不发 / 两道上限 / 拉黑 / 删号级联）+ 相邻 8 套全绿；
浏览器（内存服务端 + e2e dev）：接口备料（原作者、两位同款作者、一条原作、两条同款，其中一位被原作者拉黑）→ 拨时钟 25 小时跑一轮清扫 →

各带「🎁 平台奖励你 30k token」「照的是你的《…》」），点进去分别落到那条同款 / 自己的原作，已读正常 → 编辑页与发布页那句话（中英文）
