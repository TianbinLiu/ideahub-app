# 作品详情页重做（2026-10-26，主人第 5 件「视频详情页太潦草，调研 B 站等同类 App」）

## 一、为什么潦草（改之前）

`pages/VideoPage.tsx` 818 行，四个问题：
1. 标题出现两次（顶栏一次、正文一次）；
2. 播放器有边距、有圆角，竖屏作品被卡片框成一小块；
3. 「去创作」类入口五个，两个是实心键，没有一个是主键（docs/ux-review-csci187-2026-10-14.md 早就点名过）；
4. 评论是评论抽屉的缩水抄本：计数读 `comments.length`（最多到 50）、回复被拍平、不能回复不能点赞、详情回来之前先说「还没有评论」。
另外，首页有的收藏、弹幕、全屏 / 转屏、倍速，这一页一个都没有。

## 二、怎么改（YouTube 手机端 + B 站 + 即梦的共性，从上到下）

| 块 | 做法 | 实现 |
|---|---|---|
| 顶栏 | 返回 / 分享 / ⋯；正文标题滚出视口之后顶栏才写标题 | `PageHeader` + IntersectionObserver |
| 播放器 | 满宽、不圆角；倍速、弹幕、全屏 / 转屏 | `SegmentPlayer` / `BranchPlayer` 的 `frame` / `rate` / `overlay` / `onFull`，控制条只有 `PlayerControls` 一份，全屏只有 `hooks/useImmersive` 一份 |
| 弹幕条 | 「弹幕 N」（服务端回来之前不写数）、开关、「发条弹幕…」；互动作品进了分支说一句、不摆点不动的键；多 P 老作品只在第 1 集 | `danmakuFetched` / `isTruncated` / `DanmakuInput` |
| 横幅 | 下架 / 回炉成功 / 保存被拒，照旧 | — |
| 标题区 | 两行标题 + 统计行 + 徽标行（AI 生成标识永远在首屏）；简介与话题**展开后**才出现 | — |
| 作者条 | 头像 36 + 粉丝数（lazy 取，没回来不编）+ 关注；自己的作品是「编辑」 | `api/users.getUser`、`account.setFollow` |
| 动作条 | 赞 · 评 · 藏 · 分享 · 举报；自己的作品 / 离线时第五格换「保存」，都不行就四格 | 第五格按 `ReportButton.canReport` 一处判 |
| 选集 / 互动结构卡 | 从播放器上方挪下来 | — |
| 评论预览卡 | 「评论 N」+ 第一条顶层评论（三态），点开就是首页那个评论抽屉 | `CommentSheet` 一份；`videos.commentsStatus` |
| 做你自己的版本 | 参数行（几段 · 多长 · 画幅 · 有没有声 · 哪一档 / 模型名）、同款署名、卡组、查看制作过程；卡里没有实心键 | `components/video/RemakeCard` |
| 相关区 | TA 的更多作品 + 同分区（进视口才问） | `components/video/RelatedWorks` + `VideoTile` |
| 吸底栏 | 「说点什么…」（打开评论抽屉并聚焦）+ 全页唯一实心主键「做同款」 | `components/video/VideoDock`（portal 到 body） |

## 三、拍板（主人授权我定，2026-10-26）

- 竖屏作品首屏 = 满宽播放器 + 标题统计 + 作者条 + 动作条（首页已经是沉浸流，详情页做「信息与延伸」）；
- 评论用 YouTube 式预览卡 + 抽屉（不做 B 站的「简介 | 评论」双页签：要把抽屉拆成两半，工作量多一倍）；
- 举报在动作条第 5 格（Google Play UGC 要求一下就点得到），拉黑在顶栏 ⋯ 面板里紧挨举报那一行；
- 撤掉顶栏「我也要创作」；卡组那颗实心「用这套卡去创作」降成文字键「带着这套卡去工坊」；「做同款」改 `bg-brand`（金色留给付费解锁）；
- 参数行的模型名走 `account.tierShownModel`（地区问到了才写供应商名）；
- 不加收藏数：服务端 `BranchCollect` 2026-08-31 写明不做计数（零成本动作是最便宜的刷量燃料，显示骗人的数比不显示更糟）；
- 付费没解锁的那一 P 不给做同款（与「查看制作过程」同一个口径：配方是付费内容的一部分）—— 原来详情页的做同款不看 locked，首页看；收成 `hooks/useRemake` 一份时按首页的来。

## 四、量出来的数

- 2026-10-26 浏览器 375×812：播放器底沿到动作条底沿之间最多 **275px**（两行标题 + 统计 + 徽标 + 弹幕条 + 作者条 + 动作条，简介折叠时不占位）；横屏作品播放器 211px，动作条底沿 574~599px，吸底栏顶沿 759px。
- 真机要算安全区（浏览器里是 0）：顶栏 59 + 状态栏 41 = 100px；吸底栏 69px（8px 底边距被手势条 24px 顶替），顶沿 743px。
  ⇒ 竖屏播放器最多 743 − 100 − 275 = 368px ≈ 45vh，`PORTRAIT_MAX_VH` 取 **44**（设计稿按安全区为 0 估的 50，真机上动作条会压到吸底栏底下）。
  640 高的屏怎么取都放不下（靠滚动）。这一条只在浏览器里量过、按真机安全区推算，还没在模拟器 / 真机上截图核对。

## 五、审核修正（开工前两份对抗审核，成立的都照做了）

1. 评论「到了没有」只做一处三态 `commentsStatus`，与 `detailed` 同生同灭（另开平行集合会让刚发布的作品永远转圈、整份重拉后不同步、失败一直转圈）；失败给重试；
2. 评论翻页：终点只认 `nextCursor === null`（`commentCount` 是全量计数，列表滤掉了被拉黑的人）；起点第一次不带游标要 100 条（详情只内联 50 条、不给游标）；
3. 倍速：两个播放器都是 rAF 墙钟驱动，dt × rate 与 `<video>.playbackRate` 一起改，`<video>` 重建后每次渲染重钉一遍；
4. 路由按 id 重挂（`VideoRoute`）：从 A 点进 B 不再串点赞数 / 播放数 / 选集 / 进度，进来回到页顶；
5. 举报 / 拉黑在离线或自己的作品上组件回 null：动作条按 `canReport` 一处判第五格放什么，不留空洞；
6. `FeedActionSheet` 两种宿主的话分开说（首页「清屏观看」「在详情页里选」，详情页「全屏观看」、当场开下载面板）；
7. `useRemake` 留着首页的 `!locked` 与「被拒那句话几秒后自清」；
8. 全屏 / 横屏沉浸态里也有「AI 生成」标识与退出键；
9. 弹幕条在服务端回来之前不写「弹幕 0」（`danmakuFetched`）；
10. 多 P 老作品只在第 1 集画弹幕（弹幕是全片秒、不分集）；
11. 关注 / 收藏失败的话摆在键旁：`account.setFollow` / `setCollect` 等结果、回滚、回一句话。

## 六、没做的

- P1（要服务端 PR）：详情接口加弹幕总数、「照这条做的同款」列表（列表接口加 remixOf 过滤）；分享数不补（拿不到真的分享了没有的信号）；
- P2：评论热度排序、作者作品数 / 获赞数、真推荐、互动作品「我看过的结局」；B 站的投币我们没有对应的东西，不抄；
- 模拟器验：全屏 / 转屏、物理返回键退全屏（靠 fullscreenchange）、倍速与弹幕同步、竖屏作品首屏截图核对 44vh；
- B 站 App 内几处细节（「简介 / 评论」页签名、发弹幕胶囊位置、UP 主行粉丝数）这次没在国内网络的真机上截图核对，不影响本方案。
