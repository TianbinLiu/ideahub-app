# TapNow / RunningHub 调研：按出片模型扩充「跟着做」，以及把模式做成生态（2026-10-05）

> 主人 10-05 两件事：
> ① 调研 TapNow 和 RunningHub（两家都是 AI 画布平台、都接了 Seedance 2.5，卖点和我们一样：服务不会自己搭工作流、又想做出好作品的人），
>    看它们的画布和工作流模板能不能整合进来，让「每个出片模型各有一套专用模式 / 模板」比现在「六个模式、分三组摆」更多。
> ② 有人说 RunningHub 的工作流和模型生态更强 —— 它是怎么做的？我们能不能也有同样质量的模型生态和工作流（这正是做创意工坊和六个模式的原因）？
>    我们的模型 / 模式生态有没有改进空间，能不能放开让用户自由创作、加入生态？
>
> 怎么查的（**没登录、没花钱**）：
> · TapNow：读了公开接口里 36 个官方技能的说明、322 个官方模板的**完整画布**（每个节点用的模型、生成方式、时长、连线），首页那组「SD2.5 Master Skills」。
>   官方技能画布与社区作品（TapTV）要登录才能打开，没走。
> · RunningHub：首页、ComfyUI 工作流区、AI 应用区、模型库、rhTV 社区「聚光营地」（十几张模板的只读画布，节点上连**实际花了多少钱**都有）、技能广场、
>   创作者激励规则页、Seedance 2.5 接口说明、RHSTORY。
> · 官方口径：火山方舟《Doubao Seedance 2.5 教程》（2026-09-30 版）与《Doubao Seedance 2.0 系列教程》—— 我们直连方舟，不经过这两家，能做什么以官方为准。
>
> 两家的提示词没有抄进来（别人的作品、也是主人定过的规矩），下文的写法都是按句式自己写的示意。

## 一、结论先说

1. **两家的模板，绝大多数是十来种固定套路换皮**（第二、三节）：一张图出整套分镜挑格、先写结构化分镜再逐镜出片、首帧改图得尾帧、先做设定图再全能参考一条出、
   你来当主角（照片 + 预设场景）、照着一条视频的运镜拍我的人、对话正反打、拆漫画逐格动起来。我们的 B / C / D 已经覆盖了其中三种，**剩下的大部分能用现有积木拼出来**。
2. **「按模型的专用模式」最大的空白在 Seedance 2.5 身上**：官方给 2.5 主推的能力 —— 视频**延长**（2.5 可多轮）、**按时间戳编辑**（片段重拍）、**样片模式**（先 480p 试拍，2.5 独有）、
   30 秒、50 个参考、只给音频当参考 —— 我们只用到了「编辑」（白模复刻与返修）。两家首页主推的正是这一组（TapNow 的 SD2.5 Master Skills、RunningHub 的「片段重拍 / 高级编辑 / 延长」）。
3. **一个被我们漏掉的事实**：官方能力表里，2.0 mini（我们的「高清」档）**也支持视频参考、编辑和延长**（≤3 段、合计 ≤15 秒），而我们的档位表把高清档的参考视频标成了不支持
   （当时没核实，`economy.ts` 里写着「将来若开闸备选 0.93，前置是 A6 实测 + 账单核对」）。打开它，返修 / 延长 / 运镜复刻就能落到便宜得多的那一档（含视频输入 14 元/百万 token，2.5 是 42）。
4. **RunningHub 的「模型生态」是算力生意**：海马云的 GPU + ComfyUI，托管开源模型、用户上传和训练 LoRA、按运行量给作者**现金分成**。这一层我们复制不了、也不该复制
   （我们是直连方舟的接口转售，没有 GPU；现金分成正撞 token「不可提现、不可在用户之间流转」那条红线）。
   **但它让普通人用得上的，是盖在算力上面的四层**：一键同款（换素材就出）→ AI 应用（工作流包成几个输入框的表单）→ 画布模板 / 技能 → 原始工作流。
   这四层我们能做、而且能比它做得更适合手机：我们已有的创意工坊（卡片 / 风格卡 / 图位方案 / 声音）就是「素材生态」，缺的是「方法生态」—— 六个模式写死在代码里，用户能发布的技能只是一句话。
5. **建议**：先把 2.5 和 2.0 mini 已有的能力吃满（新增「修这一段」一组五个动作 + 八个新模式，第五节），再把模式改成**可存档、可发布的「玩法」**（声明式积木：跑通一次才能发、能在哪几档跑自动判、价钱自动算），
   奖励只发平台 token（沿用同款奖励那套规则）。模型这边只建议评估一条：**真人档换 MiniMax H3**（同一家供应商、多参考 + 有声 + 15 秒），其它供应商等需求明确再说。

## 二、TapNow（tapnow.ai，Tamar AI Inc.，版本 v2.19.7）

### 产品形态
首页是一个对话框（「What are we making today?」）+ 一排工作室 / 技能入口 + 官方模板；画布是节点式（文本 / 图片 / 视频 / 音频节点，连线传参）；社区 TapTV 可以「克隆项目」拿到别人的整张画布。
它把自己叫 Creative OS：Agent 在画布上铺节点、写提示词，用户在关键处挑选。

### 技能与工作室（Apps / Skills，36 个）
数据结构值得学：每个技能都写清 **适用场景 / 需要你给什么 / 固定几步 / 产出什么 / 之后能接着做什么 / 边界**，并标一个推荐模型。和视频相关的：

| 技能 | 它做什么 | 对我们的意义 |
|---|---|---|
| **Seedance 2 / Seedance 2.5 / MiniMax H3 / Kling 提示词助手**（每个模型一个） | 先确认需求与素材（不确认不写、不出）→ 建一张**参考图分工表**（每张参考管长相 / 产品 / 场景 / 镜头 / 动作 / 台词 / 声音 / 起止状态中的哪一样）→ 写带时间码的完整方案 → 出了不满意时**只改影响结果的那一处**，不悄悄删素材、不偷换模型 | 我们的参考清单（N1）只写「图片 N = 谁」，没写「这张管什么」；也没有「这段不满意 → 诊断 → 只改一处」 |
| **SD2.5 Master Skills**（首页主推，五张官方画布） | 秒级重拍（在时间轴上重拍某几秒）、无限延长（前后续写 + 外扩）、OmniCamera（同一段换机位）、全模态主体（声音 + 图 + 视频合成一个主体，最多 50 个参考）、空间擦除替换（自动跟踪运动物体，擦掉或换掉） | 全是 2.5 的独门能力，我们只做了其中「编辑」一种（返修） |
| **H3 Master Skill** | 图 + 视频 + 音频组合指挥 MiniMax H3 | 见第六节模型生态 |
| **Casting Room**（选角间） | 角色小传 → 定妆照 → 几套造型 → 声音 → 表情，存成可复用的「主体」 | 我们的人物卡 + 图位方案 + 声音样本已有大半，缺「一个人多套造型 / 表情」 |
| **Depth Filmmaking Studio** | 源视频转成深度图视频（只留动作与空间、不留身份）→ 按新的人物 / 场景参考重拍；预置希区柯克变焦、环绕、甩镜三种运镜 | 与我们的白模复刻同一个思路（白模 = 去身份留动作）；预置运镜库是新东西 |
| **Whitebox Video Previs** | 3D 白盒摆位 → 出一条白盒参考视频 → 验过再交给正式出片 | 与我们的导演台同一个思路 |
| **Music Video Studio / Music Performance** | 歌 + 歌词 + 参考 → 按节拍切镜的 MV / 角色演唱 | 唱段类模式 |
| **Creation Breakdown**（拆解这张画布） | 读一张已有画布：创作意图、关键节点、模型选择、返工，**只讲看得见的证据、不替作者编动机** | 我们的「制作过程」页能加一个「AI 讲讲这条是怎么做的」 |
| **Skill Creator** | 把自己反复做的流程存成技能（触发条件、输入输出、边界、好坏例子） | 用户自建「玩法」的雏形（公开页面没看到能不能发给别人） |
| 数字人系列 / 电商系列 | 口播、房产带看、产品讲解、新闻播报；一张产品图出全套电商图 / 广告 / 多尺寸 / 多语言 | 口播与电商不在我们现在的定位里（第七节要主人定） |

### 反复出现的套路（我们能不能拼出来）

| 套路 | 典型模板 | 结构 | 我们 |
|---|---|---|---|
| ① 一张图出整套分镜 | 多镜头电影分镜、多角度分镜、九宫格多景别 | 一张人物图 → 12 格故事 / 四个角度各一张四宫格（远中近特）/ 3×3 关键帧 → 挑一格放大出片，**或整张宫格直接喂视频模型「按格依次演成一条」** | C 已有（从文字出组图）；缺「从一张图出」与「整组一条出」 |
| ② 先写结构化分镜，再逐镜出片 | Json 大师、分镜大师、狗血小短剧、音乐 MV | 对话节点写 N 个镜头（景别 / 机位 / 画面）→ 每镜一个出片节点 | 剧本 → 分镜技能、B 的拆镜头已有 |
| ③ 首帧改图得尾帧 | 分镜大师、尾帧生成 | 首帧 → 「把车去掉」= 车开走的结尾 / 「换成特写」→ 首尾帧出片 | 「改这一帧」与标准档首尾帧都有，缺一个把它们串起来的模式 |
| ④ 先做设定，再一条出 | 文生角色全套专业卡、（RH）选取角色卡变装、产品闪亮登场 | 三视图 + 全身 + 半身 + 特写（或服装六宫格 / 产品三视图）→ 全能参考一条出 10~30 秒 | B 就是这个 |
| ⑤ 姿势 / 动作参考合成 | 让 TA 动起来、迁移打斗动作 | 人偶姿势图 + 人物 → 合成到场景 → 动起来 | 导演台（摆人偶）已有 |
| ⑥ 你来当主角 | Seedance 2.0 专区大多数 | 用户照片 + 模板风格图 → 关键帧（把人放进预设场景）→ 「从这一帧开始」出 5~10 秒 | 没有（缺预设库） |
| ⑦ 镜头语法库 | 景别 × 视角 × 特效镜头大全、英雄史诗电影赞歌 | 景别 1~9、俯仰 1~7、正侧背、镜头效果各出一张九宫格挑；或按 9 种组合各出一帧、按顺序参考出片 | 运镜词表有；缺「景别 / 视角」可视化挑选 |
| ⑧ 对话正反打 | 生成对话镜头 | 两个人 + 场景 → 双人镜头、过肩 A、过肩 B 各一张 | 没有 |
| ⑨ 拆漫画逐格动起来 | 漫画转动画 | 去掉文字与气泡 → 拆成单格 → 每格图生视频 | 没有（C 的「一格一段」能接） |
| ⑩ 爆款复刻 | 爆款电商视频复刻机 | 分析一条爆款的分场 → 按我的产品改写 → 每场一张图 → 全能参考出片 | 做同款 / 白模复刻是近亲 |

## 三、RunningHub（runninghub.cn，安徽海马云）

### 产品矩阵：从轻到重六层
1. **一键同款**（rhTV 社区「聚光营地」第一栏）：「替换素材即可生成」—— 只换你的照片 / 产品，分 热门精选 / 商业广告 / 人像摄影 / 动作舞蹈 / 趣味玩法 / 专题（例：周星驰电影风格专题）。
2. **快捷创作**：挑模型 + 挑模板，一键出。
3. **AI 应用**：作者把一个 ComfyUI 工作流**包成只剩几个输入框的表单**。例：「AI 漫剧批量资产创建」—— 输入只有 分辨率 / 类型（角色 · 场景 · 道具）/ 风格描述 / 小说原文，
   页面写明预估价（约 2 RH 币）、**近期成功率 99%、平均 85 秒**、2.49 万次运行，下面是别人用它做出来的作品墙（96 条）和评论，还能直接当 API 调。
4. **rhTV 无限画布**：工作流模板（「预览工作流 → 克隆并编辑」，热门是各种卡点换装、产品亮相、转场、子弹时间、环绕展示、卡点舞）、技能广场（发现 / 喜欢 / **我的** —— 用户能建自己的技能；
   例：「换机位重拍：保留原视频表演与动作，只换摄影机角度」「诺兰感时间冻结」「宫崎骏式手绘诗篇」，每个技能是一个可以「添加到对话」的导演 Agent）、创作学院。
   画布节点能直接嵌 AI 应用、3D 导演台、快剪；节点上记着这一步的模型、参数和**实扣金额**。
5. **ComfyUI 工作流**：社区作者上传的原始节点图（例：Seedance 2.0 全能参考、WAN 2.2 首尾帧循环、SeedVR2 超分补帧、多角色对话动画），分 20 多个类目。
6. **API 与 VibeX**：模型 API / AI 应用 API / 工作流 API / LLM API；VibeX 让用户自己开发应用、网站与 Agent（「百亿 Token 补贴」）。
另有 **RHSTORY（RH 剧场）**：有剧本（导入 TXT / DOCX / PDF，AI 整理、提取角色场景道具、拆分镜）/ 有想法 / 有视频（视频重绘：换角色、画风、语言、画幅，出海用），可选「导演风格」，社区是多集短剧。

### 模型生态
**模型库**：用户上传 LoRA / UNET（写实、二次元、国风、产品、服饰……），可在线**训练** LoRA；社区里连 MiniMax H3 开源版都有人练风格 LoRA。
再加上自研模型（H3 增强版、RH Upscale 超分）和接入的闭源模型（Seedance 2.5、万相 3.0、MiniMax H3……）。**底座是海马云的 GPU**。

### Seedance 2.5 在它那里的四种用法（画布节点里读到的，含实扣）
它自己写的功能说明：①视频编辑（单个视频 + 参考）②**高级编辑**（截时间戳、逐帧定位到某一帧精修，提示词里嵌一个「帧标记」）③视频延长（往前或往后续写）④**片段重拍**（在视频里最多截 5 段、逐段改）。
画布实例：音乐剧片段（两张角色设定图 + 改写好的英文唱词 → 30 秒、有声，实扣 ¥57.14）；编辑（「给他戴上红色皮帽」，5 秒 ¥29.53）；向后延长 7 秒 ¥19.28、向前续写 6 秒 ¥23.81；
选取角色卡变装（三视图 + 一段很长的结构化提示词 → 30 秒 ¥56.78）；撞车营销（「仿照 @视频1 的镜头设计」+ 我的人物与服装 + 一句口播 → 20 秒）。
它的 2.5 接口把官方参数几乎原样露出来：最多 30 图 + 10 视频 + 10 音频、`omni_reference_task_type`（auto / reference / edit / extend）、`draft`（样片）、`realPersonMode`、`return_last_frame`、`output_format`（mp4 / mov），
25 秒 720p 标价 ¥47.93。另有自研「深度捕捉」工具（视频 → 深度图视频，用来复刻动作与运镜）。

### 创作者激励（官方规则页）
- 收益来源：发布**工作流、AI 应用或模型**。按三项算：**有效运行人次**（含 API 调用）、**被收藏次数**、**原创度**（越原创额外越多）。
- 搬运的模型不分成，上传的模型人工审核原创性；抄袭被举报或抽检发现即下架、扣收益；低质内容限制可见。

- 另有：首发奖励、周榜奖金、赛事（百万奖金）、邀请一个新用户双方各得 500 RH 币。

## 六、生态：RunningHub 是怎么做的、我们差在哪、怎么放开

### 它的生态立在五根柱子上
1. **素材**：模型库（LoRA）、资产库。
2. **方法**：工作流 → AI 应用 → 画布模板 → 技能 → 一键同款，**同一个方法有从专业到傻瓜的几层外壳**。
3. **分发**：按场景分类目、专题、热门榜、作品墙（别人用它做出来的东西）。
4. **信任信号**：运行次数、收藏数、近期成功率、平均用时、预估价、实扣金额。
5. **激励**：按运行量 + 收藏 + 原创给现金；赛事；邀请得币。

### 我们已有的（对照）
| 柱子 | 我们 |
|---|---|
| 素材 | 创意工坊卡片广场（人物 / 场景 / 道具 / 风格 / 背景卡）、图位方案市场、声音市场、Live2D 形象与人格市场 —— **风格卡与图位方案就是闭源模型上的 LoRA 等价物**，而且已经是用户可做、可分享的 |
| 方法 | 六个模式（官方、写死在代码里）、四条结构化技能（官方）、出片技能（用户可建可发，但只是一句话）、白模模板市场、工作流模板（上了架的公开配方：复制一整条作品的流程、选角换人，适合「照着这条故事再做一条」，不是「换一张图就出」的单个方法） |
| 分发 | 模板市场按出片模型筛；作品页「查看制作过程」；做同款 |
| 信任信号 | 报价与实扣对账（很强）；**没有**运行次数、成功率、平均用时、示例作品墙 |
| 激励 | 同款奖励（别人照着做同款并公开满 24 小时，平台发 30k token；每人、每条原作、全站几道上限防刷） |

### 差距
1. **方法层只有官方能出**：加一个模式 = 一个完整 PR（向导 + 状态 + 规则 + 检查脚本），六个做了三期。用户能发布的只有一句话的技能。
2. **同一个方法没有「傻瓜外壳」**：没有「换素材就出」那一层（RH 一键同款、TapNow 可执行模板）。
3. **模式的入口不带示例**：选法屏只有一句话说明，没有示例视频、没有「多少人用过、成功率多少」。
4. **2.5 / 2.0 mini 的能力只用了一半**（第四、五节）。
5. **没有「这条是怎么做出来的」讲解**（TapNow Creation Breakdown），学方法全靠自己看配方。

### 方案：把模式做成「玩法」
**玩法 = 一份声明式的固定步骤**（不是代码），由一小组白名单积木拼成：
- 输入：几张卡（人物 / 场景 / 道具，几张到几张）、一张照片、一段文字（有上限）、一段视频（运镜参考）——作者勾哪几项「可换」，就是一键同款的那几个空。
- 步骤：一次对话（带输出形状检查，和现在的结构化技能同一副骨架）、画几张图 / 一组图、出一段（直出 / 帧当参考图 / 参考视频 / 编辑 / 延长）、挑格子。
- 落地：每一步的产物落进现有结构（卡 → 素材、图 → 开头帧或临时参考图、段 → `appendSpecs`，C 第三期刚做好的那套）。
- **能在哪几档跑由积木自动判**（与 `guidedModes.modeBlock` 同一把尺：用了参考视频就只能 2.x、用了首尾帧硬约束就标准档最准……），**价钱由积木自动算**（与真扣同一个函数）。
- 安全：没有任意代码；作者写的提示词只是发给模型的内容（照样过方舟审核），钱照样按调用在服务端结算，装来的玩法与自己的走同一条路（出片技能已经这么做）。

分四步走：
- **E1 官方玩法用积木写**：先把 G 特效同款、H 前后对比做成第一批数据驱动的玩法（验证积木够不够用）；B / C 这种有挑选步骤的复杂向导先不改。App 内完成。
- **E2 存为我的玩法**：跑通过一次的流程可以存成自己的玩法（与工作流模板「跑通一次才能发」同一条规矩），换素材再跑。要服务端存。
- **E3 玩法广场**：发布、审核（原创 / 合规）、按出片模型筛、示例作品墙、**用过的人数 / 成片数 / 成功率 / 平均花费**。要服务端。
- **E4 奖励**：别人用你的玩法做出作品并公开满 24 小时，平台发 token（**同款奖励那一套规则与防刷上限原样搬过来**）；创作者等级与徽章（TapNow 那种）。
  **不做现金分成**：现金要走「商家转账到零钱」且要企业主体（红线备忘），是另一个立项，由主人决定要不要做。

### 模型生态：三条路的取舍
1. **先把已接的模型吃满**（推荐）：2.5 的延长 / 时间戳编辑 / 样片 / 30 秒 / 纯音频参考，2.0 mini 的视频参考 / 编辑 / 延长。这些不换供应商、不加合规面，花钱的验证也小。
2. **真人档换 MiniMax H3**（值得调研）：两家都在主推它（TapNow 有专门的 H3 技能、RH 做了增强版）。2026-07-31 发布、8 月开源：最多 9 图 + 3 视频 + 3 音频参考、原生双声道、4~15 秒、最高 2K，API 约 $0.13/秒。
   我们已经接着 MiniMax（真人档的 Hailuo 2.3 Fast），换模型不加供应商；要实测的是：收不收真人照片（Hailuo 收）、账单、出境合规口径（服务端已切国际站）。
3. **加新供应商**（可灵 / 万相 3.0 / Veo）：每家都是接口 + 计价 + 内容合规三件套，等有具体需求再说。
**不做**：自建 GPU、托管开源模型、用户训练 LoRA —— RunningHub 的底座是海马云的算力，我们没有，也不该为此转型；把 RunningHub / TapNow 当后端中转调用 —— 多一层第三方、合规与成本都不可控。

**不花钱就定了的事**（官方 2.5 提示词指南，2026-10-05 读；示例文件用 ffprobe 量）：
- 延长的产物**只有新的一截**：示例输入 15.046s，产物 5.000s（mov，h264 + PCM 声音），另附的「拼接后的视频」20.083s。原来列进付费探测的 ④ 不用再花钱。
- 按时间段编辑的官方写法是「把视频 1 中 4-6 秒……，其余内容不要变化」；App 的写法照它（`只改视频1中第a-b秒：……。这几秒以外的内容不要变化`）。
- 编辑的产物比原片短约 0.33 秒（官方常见问题；输入帧数是 8n+1 时一致）；延长推荐 mov 输出、音量可能轻微变化，2.5 自己生成的片子延长效果更好。
  我们先照旧出 mp4（合成链路没验过 mov 里的 PCM 声音）。
