## 1. 尺度诊断：桌子为什么大了（SCALE 3.2 → 1.0）

**病根不是桌子，是尺度基准。** 上一版为了让 22×9 的 PBR 盖板把 splat 里的桌面整个盖住，
把房间放大了 **SCALE = 3.2**：量出来纵深 7.96 m 的屋子变成 25.5 世界单位、桌面 2.5 m 变成 8.0、
桌高 0.765 m 变成 2.45 —— 而铸卡师（TripoNpc，真人比例 **1.7 世界单位**，她没跟着放大）还是 1.7。
结果上一版验收图里她像个 1/10 的手办站在一张平台上：

| 比值 | 上一版（SCALE 3.2） | 真实/本版（SCALE 1） |
|---|---|---|
| 桌长 ÷ NPC 身高 | 8.00 ÷ 1.7 = **4.71** | 2.50 ÷ 1.7 = **1.47** |
| 桌高 ÷ NPC 身高 | 2.45 ÷ 1.7 = **1.44**（比人还高） | 0.765 ÷ 1.7 = **0.45**（≈ 腰） |
| 房深 ÷ 桌长 | 25.5 ÷ 8.0 = 3.18 | 7.96 ÷ 2.5 = **3.18**（同一间屋，比例不变） |
| 房深 ÷ NPC 身高 | 25.5 ÷ 1.7 = **15.0** | 7.96 ÷ 1.7 = **4.68** |
| 桌宽 ÷ NPC 身高 | 3.74 ÷ 1.7 = 2.20 | 1.17 ÷ 1.7 = **0.69** |

**改法**：以房间为基准 —— splat 点云量出来的 **7.96（纵深）× 4.31（宽）× 3.84（高）就是米**，
于是 `SCALE = 1.0`。四个数（桌长 2.50、桌宽 1.17、桌高 0.765、房深 7.96）与 NPC 的 1.7
摆在一起，上面那张"真实"列就是验据。**"桌子在画面里占多大"改由相机位置调，不再动场景缩放。**

### 1.1 新的落位四件套（`gsStep0.ts`）

```ts
const YAW_DEG = 20.15;  // 不变：窗在 -z、壁炉墙在 -x
const TILT_DEG = 0;     // 上一版 -6°；这一版必须 0（否则网格桌面与 splat 桌面上下错开 2.5·sin6° ≈ 0.26 m）
const ROLL_DEG = 1.203; // 新增：点云桌面法线对 +y 歪 1.2°（房间的 s 轴方向），不纠远端会高出 5.2 cm
const SCALE = 1;
const TARGET = [0, -0.02, 0]; // 桌面顶面中心；y=-0.02 让 splat 桌面沉到网格毡面（+0.004）下 2.4 cm
```

- **ROLL 是量出来的，不是凑对称**：桌面那层点云的法线 = (-0.0212, 0.9998, 0.0005)（yaw 之后的世界系），
  对 +y 歪 **1.22°**；2.5 m 长的桌面远端因此比近端高 5.2 cm —— 不纠的话网格毡面压不住 splat 桌面，
  验收图里"桌面远半截变成 splat 的灰桌面"就是这么来的（本日志 §6 的第一版截图）。
  纠完残差 std **0.94 cm**，网格毡面再抬高 2.4 cm 就盖住了。
  代价：整间屋绕视线轴侧倾 1.2°（窗心横移 ~12 cm），肉眼看不出来。
- **TARGET.y = -0.02**：splat 桌面顶面中心落到 -0.02，网格毡面顶面 +0.004 → 网格比 splat 高 2.4 cm。
  桌高相对地板（splat 地板在 -0.785）= **0.789 m**（毡面顶 0.004 到地板），比量测的 0.765 多 2.4 cm ——
  这是"盖住 splat 桌面"的代价，仍在 NPC 腰部。
- **删了 tilt 之后圆窗还在画面里**：米制机位俯角 ~27°、窗心只比桌面高 0.68 m、在相机前 ~5 m
  ⇒ 窗心在视野轴上方 ~15°，50° 垂直视野装得下（见 §5 的俯视截图）。

### 1.2 新机位 `layout.GS_CAM`

```ts
GS_CAM = { pos: [0.55, 1.1, 2.0], look: [-0.1, 0.0, -0.9] };  // 俯角 ≈ 20.8°，距桌心 ≈ 2.35 m
```

- 老 `LAND_CAM` 是 (0, 3.9, 7.4) / 俯角 30° —— 对 22×9 的"UI 画布桌面"合适，对 2.5×1.17 的真桌子
  就是"站在三米外俯拍一张课桌"。新机位的选取顺序（都按 800×363 的 app 画幅量）：
  1. 先按"桌面要占画面下半"定机位高度/距离：**pos y 1.1、z 2.0（桌心后方 2.0 m）**；
  2. 再看 NPC：她站在 z=-1.9，1.75 m 高，头顶落在画面 **~12%**（顶部 UI 条以下）；
  3. 再看窗：窗心落在画面 **右上 20~30%**，不被 NPC 完全挡住（截图里她站在窗前偏左一点）；
  4. 俯角 21° 比老机位 30° 浅一档（真桌子只有 1.17 m 深，30° 会把桌面压成一条）；
     桌面近边落在画面下缘外（与老场景一样"桌子从画面下缘伸出去"）。
- 相机只影响构图，**不改场景尺度** —— 这一条写死在 `defaultCamFor`：GS 米制档只返回 `GS_CAM`。

### 1.3 桌面与 splat 桌子的对位

- **同向同寸**：splat 那张长桌长轴沿房间纵深 d（世界 z），2.50 × 1.17；网格桌面也是 2.50（z）× 1.17（x）。
  上一版是把 22×9 的横向盖板压上去的（方向都不同，只是靠尺寸大盖住）。
- 网格桌面的顶面（毡面 +0.004）把 splat 桌面（-0.02）整块盖住；点云 ±0.94 cm 的残差尾巴
  **理论上会零星透出**，验收三张里没有可见的穿透（见 §8 风险 1）。
- 桌面**不落地**的老观感只在老场景保留（GS 关着时桌腿沿用旧高度）；米制档桌腿落到地板 -0.785。

## 2. 旧桌面是怎么找回并复用的

1. **源头**：`TableScene.tsx` 在 GS 第 0 步之前那一版（commit `e225b5e9^`，G4 时期的"赌桌绒呢桌布 + 皮革软包护栏"）
   里的 `makeFeltCloth / TableCloth / TableRail / Table / CenterLine`。
2. **搬出来**：整段几何与材质**原样**搬进新文件 `WorkshopTable.tsx`（视觉参数一个没改）：
   深绿毡面（`#123c2a` + 噪点）、金色印花（双重边框 / 庄家弧线 / 中央法阵 24 射线 / 四角菱花）、
   黄铜色皮革软包护栏（圆柱 + 四角圆球）、深胡桃木桌体/桌沿/桌腿、青色中线。
3. **参数化**：组件接 `T`（桌面尺寸）+ `height`（离地高）+ `metric`（米制装饰档）。
   - 老场景：`T` 来自 `layout.sceneLayout(land).table`（横屏 22×9 / 竖屏 16×7），`metric=false` ——
     尺寸、护栏半径 0.17、桌沿 0.6 宽、桌腿 0.4 → **观感逐字节不变**；
   - 米制档：`T = GS_TABLE (1.17×2.5×0.14)`、`height=0.765`、`metric=true` —— 护栏半径 0.035、
     桌沿 0.03、桌腿 0.06 且落到地板、毡面 0.97×2.35、四角菱花去掉（1.7 cm 的角花会糊成噪点）。
4. **删掉盖板**：`GsStep0Environment.tsx` 里的 `GsTableCover` 与它的木纹/法线生成函数（约 120 行）整个删了；
   `TableScene` 现在只有一处 `<Table />`，它再调 `<WorkshopTable>`。这样"桌面尺寸"只剩一处（layout），
   不会出现"桌子和盖板各画一半"。
5. **材质**：米制档从 `meshStandardMaterial` 换成 **`meshPhysicalMaterial`**，`roughness=0.78`、
   `metalness=0`、`specularIntensity=0.18`、`envMapIntensity=0.06` —— 毡面保持哑光，
   且**掠射角下不再出现"桌面右半截发灰的冷镜面"**（第一版验收图里的那层灰就是标准材质 4% F0 的
   Fresnel + PMREM 冷天空；任务要求"别出现镜面反光"）。

## 3. 桌面光毯（lightmap）

### 3.1 怎么生成

`design/gen-table-lightmap.mjs`（**零依赖**：只用 Node 内置 `zlib`，自写 PNG 编码；不需要 canvas/sharp）：

```bash
node design/gen-table-lightmap.mjs                     # 写 public/models/study/tex/table-lightmap.png
node design/gen-table-lightmap.mjs --window 0.7 --fire 0.8 --sigil 0.5   # 调三种光的强度
node design/gen-table-lightmap.mjs --seed 7 --out /tmp/x.png             # 换噪点种子 / 换输出
```

- 尺寸 **1024 × 512**（RGBA8；长轴 = 桌面 2.5 m 方向，一张 texel ≈ 2.4 mm），与桌面长宽比（2.14）匹配。
- 三种光（参数都在脚本顶的 `PARAMS`，可调）：

| 光 | 参数 | 读数（0~255） |
|---|---|---|
| ① 圆窗冷光斑 | center (u .76, v .52)，椭圆半径 (.20, .34)，色 (0.62,0.76,1.0)，strength **0.5** | 池心 **155,160,195** |
| ② 左前壁炉暖光 | center (u 1.04, v -0.10)（远端左角之外），半径 (.78,.95)，色 (1.0,0.44,0.16)，strength **0.6** | 远端左角 **164,81,43** |
| ③ 中央法阵自发光 | 与毡面金线同轴，半径 0.0857 m（= 毡面纹理 150/2048 × 桌宽），strength **0.62** | 桌面中心 **72,58,42** |
| 环境 | farCool 0.06 / nearDark 0.14 | 近端右角 0,0,0 |

- 方向约定（与渲染端必须一致）：canvas **x 0 = 玩家这一端，x 1023 = 圆窗那一端**；
  **y 0 = 桌左（壁炉侧），y 511 = 桌右（书柜侧）**。推导见 `WorkshopTable.Lightmap` 的注释
  （贴图 flipY + 父组绕 y 转 90°）。
- 抖动：每像素 ±1.2/255 的确定噪点（同一 seed 每次同一张），压住 8 bit 渐变的带状。

### 3.2 怎么贴在桌上

- `WorkshopTable` 在毡面上再叠一层 **加色平面**（`planeGeometry [2.3, 0.97]`，绕 y 转 90°，
  `blending: AdditiveBlending`、`depthWrite: false`、`toneMapped: false`），只负责"加光"，
  不盖住毡面的金线与法阵（与"当 map 盖上去"相比保留了毡面的 normal/roughness 贴图）。
- 桌面本体仍是**哑光**：roughness 0.78（要求区间 0.6~0.8）、metalness 0、specularIntensity 0.18。
- 贴图缺失不会让桌子消失：加载失败只在 console 说一句，桌面退回纯毡面（光毯是增强项）。
- PNG 体积 **≈ 0.69 MiB**（1024×512 RGBA + 抖动）；要更小可改 RGB / 降噪，脚本里一处就能改。

## 4. 火与光（方案 A 的核心）

### 4.1 壁炉位置：从"估的点"微调到"看得见的炉膛"

- 上一版 `ANCHOR.fire = (s -3.18, d 4.80, y 0.50)` 是**估的**（炉膛被家具挡住，量不到）。
  米制场景里把火放在那里，验收图里火焰**悬在壁炉右侧的墙上**（截图 `.tmp-gs-table/` 的第一轮）。
- 本版按"允许微调到视觉合理处"移到 **`(s -2.72, d 3.10, y 0.62)`** → 世界 ≈ **(-1.45, -0.24, +0.10)**：
  正对壁炉开口、离桌面左沿 0.87 m、离 NPC 左肩 ~1.9 m。位置仍由 `toSplat/toWorld` 现算，**只改一处**。

### 4.2 三件东西（`HearthFire.tsx`）

1. **点光源**：暖色 `#ff9a4a`、`intensity 7` / `distance 5.5` / `decay 2`（米制 1/d² 衰减）。
   闪烁 = 7.3 Hz 主频 + 2.1 Hz 呼吸 + 23.7 Hz 细抖的**多频正弦叠加**（幅度 22%，不是随机跳变——
   随机跳在低帧率下读成"坏灯"）；炉心位置 ±2.5 cm 轻跳。
2. **火焰动画**：`ShaderMaterial` + 5 层 fbm 噪声（向上卷动 + 低频左右摆），泪滴轮廓 × 噪声阈值，
   颜色从底部暗红 → 橙 → 顶上黄白；**双层**（外焰 0.38×0.55 m + 内焰 0.55 倍）、加色混合、
   绕 y 轴面向相机（只转 y，转 x 会像烧到桌面上）。
3. **假光池**：炉前地面一块 1.5×1.1 m 加色渐变（splat 地板不吃灯 —— 不加这一块，火"照不亮任何东西"），
   炉口再叠一层 2.6 倍大的柔光晕。`renderOrder={20}` 是整个火能看见的前提（见 4.3）。

### 4.3 ★ 光照边界（注释里写死，别以后以为火对墙也生效）

- **light 只照 mesh**：splat 用的是 ShaderMaterial，three 只给"要灯"的材质上传灯光 uniform。
  所以这盏点光只照到 **桌子 / NPC / 卡牌 / 法阵**；**splat 的墙、窗、地板一个像素都不会变亮**。
  "墙也暖一点"不要靠调灯（只会把桌子和人烤过曝），桌面暖靠光毯、地面暖靠假光池。
- **火必须画在 splat 之后**：SparkRenderer 是**透明**材质、`renderOrder=10`；火焰默认 0 会先画，
  然后整片 splat 糊上来。第一轮验收"壁炉里看不见火"就是这个原因（不是位置错、也不是 shader 没跑）。
  火焰 / 内焰 / 炉口光晕 / 地面光池四个网格全部 `renderOrder={20}`（与 `GsStep0Room` 文件头的
  渲染顺序约定一致：网格 0 / splat 10 / 玻璃与光效 20）。

### 4.4 灯组其余部分（米制重调）

| 灯 | 上一版（SCALE 3.2） | 本版（米制） | 为什么 |
|---|---|---|---|
| 月光方向光 | `sun [-2.5,7,-12] / 1.5` | `sun [-1.2,3.2,-6] / 0.9` | 方向光强度与距离无关，但桌面离窗近了 3 倍；0.9 是对着 splat 墙面亮度校的（再高桌面比 splat 亮，接缝显形） |
| 阴影框 | ±13.5 / ±9.5 | ±2.4 / ±1.8，near 0.1 / far 12 | 桌面+人只占 ±2 m；同样 2048² 阴影图每米多 6 倍像素（窗棂影从"糊"变"看得出格子"） |
| 窗面泛光 RectAreaLight | 3×3 / intensity 4 | 0.9×0.9 / intensity 12 | 面积小 11 倍、离得近；按现场观感校（第一版 26 把桌面远半截打爆） |
| NPC 补光 | `[0.8,2.6,7.6] / 0.9` | `[0.4,1.6,3.6] / 0.9` | 方向不变（相机侧顺光），距离按米制收；`?nofill=1` A/B 仍可用 |
| 雾 | [20,70] | [7,22] | 房间纵深 7.96 m；窗前 7 m 不吃雾（否则圆窗被雾压灰） |

## 5. 相机与卡位联动

- **卡牌基尺寸只有一个出处**：`layout.cardLayout()` —— 老场景 1.1×1.65，米制档 **0.28×0.42**。
  `CardMesh / SlotPlate / DeckStack / DeckSpread / MarketFan / DragLayer / FlightCard / DialogTableCards`
  全部读它（写死任何一处都会出现"画的是小米制、落点算的是老尺寸"）。
- **为什么是 0.28**：4 张角色卡一排横跨 4·0.28 + 3·0.015 = **1.165 m ≈ 桌宽 1.17**；
  在 800×363 的真机画幅上每张约 **68×28 px**（与老场景 64×34 同一档），卡面放得下封面 + 卡名，
  也不会"卡比桌子还宽"。0.42 深 = 1.5 倍宽（塔罗牌比例）。
- **5 个卡位 = 桌面上分层**（从 NPC 侧到玩家侧，各层卡深相加不重叠）：

| 层 | 世界坐标 | 尺寸 | 屏幕（852×348 投影算，与截图一致） |
|---|---|---|---|
| 场景位 | (0, **-1.0**) | 0.224×0.336（0.8 档） | y ≈ **48%**（远端、法阵之前） |
| 4 角色位 | x = ±0.4425 / ±0.1475，**z=-0.35** | 0.28×0.42（1.0 档） | y ≈ **57%**、x 33~67% |
| 市场两排 | z = **0.15 / 0.50**，dx 0.27，0.72 档 | 0.202×0.302 | y ≈ 67% / 77% |
| 卡组堆 / 摊开 / 合成法阵 | z ≈ 0.92~1.0（玩家这一侧） | 法阵缩到 0.32 | y ≈ 95~100%（贴画面下缘） |

- **"投影法重算"的落地**：旧的 `TABLE_SLOTS` 是按 22×9 桌面的屏幕百分比量的（角色排 y 44~53.5%），
  米制桌面**长轴换成了 z**，那组比例直接套会算到桌面外。本版改用"桌面分层 + 投影校核"：
  先按卡深排层（上表），再把每格投影回屏幕核对（`GameTableSlots` 每帧写 `SLOT_SCREEN`，
  2D 落点判定读同一份）—— 屏幕读数与上表一致，四张卡都在桌沿以内。
- **对话机位**：`layout.npcCam()` 给米制档一台新的 `GS_NPC_CAM = (0,0.72,1.15) → (0,0.35,-1.55)`
  （老场景的 `NPC_CAM` 是世界 UI 尺度，米制下会落到桌子底下）。`studioStore` 进对话、`TripoNpc`
  的注视基准都改成 `npcCam()`。
- **NPC 站位与身高**：新配置 `GS_MILLTINA_CFG`（`TableScene`）。★ 验收探针量出来一件事：
  `MILLTINA_CFG.scale=3.35` 换算到世界是 **约 3.43 m 高**（模型原点→头骨 1.0236 模型单位 × 3.35），

## 8. 已知风险 / 下一步

1. **splat 桌面残差**：ROLL 纠完残差 std 0.94 cm，网格毡面抬高 2.4 cm；>2.4 cm 的尾部点理论上会
   从毡面透出来。三张验收图里没看到可见穿透，但换资产/重估位姿要重量一次。
2. **对话俯身的幅度没重标定**：`GS_MILLTINA_CFG` 只改了站位与胸物理 rail；`leanSlide`
   （back 0.42 / z 0.08 / y 0.216）还是按老桌沿（4.3 m 远）量的。站姿验收图没问题，
   进对话让她伏桌时要再看一次（这是这一版**唯一没动的旧参数**）。
3. **帧率只有模拟器读数**（宿主机 GPU，ANGLE 桌面显卡），真机帧率仍没量；2M 高斯在手机上要按
   设置页两档 + 角标量。
4. **splat 里的椅子**：近侧/远侧各一把烘死在房间里。NPC 站在远端（椅子在她左边），近侧那把在
   桌面右侧当"前景"，三张图里都读得过去；但玩家绕到桌子另一边看会穿帮。
5. **老场景不受影响**：`sceneLayout()` 在 GS 关着时逐字节返回老布局；桌面组件换了实现但尺寸/材质/机位/
   卡位一个数没动（`WorkshopTable` 的 `metric=false` 分支就是原实现）。GS 失败回退时 `setGsPhase("failed")`
   会把米制标志位翻回 false，桌子/机位/NPC 一起退回老场景。
6. **光毯体积** 0.69 MiB（可改 RGB / 降噪）；**GS 资产**（31 + 8 MiB spz）仍不进仓库。
7. **`gsSceneCam` 是验收钩子**：不写这个 localStorage 键就不存在；生产里没人写 = 完全走 `GS_CAM`。
8. **2.5D / Blender 方向没做**（主人拍板先做 A；2.5D 那套仍在 `app` 工作区未提交，不属于本分支）。

### 10.9 这一版的风险 / 下一步

1. **两排是平放不是立牌**：立牌会把中线整条挡住（10.4 末尾那段实测），所以"脸对脸"的读感靠
   "两排 + 中线"给，牌面统一朝玩家。要真做立牌得先把机位抬到 1.9 m 以上 —— 那个机位在 splat 里是黑的。
2. **市场每页 4 张**（原来 8）：1.17 m 的桌宽放不下两排平放的牌。翻页变多（18 张种子 → 5 页）。
3. **下沉 0.12 m**：玩家侧的任何机位（正面/俯视/近景）都看不到裙摆以下；只有**纯侧面**能看到裙摆
   底缘贴着石板（不再往下），真机验收时留意。
4. **splat 桌面残差**仍在（§8 风险 1）：木端板只盖两端，长边仍是"网格毡面抬高 2.4 cm 压住点云"那套。
5. **腰高 0.571×身高** 是按人体比例估的（模型没有"腰"骨可以探针量）；要更准就得读 Hips 骨。
