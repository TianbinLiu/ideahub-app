## 1. 尺度诊断：桌子为什么大了（SCALE 3.2 → 1.0）

**病根不是桌子，是尺度基准。** 上一版为了让 22×9 的 PBR 盖板把 splat 里的桌面整个盖住，
把房间放大了 **SCALE = 3.2**：量出来纵深 7.96 m 的屋子变成 25.5 世界单位、桌面 2.5 m 变成 8.0、
桌高 0.765 m 变成 2.45 —— 而铸卡师（TripoNpc，真人比例 **1.7 世界单位**，她没跟着放大）还是 1.7。
结果上一版验收图里她像个 1/10 的手办站在一张平台上：

| 比值 | 上一版（SCALE 3.2） | 真实/本版（SCALE 1） |
|---|---|---|
| 桌长 ÷ NPC 身高 | 8.00 ÷ 1.7 = **4.71** | 2.50 ÷ 1.7 = **1.47** |
| 桌高 ÷ NPC 身高 | 2.45 ÷ 1.7 = **1.44**（比人还高） | 0.765 ÷ 1.7 = **0.45**（≈ 腰） |
| 房深 ÷ 桌长 | 25.5 ÷ 8.0 = 3.18 | 7.96 ÷ 2.5 = **3.18**（同一间屋，比例不变） |
| 房深 ÷ NPC 身高 | 25.5 ÷ 1.7 = **15.0** | 7.96 ÷ 1.7 = **4.68** |
| 桌宽 ÷ NPC 身高 | 3.74 ÷ 1.7 = 2.20 | 1.17 ÷ 1.7 = **0.69** |

**改法**：以房间为基准 —— splat 点云量出来的 **7.96（纵深）× 4.31（宽）× 3.84（高）就是米**，
于是 `SCALE = 1.0`。四个数（桌长 2.50、桌宽 1.17、桌高 0.765、房深 7.96）与 NPC 的 1.7
摆在一起，上面那张"真实"列就是验据。**"桌子在画面里占多大"改由相机位置调，不再动场景缩放。**

### 1.1 新的落位四件套（`gsStep0.ts`）

```ts
const YAW_DEG = 20.15;  // 不变：窗在 -z、壁炉墙在 -x
const TILT_DEG = 0;     // 上一版 -6°；这一版必须 0（否则网格桌面与 splat 桌面上下错开 2.5·sin6° ≈ 0.26 m）
const ROLL_DEG = 1.203; // 新增：点云桌面法线对 +y 歪 1.2°（房间的 s 轴方向），不纠远端会高出 5.2 cm
const SCALE = 1;
const TARGET = [0, -0.02, 0]; // 桌面顶面中心；y=-0.02 让 splat 桌面沉到网格毡面（+0.004）下 2.4 cm
```

- **ROLL 是量出来的，不是凑对称**：桌面那层点云的法线 = (-0.0212, 0.9998, 0.0005)（yaw 之后的世界系），
  对 +y 歪 **1.22°**；2.5 m 长的桌面远端因此比近端高 5.2 cm —— 不纠的话网格毡面压不住 splat 桌面，
  验收图里"桌面远半截变成 splat 的灰桌面"就是这么来的（本日志 §6 的第一版截图）。
  纠完残差 std **0.94 cm**，网格毡面再抬高 2.4 cm 就盖住了。
  代价：整间屋绕视线轴侧倾 1.2°（窗心横移 ~12 cm），肉眼看不出来。
- **TARGET.y = -0.02**：splat 桌面顶面中心落到 -0.02，网格毡面顶面 +0.004 → 网格比 splat 高 2.4 cm。
  桌高相对地板（splat 地板在 -0.785）= **0.789 m**（毡面顶 0.004 到地板），比量测的 0.765 多 2.4 cm ——
  这是"盖住 splat 桌面"的代价，仍在 NPC 腰部。
- **删了 tilt 之后圆窗还在画面里**：米制机位俯角 ~27°、窗心只比桌面高 0.68 m、在相机前 ~5 m
  ⇒ 窗心在视野轴上方 ~15°，50° 垂直视野装得下（见 §5 的俯视截图）。

### 1.2 新机位 `layout.GS_CAM`

```ts
GS_CAM = { pos: [0.55, 1.1, 2.0], look: [-0.1, 0.0, -0.9] };  // 俯角 ≈ 20.8°，距桌心 ≈ 2.35 m
```

- 老 `LAND_CAM` 是 (0, 3.9, 7.4) / 俯角 30° —— 对 22×9 的"UI 画布桌面"合适，对 2.5×1.17 的真桌子
  就是"站在三米外俯拍一张课桌"。新机位的选取顺序（都按 800×363 的 app 画幅量）：
  1. 先按"桌面要占画面下半"定机位高度/距离：**pos y 1.1、z 2.0（桌心后方 2.0 m）**；
  2. 再看 NPC：她站在 z=-1.9，1.75 m 高，头顶落在画面 **~12%**（顶部 UI 条以下）；
  3. 再看窗：窗心落在画面 **右上 20~30%**，不被 NPC 完全挡住（截图里她站在窗前偏左一点）；
  4. 俯角 21° 比老机位 30° 浅一档（真桌子只有 1.17 m 深，30° 会把桌面压成一条）；
     桌面近边落在画面下缘外（与老场景一样"桌子从画面下缘伸出去"）。
- 相机只影响构图，**不改场景尺度** —— 这一条写死在 `defaultCamFor`：GS 米制档只返回 `GS_CAM`。

### 1.3 桌面与 splat 桌子的对位

- **同向同寸**：splat 那张长桌长轴沿房间纵深 d（世界 z），2.50 × 1.17；网格桌面也是 2.50（z）× 1.17（x）。
  上一版是把 22×9 的横向盖板压上去的（方向都不同，只是靠尺寸大盖住）。
- 网格桌面的顶面（毡面 +0.004）把 splat 桌面（-0.02）整块盖住；点云 ±0.94 cm 的残差尾巴
  **理论上会零星透出**，验收三张里没有可见的穿透（见 §8 风险 1）。
- 桌面**不落地**的老观感只在老场景保留（GS 关着时桌腿沿用旧高度）；米制档桌腿落到地板 -0.785。

## 2. 旧桌面是怎么找回并复用的

1. **源头**：`TableScene.tsx` 在 GS 第 0 步之前那一版（commit `e225b5e9^`，G4 时期的"赌桌绒呢桌布 + 皮革软包护栏"）
   里的 `makeFeltCloth / TableCloth / TableRail / Table / CenterLine`。
2. **搬出来**：整段几何与材质**原样**搬进新文件 `WorkshopTable.tsx`（视觉参数一个没改）：
   深绿毡面（`#123c2a` + 噪点）、金色印花（双重边框 / 庄家弧线 / 中央法阵 24 射线 / 四角菱花）、
   黄铜色皮革软包护栏（圆柱 + 四角圆球）、深胡桃木桌体/桌沿/桌腿、青色中线。
3. **参数化**：组件接 `T`（桌面尺寸）+ `height`（离地高）+ `metric`（米制装饰档）。
   - 老场景：`T` 来自 `layout.sceneLayout(land).table`（横屏 22×9 / 竖屏 16×7），`metric=false` ——
     尺寸、护栏半径 0.17、桌沿 0.6 宽、桌腿 0.4 → **观感逐字节不变**；
   - 米制档：`T = GS_TABLE (1.17×2.5×0.14)`、`height=0.765`、`metric=true` —— 护栏半径 0.035、
     桌沿 0.03、桌腿 0.06 且落到地板、毡面 0.97×2.35、四角菱花去掉（1.7 cm 的角花会糊成噪点）。
4. **删掉盖板**：`GsStep0Environment.tsx` 里的 `GsTableCover` 与它的木纹/法线生成函数（约 120 行）整个删了；
   `TableScene` 现在只有一处 `<Table />`，它再调 `<WorkshopTable>`。这样"桌面尺寸"只剩一处（layout），
   不会出现"桌子和盖板各画一半"。
5. **材质**：米制档从 `meshStandardMaterial` 换成 **`meshPhysicalMaterial`**，`roughness=0.78`、
   `metalness=0`、`specularIntensity=0.18`、`envMapIntensity=0.06` —— 毡面保持哑光，
   且**掠射角下不再出现"桌面右半截发灰的冷镜面"**（第一版验收图里的那层灰就是标准材质 4% F0 的
   Fresnel + PMREM 冷天空；任务要求"别出现镜面反光"）。

## 3. 桌面光毯（lightmap）

### 3.1 怎么生成

`design/gen-table-lightmap.mjs`（**零依赖**：只用 Node 内置 `zlib`，自写 PNG 编码；不需要 canvas/sharp）：

```bash
node design/gen-table-lightmap.mjs                     # 写 public/models/study/tex/table-lightmap.png
node design/gen-table-lightmap.mjs --window 0.7 --fire 0.8 --sigil 0.5   # 调三种光的强度
node design/gen-table-lightmap.mjs --seed 7 --out /tmp/x.png             # 换噪点种子 / 换输出
```

- 尺寸 **1024 × 512**（RGBA8；长轴 = 桌面 2.5 m 方向，一张 texel ≈ 2.4 mm），与桌面长宽比（2.14）匹配。
- 三种光（参数都在脚本顶的 `PARAMS`，可调）：

| 光 | 参数 | 读数（0~255） |
|---|---|---|
| ① 圆窗冷光斑 | center (u .76, v .52)，椭圆半径 (.20, .34)，色 (0.62,0.76,1.0)，strength **0.5** | 池心 **155,160,195** |
| ② 左前壁炉暖光 | center (u 1.04, v -0.10)（远端左角之外），半径 (.78,.95)，色 (1.0,0.44,0.16)，strength **0.6** | 远端左角 **164,81,43** |
| ③ 中央法阵自发光 | 与毡面金线同轴，半径 0.0857 m（= 毡面纹理 150/2048 × 桌宽），strength **0.62** | 桌面中心 **72,58,42** |
| 环境 | farCool 0.06 / nearDark 0.14 | 近端右角 0,0,0 |

- 方向约定（与渲染端必须一致）：canvas **x 0 = 玩家这一端，x 1023 = 圆窗那一端**；
  **y 0 = 桌左（壁炉侧），y 511 = 桌右（书柜侧）**。推导见 `WorkshopTable.Lightmap` 的注释
  （贴图 flipY + 父组绕 y 转 90°）。
- 抖动：每像素 ±1.2/255 的确定噪点（同一 seed 每次同一张），压住 8 bit 渐变的带状。

### 3.2 怎么贴在桌上

- `WorkshopTable` 在毡面上再叠一层 **加色平面**（`planeGeometry [2.3, 0.97]`，绕 y 转 90°，
  `blending: AdditiveBlending`、`depthWrite: false`、`toneMapped: false`），只负责"加光"，
  不盖住毡面的金线与法阵（与"当 map 盖上去"相比保留了毡面的 normal/roughness 贴图）。
- 桌面本体仍是**哑光**：roughness 0.78（要求区间 0.6~0.8）、metalness 0、specularIntensity 0.18。
- 贴图缺失不会让桌子消失：加载失败只在 console 说一句，桌面退回纯毡面（光毯是增强项）。
- PNG 体积 **≈ 0.69 MiB**（1024×512 RGBA + 抖动）；要更小可改 RGB / 降噪，脚本里一处就能改。

## 4. 火与光（方案 A 的核心）

### 4.1 壁炉位置：从"估的点"微调到"看得见的炉膛"

- 上一版 `ANCHOR.fire = (s -3.18, d 4.80, y 0.50)` 是**估的**（炉膛被家具挡住，量不到）。
  米制场景里把火放在那里，验收图里火焰**悬在壁炉右侧的墙上**（截图 `.tmp-gs-table/` 的第一轮）。
- 本版按"允许微调到视觉合理处"移到 **`(s -2.72, d 3.10, y 0.62)`** → 世界 ≈ **(-1.45, -0.24, +0.10)**：
  正对壁炉开口、离桌面左沿 0.87 m、离 NPC 左肩 ~1.9 m。位置仍由 `toSplat/toWorld` 现算，**只改一处**。

### 4.2 三件东西（`HearthFire.tsx`）

1. **点光源**：暖色 `#ff9a4a`、`intensity 7` / `distance 5.5` / `decay 2`（米制 1/d² 衰减）。
   闪烁 = 7.3 Hz 主频 + 2.1 Hz 呼吸 + 23.7 Hz 细抖的**多频正弦叠加**（幅度 22%，不是随机跳变——
   随机跳在低帧率下读成"坏灯"）；炉心位置 ±2.5 cm 轻跳。
2. **火焰动画**：`ShaderMaterial` + 5 层 fbm 噪声（向上卷动 + 低频左右摆），泪滴轮廓 × 噪声阈值，
   颜色从底部暗红 → 橙 → 顶上黄白；**双层**（外焰 0.38×0.55 m + 内焰 0.55 倍）、加色混合、
   绕 y 轴面向相机（只转 y，转 x 会像烧到桌面上）。
3. **假光池**：炉前地面一块 1.5×1.1 m 加色渐变（splat 地板不吃灯 —— 不加这一块，火"照不亮任何东西"），
   炉口再叠一层 2.6 倍大的柔光晕。`renderOrder={20}` 是整个火能看见的前提（见 4.3）。

### 4.3 ★ 光照边界（注释里写死，别以后以为火对墙也生效）

- **light 只照 mesh**：splat 用的是 ShaderMaterial，three 只给"要灯"的材质上传灯光 uniform。
  所以这盏点光只照到 **桌子 / NPC / 卡牌 / 法阵**；**splat 的墙、窗、地板一个像素都不会变亮**。
  "墙也暖一点"不要靠调灯（只会把桌子和人烤过曝），桌面暖靠光毯、地面暖靠假光池。
- **火必须画在 splat 之后**：SparkRenderer 是**透明**材质、`renderOrder=10`；火焰默认 0 会先画，
  然后整片 splat 糊上来。第一轮验收"壁炉里看不见火"就是这个原因（不是位置错、也不是 shader 没跑）。
  火焰 / 内焰 / 炉口光晕 / 地面光池四个网格全部 `renderOrder={20}`（与 `GsStep0Room` 文件头的
  渲染顺序约定一致：网格 0 / splat 10 / 玻璃与光效 20）。

### 4.4 灯组其余部分（米制重调）

| 灯 | 上一版（SCALE 3.2） | 本版（米制） | 为什么 |
|---|---|---|---|
| 月光方向光 | `sun [-2.5,7,-12] / 1.5` | `sun [-1.2,3.2,-6] / 0.9` | 方向光强度与距离无关，但桌面离窗近了 3 倍；0.9 是对着 splat 墙面亮度校的（再高桌面比 splat 亮，接缝显形） |
| 阴影框 | ±13.5 / ±9.5 | ±2.4 / ±1.8，near 0.1 / far 12 | 桌面+人只占 ±2 m；同样 2048² 阴影图每米多 6 倍像素（窗棂影从"糊"变"看得出格子"） |
| 窗面泛光 RectAreaLight | 3×3 / intensity 4 | 0.9×0.9 / intensity 12 | 面积小 11 倍、离得近；按现场观感校（第一版 26 把桌面远半截打爆） |
| NPC 补光 | `[0.8,2.6,7.6] / 0.9` | `[0.4,1.6,3.6] / 0.9` | 方向不变（相机侧顺光），距离按米制收；`?nofill=1` A/B 仍可用 |
| 雾 | [20,70] | [7,22] | 房间纵深 7.96 m；窗前 7 m 不吃雾（否则圆窗被雾压灰） |

## 5. 相机与卡位联动

- **卡牌基尺寸只有一个出处**：`layout.cardLayout()` —— 老场景 1.1×1.65，米制档 **0.28×0.42**。
  `CardMesh / SlotPlate / DeckStack / DeckSpread / MarketFan / DragLayer / FlightCard / DialogTableCards`
  全部读它（写死任何一处都会出现"画的是小米制、落点算的是老尺寸"）。
- **为什么是 0.28**：4 张角色卡一排横跨 4·0.28 + 3·0.015 = **1.165 m ≈ 桌宽 1.17**；
  在 800×363 的真机画幅上每张约 **68×28 px**（与老场景 64×34 同一档），卡面放得下封面 + 卡名，
  也不会"卡比桌子还宽"。0.42 深 = 1.5 倍宽（塔罗牌比例）。
- **5 个卡位 = 桌面上分层**（从 NPC 侧到玩家侧，各层卡深相加不重叠）：

| 层 | 世界坐标 | 尺寸 | 屏幕（852×348 投影算，与截图一致） |
|---|---|---|---|
| 场景位 | (0, **-1.0**) | 0.224×0.336（0.8 档） | y ≈ **48%**（远端、法阵之前） |
| 4 角色位 | x = ±0.4425 / ±0.1475，**z=-0.35** | 0.28×0.42（1.0 档） | y ≈ **57%**、x 33~67% |
| 市场两排 | z = **0.15 / 0.50**，dx 0.27，0.72 档 | 0.202×0.302 | y ≈ 67% / 77% |
| 卡组堆 / 摊开 / 合成法阵 | z ≈ 0.92~1.0（玩家这一侧） | 法阵缩到 0.32 | y ≈ 95~100%（贴画面下缘） |

- **"投影法重算"的落地**：旧的 `TABLE_SLOTS` 是按 22×9 桌面的屏幕百分比量的（角色排 y 44~53.5%），
  米制桌面**长轴换成了 z**，那组比例直接套会算到桌面外。本版改用"桌面分层 + 投影校核"：
  先按卡深排层（上表），再把每格投影回屏幕核对（`GameTableSlots` 每帧写 `SLOT_SCREEN`，
  2D 落点判定读同一份）—— 屏幕读数与上表一致，四张卡都在桌沿以内。
- **对话机位**：`layout.npcCam()` 给米制档一台新的 `GS_NPC_CAM = (0,0.72,1.15) → (0,0.35,-1.55)`
  （老场景的 `NPC_CAM` 是世界 UI 尺度，米制下会落到桌子底下）。`studioStore` 进对话、`TripoNpc`
  的注视基准都改成 `npcCam()`。
- **NPC 站位与身高**：新配置 `GS_MILLTINA_CFG`（`TableScene`）。★ 验收探针量出来一件事：
  `MILLTINA_CFG.scale=3.35` 换算到世界是 **约 3.43 m 高**（模型原点→头骨 1.0236 模型单位 × 3.35），

## 8. 已知风险 / 下一步

1. **splat 桌面残差**：ROLL 纠完残差 std 0.94 cm，网格毡面抬高 2.4 cm；>2.4 cm 的尾部点理论上会
   从毡面透出来。三张验收图里没看到可见穿透，但换资产/重估位姿要重量一次。
2. **对话俯身的幅度没重标定**：`GS_MILLTINA_CFG` 只改了站位与胸物理 rail；`leanSlide`
   （back 0.42 / z 0.08 / y 0.216）还是按老桌沿（4.3 m 远）量的。站姿验收图没问题，
   进对话让她伏桌时要再看一次（这是这一版**唯一没动的旧参数**）。
3. **帧率只有模拟器读数**（宿主机 GPU，ANGLE 桌面显卡），真机帧率仍没量；2M 高斯在手机上要按
   设置页两档 + 角标量。
4. **splat 里的椅子**：近侧/远侧各一把烘死在房间里。NPC 站在远端（椅子在她左边），近侧那把在
   桌面右侧当"前景"，三张图里都读得过去；但玩家绕到桌子另一边看会穿帮。
5. **老场景不受影响**：`sceneLayout()` 在 GS 关着时逐字节返回老布局；桌面组件换了实现但尺寸/材质/机位/
   卡位一个数没动（`WorkshopTable` 的 `metric=false` 分支就是原实现）。GS 失败回退时 `setGsPhase("failed")`
   会把米制标志位翻回 false，桌子/机位/NPC 一起退回老场景。
6. **光毯体积** 0.69 MiB（可改 RGB / 降噪）；**GS 资产**（31 + 8 MiB spz）仍不进仓库。
7. **`gsSceneCam` 是验收钩子**：不写这个 localStorage 键就不存在；生产里没人写 = 完全走 `GS_CAM`。
8. **2.5D / Blender 方向没做**（主人拍板先做 A；2.5D 那套仍在 `app` 工作区未提交，不属于本分支）。

1. **两排是平放不是立牌**：立牌会把中线整条挡住（10.4 末尾那段实测），所以"脸对脸"的读感靠

### 11.2 火：三层 + 柴木发光 + 火星 + 火光变色（`HearthFire.tsx`）

上一版是一层 fbm 噪声 + 一个压扁的内焰（§10.6）。这一版按真实壁炉拆成四件：

**① 三层火焰**（同一张 shader、三组 uniform，`FLAME_LAYERS`）：

| 层 | 相对宽/高 | 上卷速度 | 噪声频率 | 湍流 | alpha | 颜色（底→中→顶） |
|---|---|---|---|---|---|---|
| 外焰 | 1.00 / 1.00 | 0.85 | 2.3 | 1.05 | 0.62 | `#5c1103`→`#ff4d0e`→`#ff9b34` |
| 中焰 | 0.72 / 0.80 | 1.45 | 3.6 | 1.30 | 0.68 | `#9c2406`→`#ff7a14`→`#ffc866` |
| 内焰 | 0.34 / 0.50 | 2.30 | 5.4 | 1.55 | 0.75 | `#ff8a1e`→`#ffd485`→`#fff3d2` |

- **顶部飘动更快**是 shader 里的 `phase = uTime * speed * (1 + 1.8·y²)`：相位随高度加速（真火的
  尖端正本来比根部抖得快），横向摆幅也乘 `y²`（根部钉死、尖端大幅摇曳）。
- **轮廓 = 三条火舌取并集**（`for i in 0..2`，每条的水平位/半宽/高度上限由 `uSeed` 定，帧间不变）。
  一条整片的 teardrop 无论怎么加噪声都读作"一团光"；三条不同高低的舌叠起来才有壁炉的样子。
- **颜色是"底部白热 → 中段橙 → 顶端暗红"**（柴火温度最高的是燃料那一段，火舌尖端先冷却）。
  第一版把它写反了（顶部最白），配合加色混合直接烧成一团白 —— 这是这一节踩得最深的一坑。

**② 柴木发光 + 炭化黑边**（`LOGS` 三根交叉的圆柱 + 专用 shader）：
沿长度的发光是 `pow(along, 1.6)`（接触火焰的中段最亮、两端暗）、朝上的面再压 `1−0.85·up`
（"底部亮、顶部暗"），炭化是"两端 + 上表面"进一段近黑 `#050303`，交界处留一圈暗红余温。
柴木**压在锚点下方**（锚点 = 柴堆上表面，最上面那根的中心 = −0.5·半径），吃深度、进不透明队列。

**③ 火星/余烬**：32 颗 `THREE.Points`，位置/寿命/大小全由 shader 从 `aSeed` 现算（CPU 每帧只写
一个 uTime）：寿命 1.2~3.1 s、向上飘 0.04~0.34 m、左右轻微飘移、头尾淡入淡出。
> ⚠ **这一版最贵的一个坑**：`gl_PointSize` 第一版给到 42~58 —— 那是"视距 1 m 处的**物理**像素"，
> 除以视距之后每颗 200+ px，32 颗软点叠在一起就是**一个白色椭圆**。验收第一轮看到的"过曝的火"
> 其实是它们，不是火焰。改成 7 之后火星才是火星（顺带：那团白色消失之后，火焰的层次才看得见）。

**④ 火光闪烁**：点光强度沿用多频正弦叠加（7.3 / 2.1 / 23.7 Hz，幅度 22%），这一版**颜色跟着强度走**：
`#ff7a2f`（暗）↔ `#ffb066`（亮）线性插值 —— 真实火焰变暗时色温同时下降。

**包围盒（运行期读 `window.__gsAccept.fire`）**：锚点 (−1.949, −0.500, +0.101)，
`x ∈ [−1.999, −1.899]`（柴木厚度）、`y ∈ [−0.630, −0.080]`（柴底 → 火舌顶）、
`z ∈ [−0.049, +0.251]`（外焰 0.30 宽的一半）。炉口内净高 ≈0.55 / 宽 ≈0.60 ⇒ **整团火收在炉膛口内**。

**为什么不用视频贴图**（主人给了 ≤1.5 MB 的口子，我们选纯程序化）：
① 这份火要能随炉膛尺寸/相机距离缩放，而循环贴图分辨率定死（近景要 ~300 px、远景只要 ~40 px）；
② 无缝循环的火焰视频要么买素材、要么离线渲染 —— 仓库里没有可用素材，也不该为一个壁炉角落
   进 1.5 MB 纹理解码预算；③ 程序化的三层 + 火星**天然无缝**（相位永不重置），视频每 N 秒会重播。

### 11.3 人物居中（z +0.50 → −0.03）

- **屏幕右 = 世界 −z**（相机在 +x 看 −x，相机的右手方向 ≈ −z），所以"往右挪"就是 **z 减小**。
  上一版站 z=+0.50，投影出来正好**偏左 0.52 m** —— 就是主人说的"位置偏左"。
- 量法（`window.__gsAccept`）：把她 **hips 骨的世界坐标**与**桌心 (0,0,0)** 各沿"相机右手方向"
  取分量，两者之差就是画面上左右方向折回世界坐标的米数（NDC 是分量除一个与深度成比例的尺度，
  两边乘回来正好约掉，所以这个数就是"在她那个深度上量到的米"，与画幅无关）。
- **读数**：`npcCenter = [−0.790, 0.107, −0.03]`、**`npcOffsetM = 0.012`**（≤ 0.1 ✓）。
  这条式子容许的区间是 z ∈ [−0.13, +0.07]，取 −0.03 是中点：**炉膛在 z≈+0.10**，
  再往 +z 挪让火从她身侧露出来就会重新偏左。
- ⚠ 代价：她站到炉口正前方之后，**正面机位只剩她两侧的缝隙看得到火**（截图 1 里火从她左手边
  露出来一条）。火的三层/火星要在**壁炉近景**（截图 3）里看。

### 11.4 椅子：用 `SplatEdit` 把点云里的椅子裁掉（`GsSplatCull.tsx`）

那把高背雕花椅是**点云里烘死的几何**：没有对象可删、没有材质可关，`SplatMesh` 的 visible
是整块房间的开关。**盖 mesh / 调近裁剪都不行**（会连地板和桌角一起切掉，而且换个机位就穿帮）。
最后用的是 Spark 2.4 自带的编辑通道：

- `SplatEdit({ rgbaBlendMode: "multiply" })` + 若干 `SplatEditSdf({ type: "box", opacity: 0 })`；
  着色器对每个高斯算一次"在不在盒子里"，在的话把它的 rgba **乘** 上 (1,1,1,0) ⇒ alpha 0 ⇒ 不画。
  `softEdge: 0.012` 给盒子边界 1.2 cm 的软过渡（硬切会在边上留半颗高斯的亮边）。
- 组件挂在**场景根**上（不是 SplatMesh 子节点）：`SparkRenderer` 每帧把"祖先里没有 SplatMesh"的
  `SplatEdit` 当**全局编辑**收走，于是盒子直接写**世界坐标**，不用反推 splat 那份落位变换。
- ⚠ 盒子**底不贴地板**（y 下限 −0.72）：留下地板那一片点云，否则椅子底下会出现一块"点云被挖掉"的黑洞。

**盒子是怎么量出来的**（不是估的）：把盒子写进 `localStorage.gsCullBoxes` 之后逐轮缩小，判据是
"正面机位那张图里椅背还在不在"（对同一块像素区取与「椅子在」参考图的平均绝对差 >40 = 没了）。
逐轮落点：`z∈[-2.2,-1.0]` 不动 / `z∈[-1.0,-0.6]` 不动 / **`z∈[-0.4,+0.2]` 没了**；
`x∈[-1.3,-1.0]` 不动 / **`x∈[-0.9,-0.6]` 没了**；y 只到 −0.6 不动、抬到 +0.3 就够。
结论：椅子是**塞在桌子远沿**的（椅背贴着桌沿站），最终盒子
`c = (−0.695, −0.16, −0.215)`、`h = (0.105, 0.56, 0.335)` ⇒ x∈[−0.80,−0.59]、y∈[−0.72,+0.40]、z∈[−0.55,+0.12]。
**只有一把**（`z∈[-1.6,-0.7]` 与 `x∈[-1.3,-1.0]` 两轮都没命中任何东西）。

### 12.2 取景右移：为什么最后是「移轴」而不是转头

**目标**：NPC 身体中心 49.5% → **58%~62%**，桌子中线同样右移，且**桌右沿不出画**。

**先试「把 `GS_CAM.look` 点往右挪」（纯转头），量完否掉**（画布 852×348、fov 50）：

| look 点 z | NPC 身体中心 | 桌右沿（木端板 z=−1.25） |
|---|---|---|
| +0.00（原） | 50.61% | 89.14% |
| +0.25 | 56.50% | 98.95% |
| **+0.30** | **57.7%** | **101.2%（出画）** |
| +0.34（把 NPC 推到 60% 需要的量） | ~60% | ~104% |

纯转头是**角度**平移，靠画面右边的桌右沿走得比人物多 —— 主人两条要求在这个做法下**无解**，不是没调好。
「整体 group 平移 x」也不行：网格桌面会跟 splat 里烘死的那张桌子错开（两端就靠 `GS_TABLE.splatLen` 的木端板盖着），
平移 NPC 又会让炉膛的火偏出她身侧；而且单纯平移（不转 look）不改变构图。

**最后用投影窗口右移**：`camera.setViewOffset(W + 2·δ, H, 0, 0, W, H)`，`δ = round(852×0.09) = 77 px`。
只换投影窗口、不改相机位姿/朝向/焦距 ⇒ 桌子在画面里的尺寸与人物高度**逐像素不变**，画面里所有东西一起右移 77 px。

量出来的数（`window.__gsAccept`，模拟器 852×348）：

- NPC 身体中心（hips 投影）**50.61% → 59.65%**；截图上"亮发+绿裙+肤色 → 最大连通块"量到 **59.75%**（差 0.1%，同一处）；
- 桌右沿（z=−1.25 的木端板）**89.14% → 98.18%**（仍在画内，余 1.8%）；桌左沿 11.8% → 20.8%；
- 生成键铭牌 73.8% → 83.2%（还在画内，离右缘约 5% 余量）。

⚠ **只在设计机位上生效**：验收用的 `gsSceneCam` 覆盖、对话/聚焦/商店机位都不移（`syncGsFrameShift` 的条件里那四个判断）；
⚠ 按真机横向（aspect 2.448）校准：桌面 dev 浏览器（1.75）桌右沿本来就出画（第 2 版起就是这样），这一版在窄窗口里更明显 —— App 锁横屏，只在 dev 出现。

### 12.3 小幅环视 ±6°/±3°（`scene/gsLook.ts`）

- **手势门**：`TableCatcher` 的 `mode()` 在"米制档 + `camera.kind === "default"` + 无 orbit"时返回 `"gsLook"`；
  老场景仍返回 `null`（`SHOW_PLAYER_BODY=false` + `orbit=null` ⇒ 手势门恒 null —— 这就是主人说的"拖拽完全不生效"）。
- **卡牌/铭牌上按下不进入环视**：按下时对 `scene` 做一次 `Raycaster.intersectObjects(scene.children, true)`，
  逐层看 `object.__r3f.eventCount`（R3F 自己的命中筛选就是它）；`userData.noCam` 的**空白桌面拾取面**跳过。
  卡牌 / 铭牌 / NPC / 卡组 / 场景位都挂着 onClick/onPointerDown ⇒ 按在上面走原路，不进入 gsLook；空白桌面与背景（splat 的 `raycastable: false`）才环视。
- **参数**：横向 0.0014 rad/px（75 px ≈ 6°）、纵向 0.0010 rad/px（52 px ≈ 3°）；**硬停 ±6°/±3°**（夹在 `gsLookDrag` 里，撞住不弹）。
- **回中**：松手 750 ms、ease-out 三次曲线（`1-(1-t)^3`），在 `CameraRig` 的每帧里推进（不另起 rAF；面板盖着停帧时回中也跟着停，关掉后从停下的角度接着回）。
- **实测（emulator-5554，CDP 触摸）**：按住拖到底读数 **yaw 6.000° / pitch 3.000°**；松手后 60 ms 采样在 **717 ms** 读到 `|yaw| < 0.05°`（750 ms 曲线，采样粒度 60 ms + CDP 往返）。
- 与卡牌拖拽：卡上按下根本不进 gsLook 分支；`g.current.moved` 仍照旧累计，拖完的 click 不会误触 `unfocus()`。
- 与"转头"不是一套：`cameraOrbit.eyeLook` 是第一人称（还要驱动角色头骨），这一档只转相机；共用一个模块会把状态搅在一起。

### 12.4 工作流小窗 + 波浪切换（`studio/ui/WorkflowWindow.tsx`）

| 项 | 值 |
|---|---|
| 尺寸 | **66% × 68%**（模拟器 864×360 CSS 上 = **570 × 245**），中心 (60%, 44%) —— 主人要的"屏幕 62%~70%、居中偏右"取中段 |
| 壳 | 圆角 `rounded-2xl` + `ring-white/15` + 阴影；遮罩 `bg-black/45 + backdrop-blur-[2px]`；底边停在 78%，右下角 GS 角标（z-9999）刚好露在小窗下面 |
| 打开/关闭 | 圆形 `clip-path: circle()` 从**点击位置**扩散到盖住整个小窗 / 反向收缩；**460 / 420 ms**、`cubic-bezier(0.22,1,0.36,1)`（380~520 内） |
| reduced-motion | `prefers-reduced-motion: reduce` 时不播 clip-path，只 **180 ms** 淡入淡出 |
| 从哪长出来 | 生成键是 3D 网格、不是 DOM：`ComposePad.go` 把 `e.nativeEvent.clientX/Y` 经 `studioStore.flowOrigin` 交给小窗；顶栏 🧩 用按钮中心 |
| 关闭动画 | 不能立刻卸载：小窗自己留 `present`，收缩播完再卸（`gen` 计数作废上一发的 onDone，关一半又开不会把新的卸掉） |
| 画布壳 | `FlowCanvas` 新 `embedded`：不 `createPortal`、不铺 `fixed inset-0`，只留一层 `flex h-full w-full flex-col`；GS 档之外老路径默认 false，一个 class 都没动 |
| 引导 | 小窗里**不自动弹**画布引导（那份说明卡是整屏宽的，在小窗里会横穿到窗外）；顶栏 `?` 仍可手动重看 |

**3D / HUD 在小窗打开时**（主人第 3 条的"不卸载/不空跑"）：

- 3D **从未卸载**（小窗是叠上去的浮层，不是路由切换）；但 `canvasCovered` 让它**停帧**（`frameloop="never"`，与原来全屏画布同一条机制）。
- 实测：小窗开着 1.3 s，`__gsAccept.frames` **delta = 0**（停帧，不空跑）；关掉后 1.3 s **delta = 62**（≈48 fps）。
- HUD 是 `document.body` 上的 DOM 角标（z-9999）—— **一直挂着**，读数冻结在停帧前那一帧；关掉后恢复（45.7 fps）。
- 3D 画面上能看到桌面/人物在遮罩外露出来的部分，所以"底下还有东西"是看得见的。

**★ 联带修的一个既有 bug**（第一次验收才暴露）：停帧 → 恢复后，`TripoNpc` 的 `leanBody/leanArm` 两个 action 会变成
**stopped 但 `time=0 / timeScale=0`**；旧判据 `pinned = ts===0 && !paused && enabled && time<=0.001` 把它当"已钉住"，
于是 mixer 不再写这两条轨道，头骨停在停帧前那一帧 —— 现象是**关掉小窗后铸卡师歪着头/头发盖脸**。
判据补上 `isRunning()` 之后（`TripoNpc` 两处：站姿钉帧 + 头部注视的 `pinnedNow`），恢复时重新 `reset().play()` 钉回站姿。
dev 里 A/B 复现与修复见 `.tmp-accept/`；`window.__tripo.perfActions` 可直接看 action 状态。

### 12.5 验收（模拟器 `emulator-5554`，横屏 852×348 CSS，dpr 2.625）

五张截图都在 `.tmp-accept/`（**不进仓库**）：

| # | 内容 | 文件 | 读数 |
|---|---|---|---|
| 1 | **正面**（设计机位） | `01-front.png` | NPC 身体中心 **59.65%**（截图量 59.75%）· 桌右沿 **98.18%** · `viewOffsetOn true` |
| 2 | **环视到 yaw 硬停**（按住不放） | `02-look-yaw6.png` | `yaw 6.000°` · pitch 0（拖到底） |
| 3 | **小窗打开中**（波浪暂停在 200 ms） | `03-panel-wave-mid.png` | 2 条 WAAPI 动画暂停在 `currentTime=200`；圆形边缘可见 |
| 4 | **小窗完全打开** | `04-panel-open.png` | 面板 **570×245 @ (233,36)**；帧计数 `724 → 724`（1.3 s delta **0**，停帧）；HUD 冻结在 46.7 fps |
| 5 | **关掉小窗回 3D** | `05-back-to-3d.png` | 帧计数 `790 → 852`（1.3 s delta **62** ≈ 48 fps）；HUD 45.7 fps；`npcScreenPct 59.65` / `tableRightPct 98.18` 不变 |

- **截图量法**（NPC 可见身体中心）：亮发（中性高亮）+ 绿裙 + 肤色 → 最大连通块 → bbox 中心；`01` 与 `05` 都是 **59.75%**（同一处，量法可复现）。
- **卡牌上按下不进入环视**（模拟器实测）：从卡组堆的牌面（viewport 335,248）横拖 135 px，`gsLook` 全程 **yaw 0**；
  对照：同一套动作从背景（250,60）横拖 160 px → **yaw 6.000°**（§12.3 的闸门在真机同一条路上成立）。
- **fps 的口径**：模拟器上 fps 随暖机 / 负载在 15~60 之间大幅抖（宿主机 GPU），**不当结论**；
  真正说明"停没停"的是帧计数（delta 0 / delta 62）。HUD 是 DOM 角标，停帧时读数冻结在停帧前那一帧。
- **复现**：`gsStep0Experiment=1` + `gsAcceptDebug=1`（探针）+ `gsPadDebug=1`（生成键暗着也当亮的用）+ `gsFlowDebug=1`（空流水线也开小窗 —— **验收钩子**，生产里没人写这个键）。
  点 3D 生成键用 **CDP `Input.dispatchTouchEvent`**（`adb shell input tap` 打不到 3D 画布，见 §11.7 同一条注）；
  波浪中间态用 `document.getAnimations()` 把两条动画 `pause(); currentTime=200`（不另做慢动作开关）。
- 探针字段（`window.__gsAccept`，写 `gsAcceptDebug=1` 才有）：`npcScreenPct` / `tableRightPct` / `frame { shift, viewOffsetOn, size }` / `gsLook { yaw, pitch, maxYawDeg, maxPitchDeg, returnMs }` / `frames`（帧计数）/ `pad.hitCenterCss`。

### 12.6 这一版的风险 / 下一步

1. **小窗里是完整的画布 UI**（卡 216×158 等固定像素）：570×245 下编辑窗 42% 只有 240 px 宽。这一版只验了**空流水线**；

6. `gsFlowDebug` / `gsPadDebug` / `gsAcceptDebug` 都是验收钩子：生产里没人写 = 完全不存在。
