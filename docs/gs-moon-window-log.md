# 明月窗 + 匹配页穿窗转场（`feat/gs-moon-window`）

> 2026-11-27。工坊（高斯泼溅米制场景）那扇毛玻璃圆窗换成**通透的窗洞 + 窗外一轮明月**；
> 大厅首屏改成**窗景背景**，点「匹配」后镜头穿窗 → 黑屏 → 匹配中，匹配成功/取消/超时回到
> 设计机位。截图与一次性脚本都在 `.tmp-moon/`（**不进仓库**）。
> 基线：`main 7004d746`；分支 `feat/gs-moon-window`。

## 0. 任务与做法一句话

| 要求 | 落地 |
|---|---|
| 去毛玻璃，通透窗洞 + 月亮 | splat 那条毛玻璃**抠不掉**（见 §2），改为在窗洞上盖一层**程序化夜空球 + 月亮盘**（带窗洞视锥裁剪），再补一圈 mesh 窗框/十字棂 |
| 月亮 ≥ 窗洞 80% | 匹配页机位离窗 1.6 m、月亮盘半径 2.29 m（窗外 7 m）⇒ 投影面积 **90.29%**；截图像素法 **85.9%（去掉窗棂）/ 81.8%（含窗棂）**，见 §3.3 |
| 匹配页背景 = 窗景 | 大厅首屏不再铺 `bg-ink` 实底：底板淡出，镜头在窗正前方；模式卡/主键挪到左右两列，窗与月亮居中不被压 |
| 点匹配穿窗 | 1.5 s、easeInCubic 加速、穿窗那一拍开始 0.4 s 黑幕；之后才调 `lobbyStore.chooseMatch` |
| 可中途取消 | 飞行途中「✕ 取消」或安卓返回键：立即把相机按回设计机位（不走缓动）、黑幕淡出、promise 回 `cancelled` → 一发队列请求都不发 |
| 回到设计机位 | 匹配成功 / 取消 / 超时 / 关大厅都走 `leaveMatchPage()`：相机 snap 到 `GS_CAM` (1.6,1.06,0.06)，黑幕淡出 |
| 复用大厅逻辑 | `lobbyStore.findMatch` / 队列 / AI 补位**一行没改**；只在 `ui/Lobby` 的"主键那一下"前插 1.5 s 转场 |

## 1. 视频调研（BV1kzr5B7ESy）

工具取字幕（30 段）+ 6 帧（18/35/55/75/95/110 s）+ 20 条热门评论。结论（**与预期不同，如实记**）：

1. **这条视频不是"明月窗/穿窗"的参考片**，它是一个**单图转 3D 高斯（ML-Sharp）Web 工具**的演示：
   6 帧依次是峡谷、树干、花园、喷泉、树的 splat 场景 + 一个"预设效果"面板 + 一张 Windows 桌面；
   字幕讲的是"拖入图片 → 生成高斯场景 → 左键旋转 / WASD 移动 → 预设效果 → 下载模型"，
   全程**没有窗户、没有月亮、也没有穿过洞口的运镜**。
2. 对本次唯一有用的三条：(a) splat 场景里相机可以自由位移 —— 穿窗 dolly 在技术上成立；
   (b) **splat 的外观（毛玻璃、烘焙光）是烘死在点云里的**，不能换面/重新打光 —— 这正是我们
   不"删玻璃"而"盖天空"的原因；(c) 它把"生成→预览→下载"做成一条链，验收要拍"从外面看回来"的证据。
3. 20 条评论全在讲工具本身（`Preview Mode: Backend not connected`、Mac 怎么跑、CUDA、导入 Blender
   掉材质、VRC 尺寸不符、"单图高斯视角动不了多少"），**没有一条在讨论窗户/月亮/转场**。
4. 所以镜头的**构图与节奏按任务书 + 本仓已有参考资料**（`docs/game-lobby-ui-benchmark.md` 的
   主键位置/动效）定：匹配页 1.6 m 平视月亮、穿窗 1.5 s 加速、穿出后 0.4 s 淡黑 —— 这三个数都是
   按"手机横屏 852×348 画布"实拍调出来的，见 §3、§5。

## 2. 为什么是"盖一层天空"而不是"删掉毛玻璃"

- 这间屋子是 splat（`public/models/study/gs/workshop-step0-1.6.spz`，1.6M 高斯）：训练图里那扇窗
  就是毛玻璃，**亮度/磨砂感已经乘进每个高斯的颜色里**，既不能换材质也不能单独剔除（点云没有"面"）。
- 做法：在窗洞位置放**夜空球 + 月亮盘**，用片元级"窗洞视锥"裁剪（portal discard）只画
  "从相机看穿过窗洞"的方向。splat 的 `transparent / depthWrite=false` ⇒ 天空画在它之后就能盖住
  毛玻璃；桌子 / NPC / 窗框有深度 ⇒ `depthTest` 让天空被它们挡住。
- ★ 窗框 / 窗棂也必须在**透明队列**里（`renderOrder 22/23`）：Spark 的 splat 总在不透明物体之后画，
  放不透明队列的窗框第一版被磨砂亮边整个盖住（截图里只剩两条细弧）。
- ★ 窗洞周围还有一圈**烘死在墙上的磨砂亮边**（点云抠不掉）：用一圈从窗框外缘向内浓、向外渐隐到 0
  的暗色 ring（`SURROUND_FRAG`）压成"窗洞的阴影"；再远的那圈淡蓝光晕当作月光晕留着（风险 §7-1）。

## 3. 明月窗实现

### 3.1 几何（`src/studio/scene/moonGeometry.ts`，全部由 gsStep0 落位常量现算）

| 量 | 值 | 怎么来的 |
|---|---|---|
| 窗心（世界） | **(-0.047, 0.659, -3.630)** | `GS_DAY.window.position` = ANCHOR.win 经落位变换 |
| 窗洞半径 | 0.45 m（直径 0.90） | gsStep0 从点云量出来的 |
| 匹配页机位 | **(-0.047, 0.839, -2.030)**，look 窗心 | 窗心 + 法线×1.6 m、抬高 0.18 m（主人给的范围 1.2~1.8 里取 1.6） |
| 月亮盘 | 窗外 **7 m**、半径 **2.29 m**、与窗面平行 | 圆心落在"匹配页相机→窗心"的延长线上（保证从匹配页看与窗洞**同心**），半径 = `coverRadial(0.95) × 0.45 × 8.6/1.6` |
| 夜空球 | 球心=窗心、半径 45 m | 室内的可见部分 = 窗洞；穿出去之后整屏 |
| 窗框 | 0.45 → 0.58 m 环 + 十字棂（16 mm）+ 交点圆钉 + 4 颗铆钉 | 窗框遮住 splat 的磨砂亮边；十字棂是"这是一扇窗"的读法 |

- 月亮 **不受 fov 影响**：屏幕尺寸只看 `(R/d)` 与窗 `(r/d)`，所以"90% 占窗"在任何横屏宽高比下都成立。
- 月亮盘平面比月盘大 1.45 倍（halo 要露在盘外）；halo 在平面边界前衰减到 0（否则天上会留下方形两道边）。
- 夜空：深蓝紫渐变 + 地平线冷光 + 稀疏星 + 两条低频云带（全程序化，无贴图、不花钱烘）。
- 月亮：三档低频噪声月海 + 两档圆形环形山 + 临边昏暗 + 冷白光晕（第一版用 hash 格子做坑，
  屏幕上是一格一格的方块，已改圆形）。
- 灯光：**删掉原来那盏窗面 `RectAreaLight`（"毛玻璃发光面片"）**，方向光（月光）原样保留；
  窗内 0.85 m 加一盏只照 mesh 的冷点光（`MOON_LIGHT`），比 RectAreaLight 硬、小。

### 3.2 窗洞裁剪（portal discard）

片元里用内建 uniform `cameraPosition` 反推视线：相机在窗内侧时，求视线与窗面交点到窗心的距离，
大于窗洞半径就 `discard`；相机穿出窗面之后（`dot(cam-win, n) ≤ 0`）不裁剪、满天都是天。
三段着色器（夜空 / 月亮 / 石框暗部）共用同一组窗洞 uniform（★ 只能声明一次，重复声明 GLSL 直接
`redefinition`，屏幕上是"月亮整块不画 + 满屏 program not valid"，第一版踩过）。

### 3.3 "月亮占窗 ≥80%"的实测

截图：`.tmp-moon/browser/02-window-moon.png`（852×348 CSS、dpr 2、点「匹配」前把时间轴冻在 0，
UI 收起；窗洞/月盘的屏幕投影由 `__r3fCam` 现算，见 §6 的 `windowInfo()`）。
量法：按投影多边形抠出**窗洞**，在窗洞内按亮度/饱和度分出月亮（`lum>95 且 sat<0.4`）与夜空
（`lum≤95 且 B>R+8`），窗棂/窗框（暗、偏暖）不计入窗洞。叠加图 `09-measure-overlay.png`（不进仓库）。

| 口径 | 值 |
|---|---|
| 月亮盘的投影面积 / 窗洞面积（几何） | **90.29%**（= 0.95²） |
| 月亮像素 / 窗洞开口（去掉窗棂） | **85.87%**（103,942 / 121,041 px） |
| 月亮像素 / 窗洞整圆（含十字棂） | **81.78%**（103,942 / 127,093 px） |
| 夜空（窗洞内剩余） | 16,797 px |
| 窗棂/窗框像素 | 6,052 px |

三条都 ≥80%；最严的一条（含窗棂）余量 1.8%。

## 4. 匹配页 + 穿窗转场

### 4.1 镜头路径（`src/studio/scene/matchCam.ts` + `moonGeometry.ts`）

| 项 | 值 |
|---|---|
| 匹配页机位 | pos **(-0.047, 0.839, -2.030)**，look 窗心 (-0.047, 0.659, -3.630)（俯 6.4°，窗洞正好占画面高 20%~80%） |
| 穿窗方向 | 匹配页机位 → 窗心，单位向量 (0, -0.112, -0.994)（**同一条视线**，转场第 0 帧朝向不跳） |
| 终点 | pos **(-0.047, 0.124, -8.39)**（走过 6.4 m，窗面在 1.6 m 处；离月面还有 2.2 m） |
| 时长 / 缓动 | **1500 ms / easeInCubic**（起步慢、越走越快；t³） |
| 穿窗时刻 | 距离比 1.6/6.4=0.25 ⇒ t=∛0.25=**0.63**（约 0.95 s） |
| 黑幕 | 穿窗那一拍 `veil=1`，CSS `opacity 400ms ease-out`（到飞行结束早已全黑） |
| 兜底 | rAF 被掐住时 `setTimeout(FLY_MS+600)` 照"飞完了"结案（黑幕已全黑，画面无差别） |

### 4.2 状态机与接线

```
idle ──openLobby()──▶ page ──点「匹配 N 人局」──▶ fly ──(t=1)──▶ outside
                                                      │                │
                         ✕取消 / 返回键 ──────────────┘                │ 取消匹配 / 超时 / 匹配到真人
                                                      ▼                ▼
                                                    idle ◀──── covered（超时：相机复位、黑幕留着）
```

- **只在 `ui/Lobby` 接线**：`startPicked()` 里先 `await beginFlyThrough()`，`done` 之后才调
  `lobbyStore.chooseMatch(size)`；`cancelled` 直接 return（**不发 findMatch**）。匹配逻辑零改动。
- **可取消**：`useBackLayer(flying, cancelMatchCine)` 把安卓返回键也接到同一个 handler；
  飞行途中右上角另有「✕ 取消」。取消 = 相机 snap 到 `GS_CAM`、黑幕淡出、首屏 UI 回来。
- **匹配成功/取消/超时/关大厅**：页面层 `ui/MatchCurtain` 盯着 `useGame.state`、`lobby.screen`、
  `lobby.open`，统一 `leaveMatchPage()`（相机 snap 设计机位 + 黑幕 0.4 s 淡出）。
  超时（`note.kind === "queue-timeout"`）走 `coverDesign()`：相机复位，但匹配中那一屏还在 ⇒ 黑幕留着。
- **分层**：3D canvas（z-auto）→ 穿窗黑幕 `MatchCurtain` **z-35**（大厅卸载后靠它淡出）→ 大厅 **z-40**
  （里面还有一层底板 + 黑幕）→ 观战 z-45 / 设置 z-50。
- **画布不停帧**：原来 `canvasCovered` 含 `lobbyOpen`（大厅是铺满的实底）；现在改成
  `lobbyOpen && !gsScene` —— 明月窗这一档大厅要看见 3D、转场要能运镜，老场景照旧停帧。
- **StudioPage 顶栏 / 底部提示条 / 高斯角标**在大厅开着时撤掉：大厅首屏的底板淡出后它们会从
  3D 上面透出来（第一版截图里"▶ 开局"正压在"✕ 返回工坊"上）。
- **UI 摆位**（只在匹配页那一屏变）：左列三张模式卡（一行紧凑版）+ 主键 + 说明；右列「凭码加入」
  （垫一层 `bg-ink/45` 的薄底）。852×348 上左列 ≤288 px、右列 ≥600 px，窗洞在中间
  x≈315~537 px —— **月亮主体一个像素都不被 UI 压住**（截图 01/02 可核）。
- 老场景（GS 关着 / splat 失败）`cinematic=false`：大厅照旧不透明、点主键直接走原流程，一个字节都不变。

### 9.2 问题二：月亮"偏软偏假" → "一眼是月亮"

改了什么（`src/studio/scene/MoonWindow.tsx` 的 `SKY_FRAG` / `MOON_FRAG`，`moonGeometry.ts` 的 `coverRadial`）：

1. **硬边**：`disc = 1 - smoothstep(0.972, 1.0, r)`（2.8% 半径的柔光）→
   `1 - smoothstep(1.0−0.0045, 1.0+0.0045, r)`（约 0.5 px AA）；
   盘外紧贴一条 **1~2 px 亮环**（高斯，中心 r=1.006、半宽 0.01），再往外一层很薄的辉光
   （`exp(-(r−1)*18)`，3% 半径内归零；第一版拖到 1.18 倍）。
2. **月海对比**：噪声窗口 0.38~0.68 → 0.45~0.55（约 ×1.7），并把"高地 / 月海"做成两种底色
   （0.92 vs 0.39 线性），另加一层中频碎边 + 两层细粒；中位亮度压到 ~100/255。
3. **环形山**：三座**固定位置**的坑（暗坑 + 坑沿亮环）+ 少量小麻点；坑底压到 ~70/255。
4. **临边昏暗**：`0.58 + 0.42*sqrt(1−r²)`（边沿 0.58）→ `1 − 0.25*smoothstep(0.30, 1.0, r)`（**边沿 0.75**）。
5. **暗环**：月盘是加色混合，画不出"比夜空更暗"的环 ⇒ 改在**夜空着色器**里乘系数：
   以相机现看的月盘角半径 `atan(uMoonR/距离)` 为 1，从月盘边沿的 **12%** 亮度平滑回到 1.0（`1.09×` 角半径）。
6. **占窗**：`coverRadial 0.95 → 0.905` ⇒ 月盘占窗面积 90.3% → **81.9%**，月盘外径向夜空 5.0% → **9.5%**。

真机截图读数（同一个测法：窗洞/月盘按投影圆取掩膜，图像像素分类 `窗洞内 & 亮度>60 & 饱和<0.5`；
"去掉窗棂"用几何遮罩扣除十字棂）：

| 指标 | 改前 | 改后 | 目标 |
|---|---|---|---|
| 月盘占窗（几何 = 半径比²） | 90.28% | **81.9%**（设计 0.905²；截图投影量 82.0%） | ≥80% ✓ |
| 月盘像素 / 窗洞开口（去窗棂） | 88.41% | **84.75%** | ≥80% ✓ |
| 月盘像素 / 窗洞整圆（含窗棂） | 84.51% | **81.01%** | ≥80% ✓ |
| 盘面中位亮度（255 满） | **136.8** | **98.2** | ~100 ✓ |
| 最暗环形山坑底 | 158.1（旧版无固定坑） | **71.2 / 72.2** | ~70 ✓ |
| 盘面内部对比（标准差，去掉边缘/窗棂） | 32.61 | **59.07（×1.81）** | ×1.6~2.0 ✓ |
| 月盘外夜空暗环（径向宽 / 窗半径） | 4.99% | **9.43%** | 12%（见下） |
| 同上，以月盘半径为 1 | 5.25% | **10.42%** | — |

- **12% 那条为什么取 9.43%**：12% 径向暗环 ⇒ 月盘 = 0.88 窗半径 ⇒ 面积 **77.4%**（像素口径更小），
  与"占窗 ≥80%"的硬指标在几何上互斥（半径每让 1%，面积让 2%）。本轮以 ≥80% 为先，
  把暗环取到 ≥80% 允许的上限附近：0.905 ⇒ 面积 81.9%、暗环 9.43%（月盘半径口径 10.42%）。
  真要 12% 的暗环，就得把"占窗 ≥80%"改成"≥77%"。
- 暗环在画面上看得到：月盘白边之外是一圈压到 12% 的深空，再往窗洞边缘回夜蓝（截图见 §9.3）。
- 帧率：真机（Adreno 829）匹配页 **51.6~60.4 fps**、桌面 43.0 fps（1.60M 高斯）；月亮改动没有加贴图 / 采样，
  只多了几次 `noise` 与一个 `acos`。
