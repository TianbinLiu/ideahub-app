# 卡片职责 V3：背景卡 = 故事背景（纯文字）、风格卡 = 画风 + 运镜、场景卡 = 地点 —— 调研与设计

2026-09-06 调研（主人点名）。三条诉求：① 场景 / 背景 / 风格三种卡的职责要按人的直觉分工；
② 「视频提取卡组」出来的卡不能再写「复刻参考视频」「运镜还原参考视频」这种离了原片就不成立的话，
卡组本身要能复刻原视频的大部分特征；③ 卡面要贴合原片（场景卡就是原片里那个场景，人抠掉）。

**结论先行**：三件都可行，且不动任何跨仓枚举（`card.type` 五个值与 `views[].kind` 三个值一个字不改，
改的只是"同一个值读作什么"，与 2026-08 铸卡分档那次同一路数）。「去人留景」做卡面已用主人自己的
模板视频实测通过（Seedream 4.0 i2i，一张 0.20 元），但对**人物占满画面的近景帧**会留残影，要配一道
"选帧 + 复核"。

## 一、现状（逐处读代码得出，非猜测）

### 1. 三种卡今天各是什么意思

| 卡种 | 代码里的定义（`types.CARD_SLOTS` / `real.ts` 五张表） | 进出片管线的方式 |
|---|---|---|
| 场景卡 scene | 地点：`全景主视图`（空间结构、地貌、建筑轮廓）+ `局部特征` | 卡面当参考图发（绑定句「定场参考…光线天气跟剧情走」）+ 文字「场景卡「名」（简介 24 字）」 |
| 背景卡 background | **氛围底色**：`色光基调`（色调、光比、光线方向）+ `质感特写`；`CARD_COMPOSITION` 明令"不要有明确主体" | **卡面当参考图发**（绑定句「只取色调、光比与光线方向，不要画成物体」）+ 同上短句 |
| 风格卡 style | **画风**：`画风样张`（笔触、线条、上色）+ `笔触特写` | 卡面当参考图发（「只沿用画法」）+ 设定帧开头 `整体画风严格跟随风格卡「名」（简介 24 字）`（`frameArtStyle`）|

同一套读法散在七处：`types.CARD_SLOTS` / `CARD_INFO_LABELS`、`real.ts` 的 `TYPE_LABEL` / `CARD_COMPOSITION` /
`SUBJECT_WORD` / `REF_HINT` / `BIND_HINT`、`NpcDialog.TYPE_HINT`、`mock/ai.ts inferType`（「背景|氛围|天空|光|色调」→ background）、
`docs/api-contract.md` 的 `views[].kind` 表、`docs/backlog.md` 的现状矩阵。⚠ `NpcDialog.TYPE_HINT` 写的风格卡是
「画风与镜头语言的基调」，而管线里**没有任何一处**把风格卡当运镜用 —— 界面说的和模型收到的已经不一致。

⇒ 与主人的直觉相比：**场景卡是对的；背景卡整个错位**（它今天是"色光氛围"，主人要的是"故事背景"）；
**风格卡只做了一半**（只有画风，没有运镜 / 节奏 / 光影）。而背景卡今天承担的"色光氛围"，正是主人心里
风格卡该管的那一半。

### 2. 「视频提取卡组」其实是三条路，主人说的两句话各有出处

| 路 | 入口 | 卡的文字从哪来 | 卡面从哪来 |
|---|---|---|---|
| A. 完成视频 → 本片卡组 | `studioStore.finalizeInner` → `real.deriveDeckCards`（`DECK_MINT`） | 豆包**只读文字**：每段 `plot` + 风格卡名；没看过一帧 | 每张 Seedream **文生图**，只拿成片第一帧当画风参考，且明令「不要照抄参考图的画面内容与构图」 |
| B. 提取模板（经典） | `VideoTemplateExtractor` → `real.extractTemplateFromVideo`（`TEMPLATE_MINT`） | 视觉模型看抽帧；被告知「这段视频的画风要求是：{recipe.styleHint}」，而 styleHint 是导演提示词写的「画面质感与**运镜要求**」 | 同上文生图 |
| C. 圈选提取（V2） | `VideoCardAnnotator`（默认卡组名就叫「视频提取卡组」） | **手填**（缺省「从视频里圈选提取（X卡）」） | 用户圈的原片裁剪（0 token） |

- **「复刻参考视频」「运镜还原参考视频」「3D卡通人偶复刻舞蹈的画面风格，动作还原度高」来自路 A**：
  白模段的 `plot` 是挂卡合成出来的点名长句，骨架第一句就是
  「以参考视频复刻原视频的人物站位、动作、节奏卡点、运动轨迹、队形与运镜」，末句「…都要与参考视频一致」
  （`studio/blockoutPrompt.ts` 425 / 520 行），里面还满是「红色人偶」「白色人偶」。`DECK_MINT` 要求
  「style＝必须恰出一张（总结整片画风）」「background＝恰出一张」，模型只能拿这段话总结 —— 于是风格卡写成
  "人偶复刻舞蹈的画面风格"，运镜卡写成"还原参考视频"。它从头到尾**没看过一帧成片**。
- 路 B 的同型问题：styleHint 本身就是"运镜**要求**"口吻，喂给铸卡后风格卡简介照抄成要求句。
- 「背景卡不要被提取」：路 A、B 的提示词都写死「background＝恰出一张 / 至多一张」，`deriveDeckCards`
  还把 `CARD_TYPES` 全部列为"缺失卡种"点名补齐 —— 只要用户没挂背景卡，AI 必出一张。
- 「卡面不贴合原片」：`mintCards` 对五种卡一律文生图（`imagePrompt` 60 字），参考帧只管画风、不许抄画面，
  所以场景卡画的是"一座像那样的城市"，不是原片那座。

### 3. 「卡组能不能独立复刻原视频」

- 做同款（`flowStore.remakeNodesOf`）抄的是各段 `plot` + 随片卡组，帧一张不带。**白模视频的 plot 就是那段
  「以参考视频复刻…」的点名句，而做同款时 `tpl:null`、根本没有参考视频** —— 这条路对白模成片在语义上是断的。
- 卡片能带走的信息：`name`（8 字）、`summary`（30 字，管线只读前 24 字）、`idLine`（60 字，**管线只对人物卡用整句**，
  `segmentGen.materialText`）、`genPrompt`（只给人看）。运镜、节奏、构图、空间布局在任何一张卡上都没有落脚点。
- 随作品发布的卡组快照（server `BranchVideo.deckCardSchema`）只认 `type/name/summary/cover/tags/idLine/realPerson(+views)`，
  加新字段要三处 zod 一起改（CLAUDE.md 那条坑），所以下面的设计**不加字段**，把话装进已有的 `idLine`。

## 二、设计

### 1. 三种卡的新分工（一张表说清，代码里七处表都按它改）

| 卡种 | 管什么 | 图 | 进管线 | 提取来源 |
|---|---|---|---|---|
| 场景卡 | 视频里的**地点 / 空间 / 舞台**（例：城市夜景街道、带长椅的黑场舞台） | 原片**去人留景**的那一帧（定场帧）；第 2 格可留原片裁剪 | 参考图 + `idLine`（空间结构、地面、背景、光源、时间） | 帧（视觉模型挑最能代表它的一帧） |
| 背景卡 | **故事背景 / 简介**：这条片讲的是什么、发生在什么设定下（纯文字） | 只展示（`role:"display"`，永不进模型）——用成片首帧或标题卡 | **只有文字**：`故事背景：{idLine}`，不当"固定素材设定"、不发图 | **不从画面提取**；来自作者写的剧情 / 简介，或用户手填；没有故事的片子就没有这张卡 |
| 风格卡 | 这条片的**画面风格 + 镜头语言**：画风、材质质感、色调光影（吸收原背景卡的"色光"）、运镜、节奏 —— 像一条可套用的 style preset（「黑暗哥特风」那种） | 原片整帧样张（0 token）；可选 i2i 洗成无人样张 | 参考图（「只沿用画法」不变）+ `idLine` 进设定帧开头与视频提示词 | 帧 + 作者要求；措辞必须独立成立 |

不变的：人物卡、道具卡（道具卡面改成"原片裁剪 + 可选净底重画"，见 §3）；`card.type` 五个值、`views[].kind` 三个值。

### 2. 提取提示词改口（路 A、B 同一份规则）

- 输入改成**看帧**：路 A 今天只读文字，改成也喂帧（成片已转存 Cloudinary，`so_` 抽帧现成：`real.grabViaCloudinary`），
  白模段的点名骨架句（`以参考视频复刻…`、`…与参考视频一致`、`红色人偶=…`）**先剥掉再喂**——它们描述的是白模，不是成片。
- 输出契约：`{type, name, summary, idLine, frameIndex, box?}`。`idLine` 改成"出片句"：只写画面里能看到的事实，
  ≤ 60 字；**禁用词**「参考视频 / 原视频 / 复刻 / 还原 / 参考 / 一致」，并在代码里用正则复核（提示词不可信，
  与 canvasAgent"钱上的闸写在白名单层"同一条纪律）：命中就重写一次，再命中就丢掉那张卡。
- 卡种规则：scene 每个地点一张（给 frameIndex）；style **恰一张**（画风 + 材质 + 色调光影 + 运镜 + 节奏）；
  prop 给 `box`；**不出 background**（故事背景不能从画面推断）；character 沿用现规则。
- 实测（2026-09-06，主人的 907 号模板 3 帧，`doubao-seed-2-1-turbo-260628`，4.4k token）：一次就给出
  风格「定格人偶写实风 / 采用定格动画人偶拍摄，人偶为关节可动素体，暗调光影烘托氛围，镜头有景别切换」、
  场景「夜晚城市街景舞台 / 背景是亮灯的城市摩天楼夜景，地面为深色带白色斑马线」、道具「横条纹长椅」带 box，
  一个禁用词都没出现。⚠ 它描述的是**白模**的风格（人偶定格）——白模模板的风格卡必须从**原片**抽帧，
  分段组有 `group.sourceUrl`，单条白模模板要补一个原片指针（实现时先核 blockoutize 那一跳留没留原片）。

### 3. 卡面贴合原片（三档，按卡种）

| 卡种 | 做法 | 成本 |
|---|---|---|
| 场景 | 视觉模型挑帧 → Seedream 4.0 i2i「去掉所有人物人偶，只保留场景，被遮挡处按周围补全，构图机位色调不变，去水印」 → 视觉模型复核「还有没有人物残留」→ 通过用它，不通过退回**带人的原帧**（诚实，不退回文生图） | 1 张图 + 1 次复核 |
| 道具 | 按 `box` 从原帧裁剪（0 token）；可选 i2i 净底 | 0 或 1 张 |
| 风格 | 整帧样张，直接用（0 token） | 0 |
| 人物 | 沿用圈选提取那套（裁剪 + 可选按方案重绘） | 现状 |
| 背景 | 首帧当展示图（`display`），不出图 | 0 |

实测（同一模板，`doubao-seedream-4-0-250828`，2560×1440，各 19 秒、0.20 元）：
- 远景群舞帧（so_11）：**干净**——城市夜景背板、斑马线地面、机位色调全部保住，人偶与右上角台标一并去掉；
- 长椅近景帧（so_3，两个人偶占满画面）：长椅与黑场保住，但左缘留一块白色残影、中间多一道光带 —— 这就是
  要"挑帧 + 复核 + 退回原帧"的原因，别把它当成一定成功。

### 4. 让卡组自己能复刻原视频

- 三种非人物卡的 `idLine` 都进提示词（今天只有人物卡进），`materialText` 按 人物 > 风格 > 场景 > 道具 > 背景 排
  预算（`VIDEO_PROMPT_MAX` 400 字，8×60 已超，所以超了从背景卡先截）；背景卡以「故事背景：」前缀单独一句，
  不套「固定素材设定，不得改动其外形」那句（对文字说外形是胡话）。
- 风格卡的 `idLine` 同时进 `frameArtStyle`（设定帧开头）与视频提示词（运镜句）——一份文字两处读。
- 做同款：白模成片的 `seg.plot` 改成组稿时**从成片抽帧总结的动作 / 站位 / 镜头描述**（与 §2 同一次视觉调用顺带产出），
  点名骨架句不再随作品发布；这样「同一份剧本 + 卡组」在没有参考视频时也能成立。
- `prepareMaterialRefs`：背景卡不再分配参考图（`allocateRefs` 的 others 循环跳过 background）；`refUsedFlags` 自动跟着变
  （同一实现）。存量的旧背景卡（氛围底色）不迁类型，只是图不再进模型、简介照旧当文字 —— 它们的简介本来就是色光描述，
  当文字仍然成立。`mock/ai.ts` 的三张氛围种子卡（黄昏金 / 雨幕青 / 星野紫）改成风格卡。

### 5. 报价 = 实收（两边一起改）

- 路 A：`deckCardsCost` 今天按 8 张 × 图钱报，改后要加一遍视觉看帧（帧数 × 900）与场景卡的复核调用；图钱只在
  场景卡 i2i 与道具净底时发生，风格 / 背景 / 裁剪道具为 0 —— 上限仍按最贵情形报、按实际结算（`deckCardsSettle` 改成
  按实际出图张数 + 看帧数）。路 B 的 `templateCost/Settle` 同理。
- 服务端结算是按每次方舟调用透传扣费的（`billedForward`），客户端只要报价口径与真实调用序列一致即可，
  不需要改服务端价目。

### 6. 要改的地方（实现清单）

- `types.ts`：`CARD_SLOTS` 的 background / style 读法与 `CARD_INFO_LABELS`；`docs/api-contract.md` 的 `views[].kind` 表同步。
- `ai/real.ts`：`TYPE_LABEL` / `CARD_COMPOSITION` / `SUBJECT_WORD` / `REF_HINT` / `BIND_HINT`；`DECK_MINT` / `VIDEO_MINT` /
  `TEMPLATE_MINT` 改口 + 禁用词复核；`deriveDeckCards` 改成看帧 + 剥骨架；`mintCards` 按卡种走 §3 的三档；
  新增 `sceneCoverFromFrame`（挑帧 → i2i → 复核 → 退回原帧）；`frameArtStyle` 读风格卡 `idLine`；`allocateRefs` 跳过 background。
- `studio/segmentGen.ts materialText`：非人物卡也用 `idLine`，背景卡单句前缀，预算排序。
- `studio/studioStore.ts finalizeInner`：把成片地址与抽帧交给 `deriveDeckCards`；白模段 plot 改成成片描述。
- `studio/ui/NpcDialog.tsx TYPE_HINT`、`components/VideoCardAnnotator.tsx`（背景卡改成"写一段文字"而不是圈矩形）、
  `pages/CustomCardPage.tsx`、`mock/ai.ts`（inferType 词表 + 种子卡）。
- `data/economy.ts`：§5 两组报价 / 结算函数。
- `docs/backlog.md` 现状矩阵、`CLAUDE.md` 约定一条。
- server：不改枚举、不改价目；仅当决定给卡加新字段时才动三处 zod（本设计不加）。
