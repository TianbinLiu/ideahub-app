# 2026-10-30 一次清掉「等主人定」：调研同类 App 后的拍板与落地

> 主人 10-30 原话：「所有 decisions 都由你来在网上调研类似平台 app 来自行决定」。
> 本文是那一轮的**正本**：每条先写同类产品怎么做（出处），再写定了什么、做没做、做在哪。
> 三道闸不变：合服务端 / 官网 PR（= 部署）要「合」，花钱的验证要「花」，发版要「出」。
> 调研由五个只读 agent 各自跑一遍网页（2026-10-30，出处逐条在各节）；拿不准的写「没核到」，不编。

## 一、更新弹窗的说明（2.75 发版后在模拟器上抓到）

**现象**：弹窗里是 2.62 起全部 14 版、约 19,700 字塞在一个小滚动框里，每版中文在前，英文手机上要翻到第二屏。

**同类怎么做**：抖音 / 微信 / 快手 / TikTok / CapCut 的商店页「更新内容」都只写当前一版、20 ~ 170 字（B 站偶有 950 字的运营稿）；
Google Play 与华为应用市场对这段文字的上限都是**每种语言 500 字**（Play：`<en-US>` 分语言各自校验）；
Play In-App Updates API 根本不带说明文字；腾讯 Shiply 的 `clientInfo{title, description}` 是单字符串、没有语言位。
NN/g：What's new 弹窗要「关得掉、以后找得回」（Evernote 的常驻入口被点名表扬）。
来源：各家 App Store 页（2026-10-30 当天看）、[Play Console Help 9859348](https://support.google.com/googleplay/android-developer/answer/9859348)、
[华为 agc-help-releaseapkrpk](https://developer.huawei.com/consumer/cn/doc/app/agc-help-releaseapkrpk-0000001106463276)、
[Shiply Android SDK](https://shiply.tds.qq.com/document/in-app-upgrade/sdk-integration/android-sdk-integration/)、
[NN/g onboarding tutorials](https://www.nngroup.com/articles/onboarding-tutorials/)。

**定**：
1. 清单 `notes` 只写**当前这一版**（中英两节，与从前同形，老 App 照旧能读）；新加 `notesByLang {zh, en}` 与 `history[≤8]`（每版 versionName / versionCode / date / zh / en）。
2. 新 App 弹窗只画**界面语言那一种**（`pickLang`），跳过的几版折起来「还有 N 个版本的更新你没装过」点开才列；设置页「这台设备」多一行**「更新记录」**（NN/g 的「找得回」）。
3. 发版脚本：这一版在 RELEASE_NOTES.md 里没有自己那一节就**当场停**；每种语言超过 500 字只提醒。
4. **强制更新的时点**：方舟 11-24 14:00 下线那一批**不自动迁移生图生视频模型**（方舟公告原文），所以 2.63 以前的包那天起免费档一档都用不了。
   定：11-24 之前最后一次发版带 `--min-version-code=76`（2.64，含 Capacitor 高危修复的那一版；2.63 以前的包不认这一格，拦不到）；
   在它前一版的更新说明里先预告一句（Firebase / Play 的做法：先 flexible 预告、到期再 immediate）。**执行要「出」。**

**做了**（本仓 `decisions-2026-10-30` 分支）：`scripts/release.mjs` 的 `releaseNotesFor`、原生 `AppUpdaterPlugin.check` 透传两格、`data/appUpdate` 的 `notesFor / skippedReleases / releaseHistory`、
`components/UpdateSheet`、`pages/SettingsPage` 的 `ReleaseHistoryRow`。服务端 `withApkBase` 原样展开 body，不用改。

## 三、AI 客服（docs/support-ai-video-research-2026-10-25.md 第四节的 14 件）

同类事实（出处见 agent 报告，摘要）：没有一家客服机器人向用户按问收费；付费聊天 App（星野 / Talkie / Character.ai）都是余额条或每日额度，没有发送键上的角标。
支付宝 / 店小蜜回答里直接给**站内入口**；Zendesk 快捷回复最多 10 个、Material suggestion chips 是对等的、不突出某一个。
店小蜜读订单状态作答；PIPL 第 21 条委托处理 ≠ 第 23 条向第三方提供（锦天城 2022 分析），淘宝 / 抖音隐私政策都把 AI 客服写成委托处理 + 显著提示。
深度合成规定第十七条 / 标识办法第四条：对话类生成要在交互界面显著提示。豆包的举报分类：危害国家安全 / 违法犯罪 / 未成年人 / 危险行为 / 侵权 / 公序良俗 / 恶意行为。
Intercom / Zendesk 都把 App 版本当**静默元数据**带上，不进可见提示。
