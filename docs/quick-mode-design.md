# 快速模式：从一句话到成片的六步流水线（设计稿，2026-11-16）

> 主人原话：简易模式一句话出片之后，再加一个「快速模式」的选项 —— 进去是一个顶部带进度条的新页面，
> 被引导着走完：写想法 → 生成剧本并拆分镜 → 角色定妆（参考图 + 配音）→ 场景卡 → 每个分镜变成
> 工坊里的一个节点、出首帧、用便宜模型出预览样片（不满意就重抽）→ 挑满意的几条升级 1080p →
> 进剪辑、发布、存到本地。

本文只定做法与边界，**没有动代码**。要改的地方按第 7 节的顺序来。

## 0. 它和现有三条路的关系

| 现有 | 干什么 | 快速模式与它的关系 |
| --- | --- | --- |
| 简约模式（`/simple`） | 一句话 → 单段出片 → 剪辑 → 发布 | **入口就在它的「已出片」选项里**（现在只有「去剪辑 / 重新生成」两颗键） |
| 工作流画布（`/flow`） | 多段流水线、方案台、逐段出片 | 快速模式的第 4 步**就把分镜铺成这条流水线**，之后仍可回画布改 |
| 跟着做（A/B/C/D/E/G/I/L） | 铸段窗里的单段做法 | 第 2 步复用「主角定妆」的铸卡能力，第 4 步复用「样片两步」 |

★ 一句话：**快速模式不是第四套出片实现**，它是一条「按顺序把现有积木摆好」的向导。它自己不做钱、
不做门禁、不做取回 —— 全都走各积木已有的唯一实现（铁律六）。

## 1. 六步（与顶部 `StepDots` 一一对应）

| # | 步骤 | 用户做什么 | 系统做什么 | 花什么钱 |
| --- | --- | --- | --- | --- |
| 1 | 想法 | 一段话：讲谁、讲什么、什么调子 | 一次 chat：剧本 → 2~8 段分镜（标题 / 剧情 / 时长 / 景别·运镜·节拍） | 一次 chat（`CHAT_TURN_TOKENS`） |
| 2 | 角色 | 传参考图（或挑已有角色卡），写名字 | 出定妆图成卡、挂上声音样本（配音） | 出图按张（`mintCards` 的实收） |
| 3 | 场景 | 挑创意工坊市场里的公开场景卡，或写一句 / 传一张图生成 | 生成场景卡；不满意可重出（再花一次） | 出图按张 |
| 4 | 预览 | 看着每一段自己抽卡，不满意点「换一条」 | 每段落成一个节点 → 画首帧 → 便宜档（480p「草稿」）出样片 | 每段：首帧图 + 样片视频 |
| 5 | 定稿 | 勾选满意的几条 | 用同一份首帧在 1080p 档上重出（**还原度 99%** = 画面不变、只提清晰度） | 选中的每段：1080p 视频 − 已付的样片？ |
| 6 | 成片 | 去剪辑、发布、存本地 | 组稿 → 剪辑页 → 发布页 | 0 |

★ 第 5 步的「还原度 99%」在实现上就是仓库里已有的**样片两步**（`FlowNode.draftFirst` → `genNode(id, { finalizeDraft: true })`）：
定稿重出时首帧、时长、画幅、参考图都不变，只换生成档位。**不要**写成「重新生成一条更高清的」—— 那会换掉画面。

## 2. 复用清单（一行都不新写）

| 要做的事 | 唯一实现 |
| --- | --- |
| 剧本 → 分镜 | `studio/structuredSkills.runScriptToShots`（门禁 / 扣钱 / 形状检查都在里面） |
| 分镜 → 节点 | `structuredSkills.shotPlanNodes` + `flowStore.seed`（整表换 nodes 的入口，必须走 `components/flow/useApplyTemplate` 的守卫） |
| 角色卡 | `studio/customCardStore`（照片 / 一句话 → AI 写描述 → 铸卡）+ `data/cardVoice`（声音样本） |
| 场景卡 | `data/account.myCards()` 里的 `type === "scene"`；市场公开卡在工坊那一层（`/workshop` 的数据源） |
| 首帧 + 样片 | `flowStore.genNode`（节点的 `draftFirst` 为真时走 480p 草稿档） |
| 定稿 1080p | `flowStore.genNode(id, { finalizeDraft: true })` |
| 抽卡（同一段再来一条） | `flowStore.genNode` 重出（会覆盖本段成片，按现有规则要先问） |
| 组稿 / 剪辑 / 发布 | `hooks/useFlowActions.toCut` → `/cut` → 发布页 |

## 4. 状态形状（草图）

```ts
type QuickStep = "idea" | "cast" | "scene" | "preview" | "final" | "cut";

interface QuickDraft {
  step: QuickStep;
  idea: string;
  plan: ShotPlan | null;        // 剧本 → 分镜的结果（可逐段改后再落）
  castIds: string[];            // 第 2 步定下的角色卡（最多 4 个）
  placeId: string | null;       // 第 3 步的场景卡
  tierDraft: string;            // 第 4 步预览用什么便宜档（默认 480p 草稿）
  tierFinal: string;            // 第 5 步定稿档（1080p 高清 / 电影级）
  pickedNodeIds: string[];      // 第 5 步勾中的段
  busy: boolean;
  err: string;
}
```

★ 状态必须活在 store 里、不活在组件里（与 `songDraftStore` / `effectDraftStore` 同一条理由）：
第 1 步和第 2 步都花钱，抽屉/页面一卸载就丢 = 用户付过钱的剧本没了。

## 5. 钱的规矩（照抄本仓铁律）

- 每一步的按钮上都要有价签，价签**从算真扣的那个表达式里取**（`runScriptToShots` 的价 = `CHAT_TURN_TOKENS`；
  铸卡价 = `mintCards` 的实收；视频价 = `nodeCost` / `segmentCost`）。
- 第 4 步「抽卡」= 重出这一段成片：**会覆盖已经出过的那一条**，按现有规则先摆确认卡（`DeleteSegBtn` 那套问法）。
- 第 5 步只对勾中的段收钱；没勾的原样留着。

## 6. 三个必须想清楚的边界

1. **在途生成时不许换 nodes**：第 3 步之后改写「想法」会触发整表换 nodes，必须走 `canReplaceNodes` 那道闸。
2. **第 4 步不能一次点着全部**：现有规则是「同一时刻只炼一段」（`busy`），所以是逐段排队，进度用一颗胶囊报（`data/jobs`）。
3. **快速模式不进口袋草稿**：它与简约模式同一条规矩（`saveWorkDraft` 挡掉），草稿留给工坊/工作流。

## 7. 落地顺序（每一批都能单独验）

1. **骨架**：路由 + 页面壳 + `StepDots` + store + 入口键（点进去能看见六步、第 1 步能写想法）。
2. **第 1 步**：想法 → 剧本+分镜（真模型），分镜可看、可删段，再进第 2 步。
3. **第 2 步**：挑已有角色卡；「传图做一张」跳 `customCardStore` 那套（复用，不新写）。
4. **第 3 步**：挑场景卡（我的 + 市场公开）；「写一句生成」复用铸卡出图。
5. **第 4 步**：铺节点（`shotPlanNodes` + `seed`）、逐段出首帧与 480p 样片、抽卡。
6. **第 5 步**：勾选 → `finalizeDraft` 定稿。
7. **第 6 步**：`toCut` → 剪辑页；发布与存本地是现有功能，不新写。

## 8. 已拍板（2026-11-16）

1. **预览与定稿是两次生成**：第 4 步用便宜档（480p「草稿」）出样片，第 5 步只对勾中的段按 **1080p（电影级 `ultra`）**
   重出。主人明确接受**画面会变** —— 所以界面文案只说「升级 1080p」，不许说「还原」「一模一样」。
   （仓库里那条「样片两步」只在电影级一档上，且预览也要按电影级计费，与本条的取舍不同。）
