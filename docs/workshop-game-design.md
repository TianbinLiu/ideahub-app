# 工坊 → 游戏：玩法设计（对标崩铁「货币战争」× 金铲铲之战，2026-11-22）

> 主人拍板的方向：把「工坊模式」从"3D 铸卡桌面"改成**一局能玩完的多人对局**——
> 横屏、桌上摆卡、金币买卡、每回合做视频、互相点赞投票、100 血跑到淘汰。
> 本文是调研结论 + 规则定稿草案 + 分阶段落地计划。**先出文档，再按阶段动手。**

---

## 一、调研：两款参照游戏的机制骨架

### 崩坏星穹铁道「货币战争」（自走棋，3 个位面）

- 棋盘界面上**用金币在商店招募角色**，角色按品质分**白/绿/蓝/紫/金（1~5 金币）**；
- 攒 **3 个同名**角色自动升星（1★→3★），**最多上场 10 人**，有前台/后台/前后台三种站位，站位对了激活「角色赋能」；
- **羁绊**：同羁绊人数越多效果越强；**装备**可穿戴到角色上，实战里通常优先给主输出；
- 战斗里未在限定行动值内清完敌人 → **扣小队生命**，生命归零本局结束；
- 桌面是**斜俯视的 3D 场景**，开局镜头从高处俯冲下来（这就是主人要的那段运镜）。

### 金铲铲之战 / TFT（自走棋，回合制）

- 每位玩家 **100 点生命**，每回合固定**基础金币**（通常 5）+ **利息**（存钱每 10 金 +1，上限 5）+ **连胜/连败奖励**（2~5 连各档）；
- 每回合**买卡/上阵/调整站位**，然后与对手配对战斗；输的一方按对手剩余棋子数**扣血**（越到后期扣得越多）；
- **卡池共享**：同费用的卡数量有限，别人拿走就少了；**刷新商店**花 2 金；
- 血量归零淘汰，剩下最后一人（或几人）结束；**多阶段**，每阶段结束有排名与奖励。

### 我们的差异点（关键判断）

自走棋的"战斗"是**棋子对撞**；我们要的是**视频对撞** —— 每回合玩家用手里卡 + 提示词做出一条短片，
全体一起看、互相点赞/投票，按名次扣血。**这是把"战斗回合"替换成"创作回合 + 展映投票"**，
其余经济/血量/卡池逻辑照抄成熟做法（它们已经调平了十几年）。

## 二、规则草案（标 ★ 的是我补的，标 ? 的是要你拍板）

### 2.0 一局的形状

```
开局：选风格卡（3 选 1） → 每位玩家 100 血、初始金币
第 N 回合：
  ① 商店阶段   买卡 / 卖卡 / 换卡（金币）
  ② 创作阶段   把卡拖进虚框 + 写提示词 → 出片（限时几分钟）
  ③ 展映阶段   按当前排名顺序播放全员本回合的视频，播放中可点赞
  ④ 投票阶段   全员看完后给所有视频投票（不能投自己）
  ⑤ 结算阶段   两个排行榜：点赞榜 / 投票榜；综合名次靠后的扣血，血归零淘汰
  直到只剩 2 人（或打满 N 回合）→ 两名胜者
```

### 2.1 卡牌与背包

- 背包**最多 9 张**；**类型上限**：角色卡 ≤ 4、场景卡 ≤ 1、★道具卡 ≤ 4（9 张里剩下的位置）；
- **道具卡只能在右边栏拖到角色卡上**（装备关系，出片时角色带道具）；
- ★卡牌品质沿用自走棋：白/绿/蓝/紫/金 = 1/2/3/4/5 金币，品质越高"画面加成"越强（见 2.4）；
- ★**卖卡**回收 1 金币（同 TFT 的低品质回收规则），已装备道具退回背包；
- ★同名牌的"升星"在创作语境下没有意义，**改为"合成升级"**：3 张同名卡合成 1 张"强化卡"（画面细节/一致性更好），占 1 格 —— ?要不要保留这条。

### 2.2 风格卡（开局 3 选 1，之后锁死）

给玩家 3 张随机风格卡，每张 = **技法的专业名词 × 题材**，例如：

| 示例 | 技法的专业名词 | 题材 |
|---|---|---|
| A | 赛璐璐（Cel-shading）＋三渲二 | 赛博朋克 |
| B | 胶片颗粒 + 浅景深（50mm 定焦） | 九十年代香港霓虹 |
| C | 湿壁画质感 + 高对比伦勃朗光 | 文艺复兴奇幻 |

- 选定后**整局所有出片都带这套风格**（写进每一发的出片提示词前缀）；
- ★玩家只决定"内容"（角色、道具、剧情、镜头），风格这层由卡锁死 —— 这正好对上 updream"风格是选的、不是写的"。

**★ 每张风格卡必须带预览图（2026-11-22 主人点名）**

- 卡面 = 标题（技法名词 + 题材）+ **一张真实样张** + 一行说明（色调 / 材质 / 镜头语言）；
- 样张的生成口径：**同一句话**（例如"雨夜里一个女孩回头"）用不同风格各出一张，玩家一眼就能比较 ——
  这比任何形容词都直观，也是崩铁/原神那种"选卡界面"让人愿意停下来看的原因；
- 样张**离线批量生成、打进包**（`public/styles/<id>.webp`，6~10 套，一局只抽 3 张）：
  对局里毫秒出图、不花任何 token；**绝不在选风格那一步实时生成**（真人真机会等 30 秒以上，还会被审核拦）；
- 选中的样张同时作为**风格样张**进 i2i 链路（我们已有 `风格卡 = 画风 + 材质 + 色调光影 + 镜头语言 + 样张` 这套），
  技法名词仍进提示词前缀，两层一起用。

### 2.3 商店与经济

- 每回合开始时刷新 **5 张**随机卡（★按玩家等级/回合数给品质权重，越到后期高费卡概率越高）；
- 刷新花 **2 金币**；★**锁定**（本回合不自动刷新）免费，给"想买但钱不够"的玩家留一手；
- 每回合固定收入：**基础 5 金** + 利息（每 10 金 +1，上限 5）+ **连胜/连败奖励**（2 连起 +1，5 连 +3）；
- ★回合结束**清空未花金币的利息计算按 TFT 规则**（保留金币才有下回合利息）；
- 钱不够时可以用 **token 换金币**（★我们的特色：一局里允许 1~2 次，把"看广告/充值"的旧逻辑接到游戏里，?要不要）。
- ★**所有人开局都是最低档视频模型**（草稿 / 480p），更好的模型只能靠金币或事件升（见 2.7）——这是本局最核心的"成长线"。

### 2.3b 事件（每两个回合一次，2026-11-22 主人点名）

对标崩铁「货币战争」：**每两个回合结束**（第 2、4、6 回合后）插一次事件，**三选一**，可以拿免费的那一项（相当于"跳过"）。
事件在**展映投票结算之后、下一回合商店之前**出现，所以它影响的是"接下来这半局"。

预算基准：一局 8 回合、每人每回合平均进账 6~9 金（基础+利息+连胜），整局现金流约 50~70 金。
所以**单次事件的开销定在 4~10 金**才有分量，又不至于让人买不起卡。

| 事件（示例） | 选项 A（花钱换成长） | 选项 B（花小钱换这一回合） | 选项 C（免费兜底） |
|---|---|---|---|
| **模型军备** | **8 金：本局视频模型升一档**（草稿→高清） | 5 金：下一回合出片费减半 | 免费：立刻 +4 金 |
| **灵感爆发** | 6 金：下一回合可以出 **2 段** | 3 金：本回合提示词上限 +50% | 免费：随机一张蓝卡 |
| **补给站** | 5 金：**背包某个类型的上限 +1**（角色 4→5） | 3 金：立刻回 15 血 | 免费：免费刷新券 ×2 |

- **模型升级线**（唯一一条，写死在三档上，与档位表同一份价目）：
  - L1 草稿 480p（开局默认，所有人一样）→ L2 高清 720p（8 金）→ L3 电影级 1080p（15 金，且要求 3 连胜才开放购买选项）
  - 升级**整局保留**，并且只作用于"游戏内的生成"，**不动玩家自己的 token 钱包**（游戏券结算，见 §四）
- ★事件卡面也带**小图与一句话收益说明**（同风格卡的规格），别让人读长文；
- ★事件不重复抽：一局里的 3~4 次事件从池子里**不重样**地抽，避免"连着三次模型军备"的尴尬。
- ? 待拍板：事件是**第 2、4、6 回合后**（3 次）还是**第 1、3、5、7 回合后**（4 次）；模型升级要不要允许一直升到 1080p。

### 2.4 创作阶段怎么"玩"

- 桌面中央有 **3 个虚框**（画面槽）：角色槽 / 场景槽 / 道具槽；玩家把卡拖进去，再写一句提示词；
- 出片 = 用【风格卡】+【拖进去的卡】+【提示词】拼成一发生成请求（复用现有 `segmentGen` 契约）；
- ★**卡的品质影响可用参数**：白/绿卡只给 480p 草稿；蓝/紫卡解锁 720p；金卡才能上 1080p —— 把"卡"和"钱/分辨率"绑起来；
- ★时间限制：每回合 **3 分钟**（?可调），超时按"当前已完成的段落"交片；
- ★**同一回合可以出多段**（做一条 9~15 秒的片子，2~3 段），段数由背包里的卡数量决定（每段要一组卡）—— ?这条会不会太重。

### 2.5 展映 / 点赞 / 投票 / 血量

- 展映：按**上一回合的综合排名**倒序播放（落后先放，避免"看完强的就不敢做"的挫败）；
- 播放中任何人可**点赞**（一回合给同一条只能点一次）；
- 看完后**全员投票**（不能投自己，可弃权）；
- ★两个榜：**点赞榜**（热度）与**投票榜**（专业评价）；**胜负按两个榜的名次相加**（并列看投票）—— 这样"讨喜"和"专业"都能赢；
- 扣血：最后一名 **-20**、倒数第二 **-15**、第三 **-10**、其余 **-5**（★人少时按比例缩放）；血量归零淘汰，**最后两人胜出**。

### 2.6 场景与运镜（主人点名要的那段）

- **横屏**，桌子宽度按横屏比例重做（对标「货币战争」的桌面占比）；
- 进入工坊：**镜头从高处俯视 → 推移到近处**（3 秒入场动画，可跳过），与「货币战争」开局一致；
- **删掉用户摄像头的粗糙人偶模型**（原来桌子中央/对面那个占位人形）；
- 桌面上：中央创作区（虚框）、左后"对手"位、前方背包条、右侧道具栏；3D 卡片仍用现有卡面贴图。

### 2.6b 桌面上的节点卡：卡面在首帧 / 尾帧之间淡入淡出（2026-11-22 主人点名）

桌面上的每一张"节点卡"（代表本局某一段视频）**卡面不再是静态封面**：

- 卡面背景 = **这一段的首帧与尾帧交替显示**，两帧之间**淡入淡出**（每帧停留约 2.5 秒、交叉淡入约 0.8 秒，一轮 6 秒左右）；
- 只有一帧时（单帧段 / 还没尾帧）：显示那一帧并做极轻微的推近（Ken Burns），别像一张死图；
- 还没画帧 / 正在生成：暗色占位 + 进度环；出片完成后自动切到"首帧↔尾帧"循环；
- 帧换了（重抽、圈选改帧、转存永久地址）卡面跟着换 —— 读的仍是 `Proposal.firstFrame / lastFrame` 这两个现有字段（`mediaRev` 已经在广播这件事）。

**实现要点**：Three.js 卡面两层贴图 + 一个 `uMix`（自定义 ShaderMaterial，或两张 Plane 叠着调 opacity），
`uMix` 走缓动曲线往返（线性看起来像闪烁）。贴图**限宽 512**、进入可视范围才上传 GPU ——
一局 4 人 × 9 张卡最多 36 张，别把 WebView 的显存吃满。

## 三、技术架构

| 层 | 现状可复用 | 要新做 |
|---|---|---|
| 场景 | `studio/` 下的 3D 桌面（Three.js）+ 卡片模型 | 横屏布局、桌子加宽、入场运镜、删人偶 |
| 卡牌 | `data/account` 卡片库、`Card` 类型、卡面 | 游戏内"手牌/背包"状态机、类型上限校验 |
| 生成 | `flowStore.genNode`（我们刚给它加了出片前首帧确认）、`segmentGen` 契约 | 把"卡+提示词+风格"翻译成 `GenSpec` 的翻译层 |
| 对局 | 无 | **服务端房间协议**：创建/匹配/回合推进/点赞/投票/血量/淘汰 |
| 匹配 | 无 | 匹配界面 UI + 服务端排队（先做"和 AI 陪玩"的单机版） |

★ 联机是最大的一块：**先做单机版（3 个 AI 陪玩）把规则跑通**，再接真实匹配。

## 四、分阶段落地（每阶段都能单独玩/单独验）

| 阶段 | 内容 | 验收 |
|---|---|---|
| **G1 场景**（先做） | 横屏 + 桌子加宽重做 + 删人偶 + 入场运镜 + 背包条/道具栏/虚框的静态布局 | 进工坊能看到横屏桌面、镜头从俯冲冲进来、没有那个人偶 |
| **G2 单机规则** | 金币/商店/买卡/背包上限/换卡/拖拽装备/风格卡 3 选 1，**不接生成**（用占位视频） | 能在桌面买卡、装配、结算金币与连胜 |
| **G3 回合循环** | 创作阶段 → 展映 → 点赞 → 投票 → 双榜 → 扣血 → 淘汰 + **每两回合一次事件（三选一）**，**AI 陪玩** | 完整一局跑完，两名胜者；事件支路走得通 |
| **G4 接生成** | 虚框 + 提示词 → 真出片（首帧确认 → 出片），成本记在谁头上要想清楚 | 一回合真出一条片，进剪辑页可发布 |
| **G5 联机** | 房间/匹配/同步（服务端 ideahub-server 加 game 模块） | 两台手机进同一局，状态同步 |

★ G4 的**成本问题**必须先定：一局 8 回合 × 4 人 = 32 条片子，按现在的定价是天文数字。
建议：游戏内用"游戏券"结算（每日限量），或每回合只出 1 段 480p 草稿（便宜档），
真正想发布再自己升级 —— ?这条要你拍板。

## 五、待你拍板的点（我建议的默认值）

1. 人数：**4 人**（含 AI），帧率/网络都最省事；
2. 回合数上限：**打满 8 回合或剩 2 人结束**；
3. 每回合时长：创作 **3 分钟**，展映+投票 **2 分钟**；
4. 出片段数：**1 段/回合**（先跑通，之后再允许 2~3 段）；
5. 成本结算：**游戏券**（每日免费额度），不直接烧 token 钱包；
6. 卡牌合成升星：**先不做**（自走棋的逻辑搬过来没有"对撞"支撑，容易变成数值游戏）；
7. **事件频次**：默认"第 2、4、6 回合后"共 3 次（8 回合局）；改成"第 1、3、5、7"就是 4 次；
8. **模型升级上限**：默认只能升到 1080p（L3），且 L3 要求 3 连胜才出现购买选项 —— 要不要放开成"花钱就能一直升"；
9. **风格样张**：默认离线批量生成 6~10 套打进包（`public/styles/`），一局抽 3 张；要不要顺带做"每套风格各 2 张（二次元/真人各一）"。

## 七、收尾：打完一局，这一局的片子怎么带走（2026-11-24 晚）

任务原话：「对局打完（最终回合结束 / 淘汰出局）后，询问玩家是否把这一局的片子保存到本地或发布到视频平台。」
落地的是**结束屏上的一块「收尾」区块**，不是结束之后另弹一屏 —— 那一屏已经是"这一局结束了"，
再弹一层是同一个事实说两遍。

### 7.1 三颗键（`src/studio/game/ui/WrapupPanel.tsx`）

| 键 | 做什么 | 不成立时 |
|---|---|---|
| **⬇️ 保存到本地** | 打开保存面板（`ui/WrapupSheet.tsx`）：这一局我交的每一段**真片**逐段下载，进 App 缓存目录 `ideahub-downloads/<game-id>/`；每段存好后有「分享 / 另存为」 | 只有占位片时**这颗键不摆**，改为说「这一段是占位片，没有成片」 |
| **🚀 发布** | 走到现有发布流程：打开「发布去向」面板 →「发布到本站（IdeaHub）」把**这一局最好的那一段**带进 `/publish`（标题 / 封面 / 简介先填好），发布页上还能改 | 同上（没有成片就没有可发的）；平台那一格只有说明与「先保存到本地」，没有假键 |
| **先不存** | 关掉，**不留二次弹**（写进 game store 的 `wrapupClosed`；离开 `/studio` 再回来、去发布页再回来都不会重问） | — |

- **只在 `over` 那一屏出现**：`RoundResultPanel` 有四个正式分支，只有"本机结束 / 联机结束"这两个摆它；
  结算屏（`round-end`）不摆 —— 这一局还要继续打，那时问"要不要留下"是问错了时机。
  `over` 的判据沿用现有那一条（有 winners / 平局 / 本机打满 `rules.MAX_ROUNDS`），本文件不另判。
- 800×363 横屏上这一块是**一行标题 + 一行键**（追加在结束屏里，不新开一屏、不盖住阶段条）。

### 7.2 片子从哪儿来（判据在 `src/studio/game/wrapup.ts`）

| 这一局 | 来源 | 拿不到时 |
|---|---|---|
| 联机局 | 本机**打完那一拍**留下的那一份战绩（`rounds/history` 的缓存：`historyCache.captureOnlineHistory` 在 `useOnlineRounds` 判出结束时存一次；存好会广播，收尾区块跟着重读） | 「还没拿到这一局的片子（服务端的战绩没读到）」+ **再试一次**（重发那一发） |
| 本机局 | 本机战绩（`localHistory`：每期结算收一条，`over` 时落盘） | 「这一局的战绩没存下来，片子也找不回来了」 |

- **绝不拿上一局顶替**：`wrapupPickOf` 的本机那一路直接问 `localHistory.localPickOf`（写失败 / 读到坏数据 /
  `savedAt` 对不上都算 missing），联机那一路按房号找那一段。判据没有第二处实现。
- **占位片不算成片**：`wrapup.wrapupOf` 把 `placeholder` 或"没有 http(s) 地址"的期分到 `placeholderRounds`，
  `clips` 里只剩真片 —— 保存 / 发布两颗键都只按 `clips.length > 0` 出现。
- 「最好的那一段」（发布默认带的那一段）：**名次最靠前**的一期（名次来自 `settlement.ranking` 的位置，
  与这一局判胜负同一把尺）；并列看点赞 + 票，再并列取更早的回合；没进榜的期排最后。

### 7.3 保存走哪条链路（多段怎么处理）

- **走 `data/videoDownload` 那唯一一份实现**，但入口是**窄**的一条：`planClipDownload`（不是
  `planDownload` —— 那一条的入口是已发布作品，还要过 `isMyVideo` / `takedown` / `isShareable` 三道闸，
  对局里的片子根本不是作品）。"能不能存"（`downloadSupport`）、AIGC 标识闸、只认 http(s) 原地址、
  文件名叫什么，四件事全部回到同一个模块的同一批实现上。
- **多段 = 逐段存，不合并**：对局里每回合是一条**独立的短片**（不是一条长片的分段），要合成一条得走
  剪辑页的原生合成器（`VideoMergePlugin`，**只在真机上跑**，还要先有一份剪辑工程）。收尾要的是"把已经有的
  几段原样拿走"，所以用下载队列本来就支持的多目标串行下载：同一个目录、断点续存、逐行进度、逐行失败原因。
  同一个目录下文件名 `AIGC-qimeng-<日期>-<id6>-r03-<url8>.mp4`（`r03` = 第 3 回合，与线性作品的 `01..NN`
  不是同一个数）。
- **结果必须落地**：整批结局走模块自己的 `outcome`（成功说"N 段都存好了"、失败说原因），每一行有自己的
  状态与失败原话，面板还写出**文件落在哪个目录**（`downloadsPathOf`）。不许静默（铁律八）。

### 7.4 发布到 **B 站等平台**：现状与缺口（调研结论）

**结论：App 今天没有"直连平台发布"的能力，所以这一版不摆那颗键。**

- 仓里能做的只有两件事：①**发布到本站**（`/publish` → `POST /api/branch/videos`，见 `docs/api-contract.md`）；
  ②**保存到本地**（`data/videoDownload`，落 App 缓存 + 交给系统分享面板）。`src/` 里**没有任何**
  B 站 / 抖音 / YouTube 的发布接口、OAuth 或 SDK（`scripts/check-game-wrapup.mjs` 有一条断言钉着，
  哪天接上了它会红，提醒把这一节和界面措辞一起改）。
- 要接平台，缺的不是一行代码：
  1. **平台授权**：各家开放平台的"上传"能力都要开发者资质 + OAuth 授权（或客户端 SDK），
     而且个人主体常常办不下来（微信分享那条已经踩过：见 `components/ShareSheet.tsx` 文件头）；
  2. **服务端/第三方的上传通道**：分片上传、断点续传、平台侧转码与审核；本仓约束是"不接新依赖、服务端不改"，
     所以这一版连一条能试水的路都没有；
  3. **合规**：成片带《AIGC 标识办法》要求的标识、发布者要为内容负责 —— 平台侧的标识与本站的那一套
     （`data/aigcLabel`）不是同一个东西，接之前得先定"谁在哪一侧加标识"。
  4. **平台各自的投递规则**（分区、话题、封面比例、时长）是产品口径，不是纯技术对接。
- 所以今天的做法是**「导出成片」+ 引导**：收尾区块的保存面板与「发布去向」面板都写明
  「App 现在没有直连平台的发布能力 —— 先把成片保存到本地，再去平台 App 或浏览器里上传」，
  并且那颗「先保存到本地」是真的能用的键（不是装饰）。
- 真要做直连，建议的顺序：①先只做一家（B 站，创作者最集中）②只做"发出去"、不做数据回收
  ③标识由我们在导出/上传前盖上（与 `AIGC_MARK_POLICY` 同一处口径）。这三条都要**主人拍板**才动手。

### 7.5 怎么验的

- `node scripts/check-game-wrapup.mjs`（`npm run build` 里跑）：**83 条断言** —— 片子来源的两个方向、
  占位片不进 `clips`、首选那一段的三档并列、合成稿的形状（一段 / 封面 / 时长 / 不写 `videoTier`）、
  三颗键的接线、"占位片不摆保存键"、"结束才出现"（结算屏那一支没有）、保存链路只有一份实现、
  失败反馈三处、平台现状（仓里零平台接口 + 缺口在本文档里）。
- 模拟器（`emulator-5554`，800×363 横屏）：本机局打到 `over` 看收尾区块、占位片那一支、
  真片那一支的保存与发布、`先不存` 关掉之后不再出现。真机不碰。
