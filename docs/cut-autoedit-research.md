> **状态：主人 2026-09-30 拍板「就按你建议的做法改」** —— §六 的六件事都按建议项走（见那一节各条后面的「定」）。
> 做到哪了看 §五 末尾的「进度」。
> 缘起：主人看到一条视频「剪映+WorkBuddy 无缝衔接，3 步把 AI 生成的分镜拼成一条成片，新手 10 分钟学会！」，
> 问能不能把我们视频生成流程里**剪辑那一步**优化成类似的体验。
> 本文就是 [`backlog.md`](backlog.md) §2.11.5 说的那份「真要做先单开一份 design doc」。

**结论先行：**

1. 那套玩法的"无缝"= **Agent 替你把剪映的草稿文件写好**。WorkBuddy（腾讯的桌面 AI Agent 工作台）装一个
   `jianying-editor` 之类的 Skill，把「分镜表 + 素材文件夹」翻译成一份剪映草稿：每个分镜一个独立片段按序上轨，
   外加字幕轨、配音轨、BGM 轨、转场；人打开剪映只做精修和导出。
2. **照字面去"接剪映"走不通**：这些工具全部只支持**电脑版**剪映（Skill 的平台表写明手机端不支持），而我们是手机 App；
   草稿格式还得追着剪映的版本修，读回已有草稿在新版上常常不行，自动导出靠 Windows 界面自动化且只对旧版稳（§一 1.2）。
3. **但那个 Agent 干的活，在我们自己的剪辑页里做得到，而且起点比它高**：它最费劲的一步（把生成器吐出来的文件按约定的目录与
   命名整理好、再排上时间线）我们天生就有 —— 组稿那一拍，段落已经按分镜顺序躺在时间轴上了。我们缺的是后面三层：
   **可回改的剪辑工程**、**包装层（字幕 / 配音 / 配乐 / 转场）**、**指挥层（一键成片 / 一句话改）**。
4. 这三层要的引擎能力，手上那套原生合成器（Media3 Transformer 1.11.0）**已经带着**（今天从 jar 里逐个 `javap` 核过，§四）；
   配音要的 TTS 服务端有现成路由，写旁白要的 chat、确认卡、白名单 op 这些样板画布那边都有。
5. 建议分四期（§五）：**P0 剪辑工程化 → P1 包装层 → P2 一键成片 + 对剪辑台说话 → P3（可选）发到剪映继续精修**。
   P0 单独就值得做 —— 它顺带修掉两件今天就存在的事：**裁剪结果离开这一页就丢**、**合并之后不能回去改**。

做完之后我们自己的「3 步」是：① 逐段出片（已有）→ ② 剪辑页点「✨ 一键成片」，确认卡上过一眼旁白稿 / 音色 / 配乐 / 转场和价钱
→ ③ 预览、改两句、「下一步」合成发布。全程在手机上，不换软件、不碰文件。

## 一、这套玩法是怎么跑的

### 1.1 WorkBuddy 是什么

腾讯 CodeBuddy 家族的桌面 AI Agent 工作台（官网口号「AI Agent 办公新范式」）：能读写本机文件、跑脚本，靠 **Skill**
（官方 SkillHub / 社区 ClawHub，对话里丢一个 GitHub 地址就能装）与 MCP 扩能力；内置「内容创作专家团」——
策划 / 文案 / 图片 / 视频生成 / 视频剪辑 / 改编六个 Agent，其中 video-editor 按 **Track 结构**
（视频轨 / 音频轨 / 文字轨 / 特效轨）拼接、加转场与字幕。它本身不是剪辑软件，是"会用工具的人"。

### 1.2 "让 Agent 控制剪映"的三条技术路线

| 路线 | 怎么做 | 代表 | 代价 |
|---|---|---|---|
| **A 写草稿文件**（教程里说的"无缝"就是它） | Skill 用 Python 直接生成剪映的草稿 JSON（`draft_content.json` / `draft_info.json`）：素材表 + 轨道 + 片段（`target_timerange` 时间轴位置 / `source_timerange` 素材截取段 / `speed`）+ 字幕 + 转场 + 关键帧。剪映一打开，草稿列表里就多一条排好的工程 | [`jianying-editor-skill`](https://github.com/luoluoluo22/jianying-editor-skill)（封装 `JyWrapper`，底层 [`pyJianYingDraft`](https://github.com/GuanYixuan/pyJianYingDraft)）；[`cutcli`](https://docs.cutcli.com/) + `capcut-cli` | **只支持电脑版**（Skill 的平台表原文：「手机端剪映｜不支持｜仅面向桌面版草稿工程」，CapCut 国际版同样不支持）；格式要追版本（Skill 1.7 版还在修"5.9+ 导入后报媒体丢失"）；读回已有草稿在新版上常常不行（pyJianYingDraft 原文「新版剪映中的 `draft_content.json` 往往不是可直接读取的明文 JSON」）；自动导出「依赖 Windows UI Automation，在剪映 5.9 或更低版本上最稳」，Mac 上只能手动导出 |
| B 模拟界面操作 | 聚焦窗口、快捷键、截图找按钮再点 | CSDN 那篇"七个单元的流水线" | 慢（作者实测一条口播约 15 分钟）、界面一改就坏、要人盯 |
| C 不经剪映 | Agent 自己用 Track 结构或 ffmpeg 出成片 | WorkBuddy 内置 video-editor；`ffmpeg drawtext` | 出来的是"死视频"：改一句字幕、换一条 BGM 都得整条重来（教程评价直接渲染类工具的原话） |

### 1.3 「AI 分镜 → 成片」那条流水线长什么样

最贴题的是 [`jianying-automation`](https://github.com/zhihe4869/jianying-automation)（"AI 分镜素材 → 可编辑剪映草稿"）：
质检 → 择优 → 去水印 → 裁黑屏 → 超分 → ASR 字幕 → 情绪配乐 → **组装** → 注册索引 → 验收。三条设计值得记：
**每个分镜独立片段进时间线、不 concat 成单条**（人才能逐镜头改）；**配乐按剧情情绪段落布局**；横屏 / 竖屏各一套字幕字号与位置。
分镜结构是靠约定好的目录（`分镜视频/`、`配乐/`、`分镜数据/shots.json`、`字幕/修正版/`）和文件名递给 Agent 的 ——
生成器与剪辑器之间隔着一层文件系统，"无缝"是靠人守约定换来的。

教程里的「3 步」还原出来是：① AI 出的分镜片段按镜号放进文件夹 → ② 对 WorkBuddy 说一句
（例：「用 jianying-editor 把这篇文章做成教程口播视频，高燃 BGM、加字幕、转场和提示音，最后写入剪映草稿并检查轨道」），
它列任务清单逐项办：配音 → 找 BGM → 音效 → 配图 → 写草稿 → 自检轨道 → ③ 打开剪映精修、导出。

### 1.4 剪映自己也在收这个口

2026-09-20 剪映在「AI 新创作发布会」上发布「剪映Hub」：**无限画布 + 多轨道编辑器**合在一个工程里 —— 从一句话 / 一个参考视频 /
一份文档出发，在画布上梳理思路、形成脚本，调即梦、小云雀出图片 / 视频 / 音频素材，**再进多轨道编辑器精修**；
专业版内置 Agent「剪映助手」（对话里一起构思和剪辑，代办素材整理、口播删减、字幕纠错、视频包装），支持自定义 Skills，
手机上的形态叫「小映」。
也就是说"生成器与剪辑器之间靠一个外部 Agent 粘起来"是过渡形态，终局是**生成与剪辑在同一个工程里、中间站着一个 Agent** ——
而且手机上也是这个形态。我们（工坊 / 画布 → 剪辑页）本来就是这个形状，缺的是剪辑页里那个 Agent 和它手上的包装工具。

## 二、它"无缝"在哪（把价值拆开）

1. **分镜自动上轨**：不用手拖，顺序按分镜表。
2. **字幕轨**：文案直接变成对好时间的字幕。
3. **配音轨**：TTS 念文案，与字幕逐句对齐（Skill 里是一个调用：`add_narrated_subtitles`）。
4. **配乐**：按主题 / 情绪从曲库挑，音量配平（一篇实测给的参数：配音 75%、BGM 20%）。
5. **转场 / 标题动画**：按名字检索套用。
6. **一句话驱动**：人说目标，Agent 拆任务、逐项办、最后自检。
7. **产物是可编辑的草稿，不是死视频**：导出之后还能回来改一句字幕再导一次。
8. **可批量 / 可套模板**：克隆一份模板草稿换素材。

## 三、逐项对照

| 能力 | 剪映 + WorkBuddy | 我们今天（`pages/CutPage.tsx`） | 差在哪 |
|---|---|---|---|
| 分镜上轨 | Agent 按约定的目录 / 文件名 / 分镜表排 | ✔ 组稿后各段按分镜顺序各成一个片段（`:264`） | **我们更省事**：分镜是结构化数据，不经过文件 |
| 裁 / 切 / 换序 / 删 | 剪映全套 | ✔ 分割、裁头裁尾、换序、删除（`:468` `:497`） | 结果只活在组件 state 里（`:108`），**离开这一页就丢**（连同还没付钱的圈选、换过的配乐）；没有撤销（`:519` 的注释自己写着） |
| 字幕 | ✔ | ✗ | 整层没有 |
| 配音 | ✔ TTS + 对齐 | ✗（但 TTS 全套现成，见 §四） | 整层没有 |

| 转场 | ✔ | ✗ 全部硬切 | 承接段本来就是接着上一段真实尾帧起拍的，硬切是对的；缺的是**换场**那几处 |

| 一句话驱动 | ✔ | 画布有（`studio/canvasAgent`），**剪辑页没有** | |
| 可回改 | ✔ 草稿常在 | ✗ 合并把 `draft.segments` 换成单段成片（`:964`），已合好的稿子这一页只剩「去发布」（`:106`） | 发布页听出配乐不对，只能回工作流重做一条 |
| 导出 | 人去剪映里点（自动导出只对旧版稳） | ✔ 原生硬件编码 mp4、720P / 1080P、起始画面 AIGC 标识 | **我们更强** |
| 改画面 | 做不到（只能换素材） | ✔ 圈选重拍 | **我们独有** |
| 批量 / 模板 | 克隆草稿换素材 | 做同款 / 模板在生成侧；剪辑侧没有"包装预设" | 以后的事 |

## 四、能不能做到：引擎与后端实查

**原生合成器**（`android/variables.gradle:17` 的 media3 `1.11.0`，从 gradle 缓存里的 aar 解出 `classes.jar` 逐个 `javap`）：

| 要做的事 | 接口（签名已核） | 我们用到哪了 |
|---|---|---|
| 字幕 / 标题 | `TextOverlay.getText(presentationTimeUs)`；`CanvasOverlay.onDraw(Canvas, presentationTimeUs)`（描边字要用它） | AIGC 角标已经在用 `TextOverlay`（`VideoMergePlugin.java:258`）—— 字幕是同一条路 |
| 闪黑 / 淡入淡出 | `RgbMatrix.getMatrix(presentationTimeUs, useHdr)`：矩阵可随时间变 | 没用过 |
| 推近 / 缓动 | `GlMatrixTransformation.getGlMatrixArray(presentationTimeUs)` | 没用过 |
| 变速 | `EditedMediaItem.Builder.setSpeed(SpeedProvider)`（挂在片段这一层，不是单给画面的效果） | 没用过 |
| 配音按时间点摆 | `EditedMediaItemSequence.Builder(Set<Integer> trackTypes)` + `addGap(long)` | 没用过 |
| 多条音轨混合 | `Composition.Builder(List<EditedMediaItemSequence>)` | 已经在用：画面一条 + BGM 一条（`VideoMergePlugin.java:341`），再加一条配音序列 |
| 音量包络 / 淡入淡出 | `GainProcessor` + `DefaultGainProvider.Builder.addFadeAt(...)`（线性 / 等功率两种曲线） | 现在是自写的常数增益 `GainAudioProcessor` |
| 交叉溶解 | **没有现成的"转场"类**；要两条视频序列 + `Composition.Builder.setVideoCompositorSettings`（`getOverlaySettings(inputId, timeUs)` 给透明度） | 实验性，第一版不做 |
| 原生实时预览 | `CompositionPlayer` | 存在，但要在 WebView 上嵌原生画面，第一版不走 |

**后端与样板**：

- **TTS**：`POST /api/tts`（server `routes/tts.routes.js`）—— 登录 + 30 次/分，单次 ≤300 字，回 mp3（24kHz / 64kbps），
  2.0 单音色与 1.0 混音都通，`aigc_metadata` 隐式标识已开；App 侧 `api/support.synthesizeSpeech` 拿回 Blob，
  音色表在 `studio/voices.ts`，声音市场的混音配方也能直接展开进请求体。**现在不向用户收 token**（只给铸卡师 / 客服念台词）。
- **ASR**：`POST /api/asr` 只回 `{ text, durationMs }`，**没有逐句时间戳** —— "识别原声出字幕"还得先改这一跳，放后面。
- **写旁白的那一发 chat**：`arkClient.chatBounded`（上限与超时由调用点给），一次 `CHAT_TURN_TOKENS` = 400。
- **字从哪来**：`VideoSegment.title` / `plot`（组稿时镜头行折在最前，`studioStore.finalizeInner`）/ 时长；情绪节拍在 `ShotSpec.beat`。
  ⚠ `plot` 是"小说式剧情概括"，不是台词也不是旁白 —— 字幕 / 配音的文案要**另写一遍**，不能把 plot 直接贴上去。
- **Agent 样板**：`studio/canvasAgent`（白名单 op + 确认卡 + 认 id 不认下标 + 执行前重问价钱）、`studio/structuredSkills`
  （形状检查 + 确认点 + 截断如实报）、`studio/agentGrammar`（本地句式 + 构建里跑正反例）。剪辑页照搬形状即可。
- **预览**：留在 WebView 里用 DOM 画 —— 字幕是叠层、淡入淡出是 opacity、变速是 `playbackRate`、配音是 `<audio>`，
  与今天预览 BGM 的做法同一条路（`CutPage` 的 `bgmRef`）。

一个约束先摆出来：TTS 路由注释里那条实测「25 字台词 ≈ 49KB」，按 64kbps 折约 6 秒 ≈ **4 字/秒**。
也就是一段 5 秒的片子只放得下 20 字左右的旁白。这是**推算**，动手前要按选定音色实测一遍（数值先量再定）。

## 五、建议的做法（按依赖排）

### P0 剪辑工程化（地基，不带任何 AI）

- 把 `CutPage` 里那几格 state（片段表 / 圈选 / 配乐 / 导出档）收进一份 **`CutProject`**，随 `data/cutSession` 落盘
  （新字段可选、判否定：老剪辑稿没有它就按今天的方式初始化）。
- **凡是长在时间上的东西都挂在片段上**（字幕、配音、转场、变速都记片段内的相对时间）：片段被裁、被挪、被删，它们跟着走。
  今天那条「你动过片段、预置音轨会和画面对不上」的提示（`presetAudioDrift`，`CutPage.tsx:295`）正是声音没挂在片段上的后果，新东西别重演。
- **合并不再吃掉源段**：`CutProject.sources` 留底，合好之后这一页多一颗「↩ 回去改」，改完再合一次（合成不花钱）。
- **撤销 / 重做**（工程是一份可快照的数据之后，这件事是顺手的）。
- **一处 `compileProject(project) → RenderPlan`**（纯函数：绝对时间的片段表 / 字幕表 / 音频事件表 / 淡入淡出表）。
  预览（DOM）与导出（原生）是两个渲染器，规则只许长在这一处（铁律六）；换行也在这里算好再交给原生，别两边各算各的。
- 连带要动的：`cacheSweep.collectReferenced` 得认工程里的新指针（配音 blob）；`MergeOpts` 扩字段后原生与 Web 必须同版发。
- 单段编辑（`segEdit`，从节点卡「编辑本段」进来）**不进工程**：那份稿子的真相在 `flowStore.nodes` 上、本来就不落 `cutSession`
  （`studioStore.persistCutDraft` 现有的规矩），包装层只在整条模式出现。

### P1 包装层（都不靠模型也能用）

- **a 字幕**：每个片段可写几句，DOM 叠层预览，原生 `CanvasOverlay` 烧进画面。样式一份 spec（字高按最短边比例、白字黑边）。
  ⚠ 位置要量：既要让开 AIGC 角标（右下角，起始 2.5 秒），也要让开首页底缘那一摞 UI（CLAUDE.md「底缘 100px 里叠着四样东西」那格
  加标题 / 作者栏）—— 烧进去的字被自家界面盖住是最蠢的一种白做。
- **b 配音**：逐句走 `/api/tts` → Blob 进 idb → **量**时长 → 预览用 `<audio>`，导出时落成本机文件、作为第三条音频序列按 gap 定位。
  一句念不完本段：先提语速（`rate`），还超就标出来让人改短，不悄悄截断。批量合成是长活，要领票（`data/jobs`）并判中途换人（`ownerEpoch`）。
- **c 配乐与配平**：保留本地文件 / 模板原声；补淡入淡出、每段原声的音量与静音、有配音时自动压低配乐
  （第一版用常数配平，起始值参考教程的"配音为主、配乐两成"，**听过再定**；之后再做真正的闪避包络）。
- **d 转场**：只做「闪黑 / 淡入淡出」一种，**默认只加在换场处**。组稿时给 `VideoSegment` 记一位 `carried`（判据就是出片时用的
  `flowStore.nodeCarry`）：承接上一段尾帧起拍的接缝保持硬切 —— 那是同一个镜头在延续，加转场反而把接缝撕开。
  这是文件夹流水线做不到的：它不知道哪两个分镜是连着拍的。

    ⇒ `AGENT_MAX_TOKENS` 600 → 1000；`CUT_OPS_MAX` 12 → 48（24 个片段里「把偶数编号的都静音」正好回 12 条，再多一个片段就只办一半）。
    另补了一句回执：一句话里先切开、再指"切出来的那一半"的编号（模型与人都会这么数）——指不到，但说清是这个原因。
  - **语音合成**（32 句、7 个音色）：
    - 文件**首尾是静的**：头 0.18~0.46 秒、尾 0~0.54 秒（缺省的「知性女声」头 0.45、尾 0.3~0.5）。不切的话声音比字幕晚半秒，

      提一成多语速就念得完）；估第一发要不要提语速改用 `TTS_SPEECH_CPS` = 4.8。六个字的短句慢得多（3.2~4.5，逗号的停顿占大头）。
    - `speech_rate` 只缩有声的那一截：r = 10 / 20 / 30 → 1.09 / 1.20 / 1.28 倍，静音不跟着缩。
    - 这批都是中文音色，念英文每秒 10.7~12.5 个字母 ⇒ 字母的折算 0.3 → 0.4（`LATIN_UNIT`）。英文念得怎么样**没有人听过**。

## 六、要主人拍板的

3. **配音怎么收钱**：TTS 按字符计费是平台的真成本，今天不向用户收。免费 + 限流、还是定一个 token 价（那样两仓价目表要同步）？
   **定：先免费 + 限量**（一段一句、字数按时长封顶；服务端现成的 30 次/分照旧），看成本再定价。
4. **配乐来源**：只留"本地文件 + 模板原声"，还是内置一小批可商用的曲子按情绪分档（要有人去找授权清楚的曲源）？
   **定：先只留本地文件 + 模板原声，不内置曲库。**
5. **字幕烧进画面**：发布之后关不掉、改不了（除非回炉）。接受吗？一键成片默认开不开？**定：接受；一键成片里默认开、确认卡上可关。**
6. **P3 要不要**：给会用剪映的人留一个"带走继续剪"的出口。**定：放最后，真机验过再说。**

## 七、风险与待验证

- **两个渲染器分叉**：预览是 DOM、导出是原生，同一条字幕两边各画一遍。防线是 P0 的 `compileProject` 与"换行在 JS 里算好"。
- **只能装机验**：字幕叠层的时间基准（角标那次核过是成片全局时间轴，裁过头的片段要再核）、音频序列开头就是 gap 行不行、
  三条音轨混合、逐片段的淡入淡出，都要真机跑一条多段稿子。media3 的实验性接口抛错一律要接住并说成人话（合并插件已有的规矩）。
- **`TextOverlay` 空文本必炸**那格坑同样适用于字幕的空档：没有字的时段要画一个空格，不是空串。
- **旁白与时长对不上**：模型写长了、TTS 念慢了，都会溢出本段。靠形状检查 + 实测时长 + 标红，不靠提示词自觉。
- **合规**：合成语音属于生成内容。画面起始标识已覆盖显式那一半；配音进了 mp4 之后 TTS 自带的隐式标识就没了 ——
  与「隐式标识还缺一格」是同一个缺口（`data/aigcLabel` 头部），做配音时一并核。
- **价目**：若配音收费，服务端结算与 `data/economy` 报价要逐条相等（两仓价目表那格坑）。
- **多语言**：新界面文案走 Lingui 并带英文；写旁白的指令冻结中文；英文内容要另挑音色。
