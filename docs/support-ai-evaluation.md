# App「AI 客服」评测报告（2026-09-04）

> 结论先行：在 25 题的客服题库上，**第三轮 25/25 通过**（关键词召回 100%、「禁止承诺」零命中、转人工判定 100%），
> 首句延迟 P50 1.6 s / P95 2.9 s，平均 2.2 句/答。这已经达到市面 AI 客服产品"知识库问答 + 转人工"这一层的水平；
> 数字人呈现（Live2D 看板娘、逐句 TTS、口型/表情同步）属于加分项，但**不是**真人视频数字人（见「差距」一节）。
> 评测环境是本机内存数据库 + 火山方舟 doubao-seed-2.0-mini（关思维链）；线上换成 DeepSeek 后需要用同一套脚本再跑一遍。

## 评的是什么

- 题库：`ideahub-server/tests/fixtures/support-eval.json`，25 题，覆盖费用/退款、取回、额度与充值、平台与安装、账号（注销/恢复/密码/用户名）、
  草稿与数据、生成能力边界（无缝/时长）、内容处置、语音、隐私、明确要人工、知识库外问题、英文、多轮追问。
- 脚本：`ideahub-server/scripts/evalSupport.js`，打真实的 `POST /api/support/chat`（SSE），量四件事：
  1. **准**：每题若干组"至少命中一个"的关键词；
  2. **不乱承诺**：36 条禁止承诺派生出的正则，命中即扣分（认得否定，「不支持提现」不算违规）；
  3. **该转就转**：转人工判定与预期一致（true / false / either）；
  4. **快**：首句（第一条 `sentence` 事件）与整段耗时。
- 运行：`EVAL_BASE_URL=http://127.0.0.1:4000 node scripts/evalSupport.js`；`EVAL_JUDGE=1` 可再加一轮模型裁判。

## 三轮迭代

| 轮次 | 通过 | 关键词召回 | 违规承诺 | 转人工正确 | 首句 P50 / P95 | 主要改动 |
|---|---|---|---|---|---|---|
| 1 | 16/25（64%） | 88% | 5 | 100% | 2.1 s / 7.9 s | 基线：知识库检索 5 节 + 禁止承诺清单 |
| 2 | 18/25（72%）* | 80%* | 2 | 76%* | 2.3 s / 6.2 s | 引号内标点不再切句；`[handoff]` 出现在句中也能识别并剥掉；加「高频问题标准答法」13 条；同义词补时长类 |
| 3 | **25/25（100%）** | **100%** | **0** | **100%** | **1.6 s / 2.9 s** | 评测脚本认否定词、撞 20/分钟限流按 Retry-After 重试；「忘记密码」允许转人工 |

\* 第二轮有 5 题撞上账号限流（20 次/分钟）被计为失败，属于评测脚本问题而非客服问题。

第一轮暴露的真实缺陷（都已修）：
- 小模型面对整节事实会抓错重点：把「取回」答成「等 25.5 分钟」、把「最长 10 秒」答成各档最短时长 → 加一层人工整理的标准答法（市面产品也是"知识库 + FAQ"两层）。
- `[handoff:xxx]` 有三成概率写在某一句开头而不是整段开头 → 服务端在每句剥掉演出标签后再查一次，标记不会被念出来。
- 「忘记密码？」被从问号处切成两句 → 切句器只在引号/括号配平处断句。
- 评测正则把「没法帮你找回原密码」「不支持提现」算成违规 → 否定词识别。

|---|---|---|---|
| 知识库问答准确 | 企业知识库 + FAQ，人工维护 | 从代码事实生成的知识库（706 行）+ 13 条标准答法；25 题 100% | ✅ 达到 |
| 不乱承诺 / 合规话术 | 话术审核、敏感承诺拦截 | 36 条禁止承诺进提示词 + 评测正则回归 | ✅ 达到 |
| 多轮上下文 | 有 | 带最近 12 轮历史，检索用最近两条用户消息（追问「那要多久」也能答 24 小时） | ✅ 达到 |
| 转人工 + 上下文带过去 | 有，且人工能看到机器人对话 | 模型判定五类情形 + 用户随时可点；工单带最近 30 条对话、AI 归纳标题/摘要/分类；管理员收站内通知 + 邮件 | ✅ 达到 |
| 人工回复回到用户 | 同一会话窗口实时 | 站内通知 + 邮件 + 「我的工单」里追加消息（**异步**，非实时） | ⚠️ 部分：没有实时在线客服 |
| 首次响应速度 | 文字 1～2 s | 首句 P50 1.6 s（豆包 mini）；语音再加一次 TTS（约 1 s） | ✅ 达到 |
| 快捷问题 / 引导 | 有 | 首屏 6 条快捷问题 | ✅ 达到 |
| 满意度评价 | 有（👍👎） | 回答完整后字幕下方 👍👎，连问题与回答原文交给服务端；👎 顺手给转人工入口；管理员可按 rating 看差评 | ✅ 达到（2026-09-04 补） |
| 工单查询 / 状态 | 有 | 「我的工单」列表 + 状态 + 追加 | ✅ 达到 |
| 数字人形象 | 多为真人视频数字人（硅基智能 / 百度曦灵）或静态头像 | 自研 Live2D 看板娘：逐句 TTS、口型跟音频包络、表情/动作随情绪标签、呼吸与身体摆动 | ✅ 有，但风格是二次元而非仿真真人 |
| 语音输入 | 部分有 | 输入条左侧「按住说话」→ 服务端转火山录音文件识别（本地用 TTS 生成的 5 秒语音逐字识别正确）→ 识别文本直接发出 | ✅ 达到（2026-09-04 补） |
| 全渠道（微信/网页/电话） | 有 | 只有 App（官网首页的是陪聊看板娘，不接工单） | ⚠️ 单渠道 |

**能达到的**：知识问答质量、合规、转人工与工单闭环、响应速度、数字人演出。
**还差的**：实时人工会话（现在是异步通知 + 邮件）。服务端已给工单留了 `replies` 往来结构，实时会话可以在此之上加轮询/SSE。满意度评价与语音输入已于 2026-09-04 补齐。

## 已知边界（评测覆盖不到的）

- 题库是我们自己写的，25 题只覆盖高频场景；真实用户会问知识库里没有的事，这时模型被要求「说不确定并转人工」（off-kb 题验证了这一行为），但覆盖面需要上线后按真实工单回填。
- 线上模型是 DeepSeek（服务端 `AI_MODEL`），本地评测用的是豆包 2.0 mini；同一套脚本换 `EVAL_BASE_URL` 指向预发即可复测。
- TTS 与口型没有纳入自动评测，靠人工看：本地端到端跑通（官网首页与 App 页都验证过 4/4 句 TTS 200、口型包络非零）。
