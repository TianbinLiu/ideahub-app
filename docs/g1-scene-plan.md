- 场景是**竖屏优先**：`layout.ts` 的注释写死"竖屏可视 x≈±1.55 → 3 张窗口化"，`TABLE = { w: 16, d: 7 }`；

## 1. 删掉玩家那具粗糙模型（最小、最先做）

- 目标物：`TableScene` 里挂的**玩家侧身体/手臂**（`PlayerArms`），不是 NPC（铸卡师要留）。
- 做法：把它的挂载点收进一个 `SHOW_PLAYER_BODY = false` 常量后面（先留代码、关显示），
  确认没有别处读它的骨骼/眼位之后再删文件。
- ⚠ **先查依赖**：`cameraOrbit.playerEye()` 可能用 `PLAYER_HEAD`；删模型后眼位要改成固定机位
  （直接用 `DEFAULT_CAM` 或 G1 的新机位），否则相机求值拿到空对象会黑屏。
- 验收：进工坊看不到那具人偶；相机不再跟着一个不存在的头走。

> **落地记录（2026-11-22）**：已摘 —— 开关在 `layout.SHOW_PLAYER_BODY`（改回 true 即整条回滚）。
> 相机兜底机位用 **`DEFAULT_CAM`**（俯视那台，本来就是"模型未加载完"的兜底）。
> ⚠ 试过 `NPC_CAM` 但不合用：它在 z=2.45，而卡组堆 / 展开排 / 桌面卡位都在 z=2.75 ——
> 会落到相机**背后**，而 3D 桌面上的卡组堆是 `openDeckView` 的唯一入口（点不到就开不了卡组窗）。
> 这条留给第 4 步的新机位一起解决（§4 的落点比 `DEFAULT_CAM` 靠后、能看全铸卡师）。
> 摘模型时还清出了三处"别处依赖玩家"：`PlayerScreenAnchor`（换形象按钮的头侧锚点）、
> `AvatarSwapButton`、以及 `openDeckView` 的第三人称滑梯（`DECK_CAM` + `orbit:"player"`）；
> 三处都走同一个开关，`PLAYER_HEAD / PLAYER_TORSO / playerEye` 随之不再被写入（相机也不再读）。

## 2. 横屏

两条路，**建议先走 A**：

- **A. 应用内锁横屏**（真横屏）：进 `/studio` 时调 Capacitor 的屏幕方向插件锁 `landscape`，退出解锁；
  3D 画布按 `window.innerWidth > innerHeight` 重算 aspect；UI 用宽布局（左：背包条；中：桌面；右：道具栏）。
  - 要先确认原生侧有没有 orientation 插件（没有就得加一个，`@capacitor/screen-orientation`）。
- **B. 伪横屏**（CSS 旋转 90°）：不推荐 —— 手势、拖拽层、WebView 的触摸坐标全要对齐旋转，
  坑比 A 多得多。

> **落地记录（2026-11-22，第 2 步）**：走的是 **A（真横屏，原生锁）** ——
> `@capacitor/screen-orientation@8.0.1` **本来就在 package.json 里**，且 `android/` 的
> `capacitor.plugins.json` / `capacitor.settings.gradle` / `app/capacitor.build.gradle` 三处都已注册
> （2026-11-22 查实），所以**不需要新装插件、不需要 `cap sync`**，只改了 Web 侧的那一个主人：
> `hooks/useOrientationLock` 把 `/studio` 从"放开方向（`unlock()`）"换成"锁 `landscape`"，
> 出工坊照旧锁回 `portrait`。浏览器（`Capacitor.isNativePlatform()` 为假）不碰方向 ——
> `npm run dev` 里把窗口拖成横的，宽布局自己按 `(orientation: landscape)`（`hooks/useIsLandscape`）切。
>
> · **aspect**：画布尺寸/aspect 本来就跟着**容器**走（r3f 9.6.1 用 react-use-measure 量容器 →
>   `updateCamera` 里 `camera.aspect = w/h` + `updateProjectionMatrix`），所以这一环不用写代码；
>   第 2 步只把画布与浮层收进中间那一层「舞台」div，让两条常驻条**占宽**而不是盖在画布上。
> · **默认机位**：横屏用 `layout.LAND_CAM`（§4 的落点，微调过：卡组堆不能贴底），竖屏窗口退回
>   `DEFAULT_CAM` —— 判据在 `layout.defaultCamFor(aspect)` 一处，取景数据写在那条常量的注释里。
> · **宽布局壳**：`studio/ui/SceneRails.tsx`，左"卡组"（翻开 / 摊开）、右"市场"（逛 / 收起）。
>   两个键都只是在调桌上已有的 action（`openDeckView` / `toggleSpread` / `openMarket` / `closeMarket`），
>   不新增玩法；道具栏留给 G2（那时才有买卡/装备），**不摆点不动的假面板**。
> · ⚠ 已知：工作流画布的「⟳ 转横屏 / ↩ 回竖屏」键走同一个主人，工坊里已是横屏，「回竖屏」那一半
>   在工坊里没有效果（`/flow` 那一页照旧有效）。要给它真正的竖屏权得把 `requestLandscape` 做成三态，
>   留给后面一并处理。

## 4. 开场运镜（俯冲 → 近处）

- 位置：`TableScene` 挂载后 **2.6 秒**的一次性动画（可点屏幕跳过）；
- 关键帧（横屏机位）：
  - 起点：`pos [0, 18, -6]`（高处俯视，看得见整张桌子与四把椅子）
  - 终点：`pos [0, 4.2, 6.2]`、`look [0, 0.2, -1.2]`（接近现在 `NPC_CAM` 的对坐高度）
  - 缓动：`easeOutCubic`，前 30% 慢、中段快、末尾稳；
- ⚠ 与 `cameraOrbit` 互斥：动画期间**暂停** orbit 的同步（否则鼠标/陀螺仪把镜头抢回去），
  结束后 `syncOrbitFromCamera()` 一次，把手感交给原来的控制；
- 验收：进工坊像「货币战争」那样从高处冲下来，落定后可以继续用原来的拖拽/缩放。

> **落地记录（2026-11-22，第 4 步）**：整段演出只在 **`src/studio/scene/introCam.ts`** 里定义，
> `CameraRig` 每帧只问一次位姿（不新增 React 状态，rAF 里不造 state）。
>
> - **终点** = `layout.defaultCamFor(aspect)` —— 横屏 `LAND_CAM`、竖屏 `DEFAULT_CAM`，**每帧现算**
>   （播放途中转屏 / 常驻条改宽度也落在现在这一台上）。
> - **起点按 aspect 分**（施工单只写了横屏那组）：
>   · 横屏 `[0,18,-6]` / `[0,0.4,-2]`（施工单原值。按 fov 50、aspect 1.204 量：卡组堆 x 58.3% /
>     摊开排 40.5~56.7% / 节点链两端 37.1~62.9% / 铸卡师头顶 y 62.9%，整张桌子在画面里）；
>   · 竖屏 `[0,17.6,5.2]` / `[0,0,0.25]` —— 兜底机位 `[0,9.8,3.0]` 沿自己的视线**后退 ≈1.8 倍**，
>     同一个构图只拉远：卡组堆从终点的 x 12.6% 退到 30.0%、节点链 24.3~75.7%（终点最右 97.4%）。
>     两种 aspect **不能共用一个起点**的理由（终点机位朝向就不同 + 竖屏窄）写在该文件头。
> - **时长/缓动**：2.6 秒（施工单写 3 秒，主人点名 2.6）+ `easeOutCubic`。施工单那句"前 30% 慢"是
>   `easeInOutCubic` 的形状，和点名的 `easeOutCubic` 不是一回事 —— 按点名落地，没有把两条揉一起。
> - **可跳过**：`CameraRig` 里一个**常驻**的 window 捕获阶段监听（`pointerdown` / `wheel`）→
>   `skipIntroCam()` 把进度置 1，下一帧就落在终点。只跳运镜、**不吞那一下点击**（手指底下的卡 / 按钮照旧收到）。
> - **与 orbit 互斥**：运镜那一帧在 `CameraRig` 里**提前 return**——轨道分支、卡组滑梯、默认机位缓动全轮不到，
>   `syncOrbitFromCamera` 一次都不调；只在最后一帧（含被跳过的那一帧）调一次，把手感交回轨道
>   （`RIG_LOOK` 同步跟着走，否则收工第一帧镜头会先看歪一下）。
> - **只播一次**：模块级单例（不落盘）；"演过了"这条记忆在**第一帧**里落（不是在 `useEffect` 里）——
>   dev 的 StrictMode 是"挂-卸-挂"两次 effect，放那里会被吃掉、开场运镜永远不播。
>   `prefers-reduced-motion: reduce` 直接不播（镜头本来就停在落点机位）；切路由时 `abandonIntroCam()` 收尾，
>   避免"加载层还盖着就退出"之后再进来永远停在高处。
> - **从哪一拍开始走**：加载层撤掉时（`StudioLoader` 的 `gone`）才 `revealIntroCam()`，之前一直停在起点。
>   挂载即开走的话，最短 0.9 秒 + 0.5 秒淡出全盖在加载层底下，用户看见桌面时俯冲已走完一半。
> - 验收：`npm run build` 全绿；真机（3C15CJ00C8V00000）进工坊截两张（+0.3s 高空俯视 / +3s 落点机位），
>   动画期间点一下直接落定、之后拖拽缩放照旧。

### 3. 新机位与理由

```ts
LAND_CAM = { pos: [0, 3.9, 7.4], look: [0, 0.2, 1.0] }   // 俯角 30.0°
```

- **俯角 30.0°**（`atan((3.9−0.2)/(7.4−1.0))`，改前 23.7°）—— 参照图要的 30~40° 里取**下沿**：
  俯角越大，桌面近半段压得越扁、卡位越往下掉，而底部栏 56.5% 是硬线；
- **相机高 3.9 / 到桌心水平距 7.4（斜距 8.36）**（改前 3.4 / 7.4，斜距 8.96）；
- 量的是 **1372×785（aspect 1.748，桌面窗口扣掉 p-1.5）** 与 **788×351（aspect 2.245，真机）**；
  **y 百分比与 aspect 无关**（垂直 fov 固定 50°），x 才随画幅变。

### 5. 为什么卡位要往桌子里挪 1.25 个单位（z 1.7 → 0.45）

这一条不是审美，是**相机这一族里没有解**推出来的：

| 相机高（俯角 30.0°、近边都钉在 96.3%） | 铸卡师头顶（窗口） | 角色位 z=1.7 的底沿（窗口） | 结论 |
|---|---|---|---|
| 3.0 | **4.8%** | 58.4% | 头顶进系统状态栏（被切） |
| 3.4（改前的高度） | 8.7% | 61.3% | 头顶压着状态栏 11.3% |
| **3.9（选它）** | **13.0%** | 64.4% | 头顶过了，但卡位仍被底部栏（56.5%）压住 |
| 4.6 | 18.5% | 67.8% | 卡位更往下 |

也就是说：**压低相机 ⇒ 铸卡师的头顶被状态栏切；抬高相机 ⇒ 卡位被底部栏压住**，
而 z=1.7 那排在"整张桌子都看得见"的构图里永远落在 56% 以下。所以卡位自己往桌子里挪到 z=0.45：
(0.45+4.5)/9 = **55%** 板面深度 —— 参照图那排"自己人"在板面 53% 处，构图反而更像参照图。
