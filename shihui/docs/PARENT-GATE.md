# 家长门与账号体系设计（MVP-2）

> 2026-08-13。v2：吸收 30-agent 三镜头设计评审的 18 条确认意见（合规/儿童体验/安全工程）。
> 合规背景见 [IDEA-REVIEW.md](IDEA-REVIEW.md)「合规清单」与「账号体系」。

## 一句话形状

**账号主体永远是家长**（手机号注册），孩子是账号下的档案（可多娃）。
**不满 14 岁儿童的全部个人信息都是敏感个人信息**（PIPL 第 28 条）——昵称、年龄段、
作品、学习记录、声音全在内，不只声音；声音的**公开**在此之上再加逐次确认。
同意义务挂在**首次采集**，不在首次发布：跟读识别从第一次开麦就在采集孩子的声音。

## 威胁模型（先说诚实话）

- 本地阶段的 PIN 防的是**孩子误操作**，不是攻击者——4-6 位 PIN 挡不住穷举，这是儿童锁。
- **共享设备是常态不是边角**：孩子拿着家长手机时，短信验证同样不是边界。所以真正的
  兜底是「事后可见 + 事后可撤」：审计日志让家长看见发生过什么，下架/删除让一切可逆。
- **孩子记住 PIN 之后**：本地无解（改 PIN 是唯一对策，家长中心一键可改）；服务端阶段
  增加异常信号提醒（如深夜发布、高频发布推送家长通知）。「逐次确认」的可信度靠
  含语音发布**永不豁免 PIN** 来保（见免重验规则）。
- 安全边界最终在服务端：发布/支付由服务端校验，本地门只是把"需要大人"做进交互。

## 数据模型

```ts
interface Guardian {
  pinHash: string        // SHA-256(salt + pin)：不为防穷举，为不以明文躺在 localStorage
  pinSalt: string
  createdAt: number
  consentVersion: string // 签署的确认书版本；文案改版必须升版本重签
}

interface ChildProfile {
  id: string
  nickname: string       // 昵称即可，不收真名/生日/学校（最小必要）
  ageBand: "≤6" | "7-9" | "10-12" | "13+"  // 一律按不满 14 岁的最严标准处理
}

/** append-only 审计日志。要能当证据：归属到孩子、覆盖取得与处置两侧 */
interface ConsentRecord {
  at: number
  action: "guardian-setup" | "voice-capture" | "publish" | "publish-voice"
        | "share" | "pin-change" | "reset"   // 服务端阶段再加 data-delete / data-export
  detail: string
  childId?: string       // 多娃归属（骨架单档案期 = 当前档案）
  consentVersion: string // 服务端阶段升级为逐条文案快照（textVersion）
}
```

**审计日志的留存**（评审确认）：本地阶段「删除全部数据」按用户意志全清（这是他的设备）；
**服务端阶段同意与删除处理记录基于法定义务单独留存**（设明确留存期，脱离用户数据删除范围），
否则应监管取证时拿不出同意证据。

## 门禁矩阵（唯一权威表）

| 动作 | 门 | 免重验 | 附加确认 |
|---|---|---|---|
| 首次建档（=注册） | 设 PIN + 签确认书 | — | 确认书为**独立单独同意页**，逐条勾选 |
| **首次启用麦克风**（跟读/录音） | **轻量告知同意页，不设 PIN** | — | 明示用途/是否留存/拒绝后果；拒绝走「我念完了」手动放行，学习无损 |
| 发布作品（无语音） | PIN | ✅ 10 分钟 | 文案明示「将公开孩子的昵称与作品」+ **产物强制携带 AI 生成标识**（显式角标/片尾 + 元数据，非可选项） |
| 发布作品（含朗诵） | PIN，**永不豁免** | ❌ | 同上 + 逐次勾选「同意公开孩子的声音」，默认不勾——豁免了 PIN 的勾选可能是孩子勾的 |
| 分享 / 导出（无语音） | PIN | ✅ 10 分钟 | 产物强制携带 AI 生成标识 |
| 分享 / 导出（**含朗诵音频的媒体**） | PIN，永不豁免 | ❌ | 逐次语音确认——导出的边界比广场更失控，义务不比发布轻 |
| 购买积分 / 订阅 | PIN + 支付渠道验证 + 单日限额 | ❌ | 显示价格与本月累计 |
| 家长中心 / 改 PIN / 改保护设置 | PIN，**永不豁免** | ❌ | 免重验窗口内孩子可横向改设置（评审 high），一律每次验 |
| 删除孩子自己的草稿/作品 | 不挂门 | — | 孩子对自己创作有处置权；多娃阶段删除限定在当前孩子档案内（防兄妹互删） |
| 学习、创作、浏览广场 | 不挂门 | — | 核心体验零摩擦 |
| 云端草稿同步（服务端阶段） | 含音频的内容**过采集同意后**才可上传 | — | 别让"同步"变成门前上传的后门 |

## 门的交互

1. **预期管理**：创作首页与完成页就有小字「发布时需要家长确认」——门不该在孩子最兴奋的
   发布瞬间才第一次出现。
2. **家长不在场的出路**（评审 high）：门的取消按钮是「先存着，等家长有空再发」——作品
   回到「我的」草稿列表，随时可重新走发布。孩子的成品永远不会因为家长不在而消失。
3. 未建档：设 PIN → 确认书**独立同意页**逐条勾选（最低告知清单见下）→ 建档 + 记录。
4. 已建档：输 PIN，连错 3 次冷却 60 秒（计数存 localStorage——sessionStorage 强杀即清零，
   评审确认）。
5. **忘记 PIN**（本地）：重置 = 清家长档案 + **全部已发布作品退回草稿**（不删除、可重发，
   代价落在"要重新走一遍家长确认"上而不是孩子的创作成果上）；审计日志保留，重置本身记一条。
   服务端阶段走短信重置，本地重置路径废除。

## 监护人确认书：最低告知清单（对照《儿童规定》第十条）

处理目的/方式/范围（学习、创作、发布各自用到什么）· 存储地点与期限、到期处理 ·
安全措施摘要 · 拒绝的后果（拒绝麦克风 = 手动放行照常学习）· 投诉举报渠道 ·
更正与删除途径（家长中心）。骨架的 `CONSENT_POINTS` 是它的短版；上线前配齐
**专门的儿童个人信息处理规则**文档 + 专人负责与投诉渠道（《儿童规定》第八条）。

## 家长中心

- 修改 PIN（记 pin-change）· 同意记录原样展示（含 childId 归属）
- 孩子档案管理（多娃：档案切换，删除动作限定档案内）
- 时长提醒设置——**时长提醒与宵禁提示是上架门槛不是增强项**（未保法第 74 条，
  与广场同批上线；薄版已实现：连续 30 分钟全屏休息提示）
- 数据导出 / 删除（PIPL 查阅复制权与删除权；本地=真清 localStorage+IndexedDB）

## 服务端契约草案（复用优先，铁律六）

**登录栈不重写**：手机号+短信码+JWT+限流直接用 ideahub-server 既有 `/api/auth/*`
（评审确认草案 v1 违反了自家引用的铁律六）。诗绘只新增业务端点：

```
POST   /api/poem/children            { nickname, ageBand }        → { childId }
POST   /api/poem/gate/verify         { pin }                      → { gateToken(10min) }
POST   /api/poem/works/:id/publish   { gateToken, voiceConsent? } → 服务端写 ConsentRecord + 校验 AI 标识元数据在场
GET    /api/poem/consents            → 审计日志（含处置记录）
DELETE /api/poem/works/:id           → 级联：DB + 视频/音频对象存储 + CDN 失效
DELETE /api/poem/account             → 注销（工信部硬要求）：全部孩子档案与作品级联删除；
                                       同意/删除处理记录依法单独留存
GET    /api/poem/export              → 监护人可读的档案+作品+同意记录导出包
```

删除的**级联清单**写死在实现里并测试钉住：数据库主表、对象存储原件、CDN 缓存失效、
委托处理方（火山）侧数据的删除申请。「及时删除」是《儿童规定》第十九条的硬词。
